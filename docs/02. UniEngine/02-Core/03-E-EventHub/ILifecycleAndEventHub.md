# ILifecycleAndEventHub

수신자가 소유자의 허브에 연결하고 알림을 관찰할 수 있게 하는 계약 묶음이다.

## 목차

1. 역할과 구성
2. 동작 흐름
3. 설계 기준과 고려사항

## 역할과 구성

- 책임: 수신자에게 필요한 관찰·연결 기능만 노출하고 소유자의 발행 권한을 분리한다.
- 상태 계약: 인터페이스는 상태를 보관하지 않으며 구현체의 IsDisposed와 연결 경로를 노출한다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| ILifecycleHub | 생애주기 연결·해제와 폐기 상태 조회를 제공한다. |
| IEventHub | object 갱신과 폐기 전·후 알림을 공통 계약으로 제공한다. |
| IEventHub&lt;TEventArgs&gt; | 형식 있는 갱신과 Builder를 제공하여 수신자가 페이로드 형식을 유지하게 한다. |

## 동작 흐름

수신자는 필요한 수준의 계약에 연결한다. 제네릭 계약은 기본 구현으로 비제네릭·생애주기 계약의 연결 경로를 이어 준다.

## 설계 기준과 고려사항

필요한 기능 수준에 따라 계약을 확장하고 기본 구현으로 연결 경로를 이어 준다. 소비자 계약에 발행과 폐기 진입점을 넣지 않아 허브 소유자의 역할을 구분한다.

- 계약에는 Update나 Dispose가 없으므로 소비자에게 소유자 측 발행·폐기 기능을 직접 노출하지 않는다.
- 구체 형식에는 해당 기능이 별도로 존재한다.

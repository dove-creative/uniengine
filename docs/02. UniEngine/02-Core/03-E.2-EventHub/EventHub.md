# EventHub

객체별 연결과 생애주기를 관리하고 내부 스트림을 통해 갱신을 전달하는 허브이다.

## 목차

- 역할과 구성
- 동작 흐름
- 설계 기준과 고려사항

## 역할과 구성

- 책임: 도메인 객체별 연결·활동 상태·폐기 알림을 관리하면서 갱신 전달을 스트림에 위임한다.
- 보유 정보: Owner, 직접 구독과 리스너가 공유하는, 연결마다 하나인 Connection, 모든 갱신 경로가 공유하는 EventStream, Sleep 토큰과 갱신·폐기 상태를 보관한다. ConnectionCount와 HasListener는 직접 구독의 연결도 포함한다.

Connection은 연결 하나의 갱신 등록과 폐기 전·후 콜백을 보관한다. 직접 이벤트는 원본 대리자를 연결 키로 사용하며, 같은 키에 여러 이벤트를 등록하면 하나의 Connection을 공유한다. 생성자 콜백도 같은 규칙을 따른다. 갱신 등록은 원본 대리자·조건·콜백 형식과 구독 핸들을 보관하며, 등록 순서와 순회 중 해제를 지원한다. Connection은 구독 핸들의 해제 알림을 받아 해당 등록을 제거한다. 생애주기 등록은 순회 중 해제를 지원하는 AdaptiveCollection으로 관리한다.

연결 안의 등록 규칙은 Connection이 맡는다. 같은 연결의 중복 검사, 갱신 구독의 생성과 -= 해제, 생애주기 콜백의 추가·제거와 폐기 알림 호출을 Connection이 직접 수행하고, 등록이 모두 사라지면 허브에 자신의 연결 제거를 요청한다. 허브는 키와 Connection의 대응, 공유 EventStream, 갱신·수면·폐기의 진행을 맡는다.

Connection은 내부 연결 계약 IEventHubConnection으로 Builder에 수명 검사와 등록 기능을 제공한다. EventHubBuilder는 경로 위치를 보관하거나 EventStream을 다루지 않는다. 조건을 스트림 경로로 연결하는 책임은 Connection에 둔다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| Connect·Disconnect | 수신자 객체 단위로 콜백과 연결 수명을 함께 등록·해제한다. |
| Builder·Updated 구독 | 객체 연결의 설정과 직접 이벤트 구독이라는 두 소비 경로를 제공한다. |
| Update·Sleep·TrySleep | 소유자의 갱신을 발행하고 연결을 유지한 채 활동을 일시 중지한다. |
| Dispose | 소유자의 폐기 전·후 알림과 모든 연결의 참조 정리를 묶는다. |

## 동작 흐름

Connect는 새 연결을 만들고 그 연결의 Builder를 반환한다. 기존 키로 다시 Connect하면 InvalidOperationException이다. 직접 +=는 같은 키의 Connection이 있으면 해당 이벤트 등록을 추가한다. OnUpdated와 직접 Updated 구독은 루트에 둔다. 조건 함수는 OnUpdatedWhere, 값 비교는 OnUpdatedWhen, 비트 조건은 OnUpdatedForFlags로 등록하며 각각 루트 아래 한 단계의 조건 경로를 사용한다. 모든 등록은 같은 Builder를 반환한다. 리스너별 Branch와 별도 순서 그룹은 없으며, 같은 위치의 같은 조건 대리자는 리스너가 달라도 WhereNode의 행 하나를 공유한다.

OnUpdatedWhen(target, callback)은 내부 스트림의 When 경로를 사용한다. 같은 부모 아래 동등한 target은 리스너가 달라도 WhenNode의 행 하나를 공유한다. EqualityComparer&lt;TEventArgs&gt;.Default로 비교하며 참조 형식과 Nullable&lt;T&gt;의 null도 유효한 target이다. 같은 위치의 target들은 WhenNode 하나에 모이고 발행 값과 일치하는 항목 하나만 방문한다. 다른 형제와의 순서는 WhenNode가 생성된 위치를 따른다.

ulong 허브의 OnUpdatedForFlags는 내부 스트림의 비트 조건 경로를 사용한다. 값과 마스크의 공통 비트가 하나라도 있을 때 통과하며 원래 ulong 값을 전달한다. OnUpdatedWhen의 ulong target은 전체 값의 동등성을 비교하므로 비트 조건과 구분한다. 같은 부모 위치의 마스크 비트는 enum 형식과 리스너가 달라도 공유한다. 같은 위치의 모든 마스크 항목은 FlagsNode 하나에 묶이며, 다른 자식 경로와의 순서는 그 묶음이 처음 생성된 위치를 따른다. 묶음 안에서는 마스크 항목의 생성 순서대로 방문한다.

Update는 스트림의 그래프 순서로 전파한다. 루트 Gate의 구독을 등록 순서대로 먼저 호출하고 WhereNode·FlagsNode·WhenNode를 생성 순서대로 방문한다. 같은 위치의 키 연산은 종류별 노드 하나에 모이며, Where·Flags 행은 등록·생성 순서이고 When은 일치하는 행 하나만 방문한다. OnUpdatedWhere(a), OnUpdatedForFlags(m), OnUpdatedWhere(b)를 등록하면 a, b행 → flags 순서이다.

한 리스너의 콜백을 묶어 호출하지 않으며, 루트에서는 리스너 콜백과 직접 구독이 등록 순서대로 섞인다. 전파 중 추가한 구독·행·노드는 다음 갱신부터 보이고 해제와 Disconnect는 즉시 반영된다. 제거한 뒤 같은 키로 다시 만든 행도 이번 Update에서는 호출하지 않으며 현재 행이나 다음 행을 제거해도 남은 행과 형제를 계속 방문한다. 스트림 그래프의 완료·오류·폐기도 같은 순서로 키와 관계없이 모든 행을 정리한다. 이는 아래의 허브 Disposing·Disposed 알림 순서와 별개의 계약이다. Update는 해제된 구독을 찾기 위해 모든 연결이나 등록을 훑지 않는다.

갱신 콜백이 실패하면 스트림이 그 구독 하나만 해제하고 ExceptionHandler.Report에 보고한다. 같은 연결의 나머지 갱신·생애주기 등록은 유지된다. 처리기가 없거나 보고가 예외를 던져도 다른 구독을 방문한 뒤 첫 보고 예외를 Update 호출자에게 전달한다. Where 조건 실패는 해당 행의 연결만 해제하며 같은 WhereNode의 다른 행은 유지한다. When의 비교 실패는 같은 위치의 WhenNode와 모든 target 행의 연결을 통지 없이 해제하며 형제 경로는 계속 방문한다. Connection은 실패 원인과 관계없이 구독 핸들의 해제 알림으로 등록을 즉시 정리한다. 갱신 등록과 생애주기 등록이 모두 사라지면 Update 중이라도 연결 키를 그 자리에서 제거하며, 이후 -=나 Disconnect는 안전하다. 아직 등록한 적 없는 빈 Connect 연결은 유지한다.

실패 직후에도 생애주기 콜백이나 다른 갱신 등록이 남아 있는 연결은 같은 경로에 같은 콜백을 다시 등록할 수 있다. 비어서 제거된 연결의 Builder는 같은 Update 안에서도 다시 등록할 수 없다. 직접 +=는 대리자 키로 새 연결을 만들 수 있으며, 그 새 구독은 다음 Update부터 호출된다.

Sleep에서 반환하거나 연결한 Token을 폐기하면 Awake가 호출된다. 수면 중 Update와 재진입 Update는 실행을 생략한다. 폐기 요청은 이 상태들보다 먼저 검사한다.

## 설계 기준과 고려사항

허브는 객체 관계와 생애주기를 소유하고 EventStream은 갱신 순서·조건 공유·전파 중 변경·실패 보고를 담당한다. 허브는 갱신 콜백이나 조건의 예외를 감싸지 않고 해제 알림에만 반응한다. 두 책임을 분리하여 허브가 별도의 갱신 호출 목록과 예외 보고 방식을 중복 구현하지 않게 한다.

- 정상 폐기는 모든 연결의 Disposing → IsDisposed 전환 → 모든 연결의 Disposed 순서이다. 같은 연결·단계 안에서는 오버로드와 관계없이 등록 순서로 호출한다. 연결 간 순서와 직접 구독의 우선순위는 보장하지 않는다.
- 직접 구독과 Builder 모두 전달한 대리자 전체가 등록 하나이다. 멀티캐스트의 항목 하나가 실패하면 그 등록 전체를 해제하고 나머지 항목을 생략한다. 앞 항목에서 -=·Disconnect·Dispose를 호출하여 해제한 경우에도 남은 항목을 건너뛴다.
- 같은 연결·콜백 형식에서 원본 대리자와 조건의 종류·값이 같은 갱신 등록은 InvalidOperationException으로 거부한다. 조건 없음은 루트끼리만 같다. typed/object Updated는 별도 형식이며 서로 중복 판정하거나 교차 해제하지 않는다. 생애주기 중복은 조건과 무관하다.
- 중복 판정은 연결·콜백 형식·원본 대리자·조건을 함께 비교하고 노드 공유는 경로 위치와 조건을 비교한다. OnUpdatedWhen에 전달한 동등한 target은 같은 위치의 WhenNode의 행을 공유한다. 같은 target 값으로 같은 콜백을 중복 등록하는 경우는 거부한다.
- 등록 뒤 target의 Equals·GetHashCode 결과가 바뀌는 경우는 지원하지 않는다. 등록 중 비교 예외는 호출자에게 전파하며 실패한 등록으로 새로 만든 빈 경로는 남기지 않는다.
- 등록은 연결 수명 → 조건 인자 → null 콜백 순서로 검사한다. null 조건은 ArgumentNullException, 잘못된 비트 마스크는 ArgumentException이며 기존 등록을 유지한다. 유효한 조건의 null 콜백은 등록 없이 무시한다.
- -=는 대리자 키의 연결에서 해당 이벤트의 일치하는 등록만 제거한다. Updated는 루트 경로의 같은 콜백 형식에 한정한다. 멀티캐스트는 같은 묶음으로 해제하며 부분 해제하지 않는다. Disconnect(key)는 연결 전체를 제거한다.
- 생애주기 콜백 실패는 직접 구독과 Builder 모두 연결 전체를 해제하고 허브가 보고한다. 보고가 정상 반환하면 다른 연결의 알림을 계속하며, 보고가 예외를 전파하면 남은 알림을 생략한다.
- Disposing 통지 중 해제한 등록 항목은 이후 호출에서 제외한다. IsDisposed 전환 후의 -=는 무시하며 폐기 중 새 등록은 거부한다.
- 구독 구성이 고정된 동안에는 첫·반복 갱신과 폐기 순회에 관리 힙 할당이 없다. 등록 시점과 사용자 콜백·Equals·GetHashCode 구현의 비용은 이 보장에서 제외한다. When의 성능은 측정하지 않았으며 Unity Mono·IL2CPP에서의 할당도 검증하지 않았다.
- Update 중 Dispose는 나머지 갱신을 멈추고 현재 콜백 반환 뒤 정리를 수행한다.
- 연결 전체를 해제할 때는 먼저 연결 상태를 끊어 구독 핸들의 해제 알림이 정리 중인 목록을 바꾸지 않게 한다. 허브 폐기 요청 이후에는 구독 해제 알림에 따른 연결 제거를 생략하고, 생애주기 통지와 마지막 참조 정리를 허브의 폐기 절차에 맡긴다.
- 예외로 종료하면 뒤의 알림은 생략될 수 있으나 참조 정리는 수행한다.
- 명시적 해제나 마지막 등록 제거로 해제된 연결의 Builder는 재연결 후에도 재사용할 수 없다. 등록은 InvalidOperationException이며, 허브 폐기 이후에는 ObjectDisposedException이 우선한다.
- Update·Dispose는 소유자가 호출하는 설계이며 런타임에서 호출자 신원을 검사하지는 않는다.

수면은 Token 하나에 묶는다. 깨우는 권한을 그 Token을 가진 작업으로 한정하여, 여러 작업이 활성 상태를 동시에 바꾸며 서로의 깨우기 시점을 덮어쓰지 않게 한다. 외부에서 만든 Token으로 재우면 그 Token 하나를 폐기하여 여러 허브를 함께 깨울 수 있다.

- 이미 수면 중인 허브의 Sleep은 거부한다. 수면 여부를 알 수 없는 호출자는 TrySleep을 사용한다. 이미 수면 중이면 TrySleep은 수면 상태를 바꾸지 않으며, 핸들을 반환하는 형태는 그 핸들을 폐기할 때 onAwake만 실행한다.
- 수면 중 Update는 보류하지 않고 생략한다. 깨어난 뒤 필요한 갱신은 onAwake에서 발행한다.
- 폐기는 수면보다 우선한다. 수면 중 폐기된 허브는 이후 Token이 폐기되어도 onAwake를 실행하지 않는다.

[사용 예제](Usage.md)의 직접 구독 절은 연결 수신자와 직접 구독자의 호출 순서를 보여준다. 수면과 깨우기 절은 TrySleep으로 중첩된 수면 범위를 처리하고, 여러 허브 함께 재우기 절은 외부 Token 하나로 두 허브를 함께 깨운다.

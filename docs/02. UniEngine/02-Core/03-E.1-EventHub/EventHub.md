# EventHub

객체별 연결과 생애주기를 관리하고 내부 스트림을 통해 갱신을 전달하는 허브이다.

## 목차

- 역할과 구성
- 동작 흐름
- 설계 기준과 고려사항

## 역할과 구성

- 책임: 도메인 객체별 연결·활동 상태·폐기 알림을 관리하면서 갱신 전달을 스트림에 위임한다.
- 보유 정보: Owner, 연결별 Order, 직접 구독 목록, 순서 그룹을 가진 EventStream, Sleep 토큰과 갱신·폐기 상태를 보관한다. ConnectionCount는 Connect로 등록한 수신자만 센다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| Connect·Disconnect | 수신자 객체 단위로 콜백과 연결 수명을 함께 등록·해제한다. |
| Builder·Updated 구독 | 객체 연결의 설정과 직접 이벤트 구독이라는 두 소비 경로를 제공한다. |
| Update·Sleep·TrySleep | 소유자의 갱신을 발행하고 연결을 유지한 채 활동을 일시 중지한다. |
| Dispose | 소유자의 폐기 전·후 알림과 모든 연결의 참조 정리를 묶는다. |

## 동작 흐름

Update 시작 시 연결별 콜백 목록을 확정한 뒤 내부 스트림이 연결 수신자 → 직접 Updated 구독자 순으로 전달한다. 전파 중 새 연결·직접 구독·Builder 콜백 변경은 다음 갱신부터 적용한다. 연결된 콜백이 실패하면 해당 연결을 제거한 뒤 스트림이 보고를 담당한다.

Sleep에서 반환하거나 연결한 Token을 폐기하면 Awake가 호출된다. 수면 중 Update와 재진입 Update는 실행을 생략한다. 폐기 요청은 이 상태들보다 먼저 검사한다.

## 설계 기준과 고려사항

허브는 객체 관계와 생애주기를 소유하고 EventStream의 두 순서 그룹은 갱신 순서와 전파를 담당한다. 두 책임을 분리하여 Hub가 별도의 갱신 호출 목록과 예외 보고 방식을 중복 구현하지 않게 한다.

- 정상 폐기는 직접 Disposing → 연결별 OnDisposing → IsDisposed 전환 → 연결별 OnDisposed → 직접 Disposed 순서이다.
- 구독 구성이 고정된 동안에는 첫 갱신부터 연결과 콜백을 순회하는 데 임시 메모리를 할당하지 않는다.
- Update 중 Dispose는 나머지 갱신을 멈추고 현재 콜백 반환 뒤 정리를 수행한다.
- 예외로 종료하면 뒤의 알림은 생략될 수 있으나 참조 정리는 수행한다.
- Update·Dispose는 소유자가 호출하는 설계이며 런타임에서 호출자 신원을 검사하지는 않는다.

수면은 Token 하나에 묶는다. 깨우는 권한을 그 Token을 가진 작업으로 한정하여, 여러 작업이 활성 상태를 동시에 바꾸며 서로의 깨우기 시점을 덮어쓰지 않게 한다. 외부에서 만든 Token으로 재우면 그 Token 하나를 폐기하여 여러 허브를 함께 깨울 수 있다.

- 이미 수면 중인 허브의 Sleep은 거부한다. 수면 여부를 알 수 없는 호출자는 TrySleep을 사용한다. 이미 수면 중이면 TrySleep은 수면 상태를 바꾸지 않으며, 핸들을 반환하는 형태는 그 핸들을 폐기할 때 onAwake만 실행한다.
- 수면 중 Update는 보류하지 않고 생략한다. 깨어난 뒤 필요한 갱신은 onAwake에서 발행한다.
- 폐기는 수면보다 우선한다. 수면 중 폐기된 허브는 이후 Token이 폐기되어도 onAwake를 실행하지 않는다.

[사용 예제](Usage.md)의 직접 구독 절은 연결 수신자와 직접 구독자의 호출 순서를 보여준다. 수면과 깨우기 절은 TrySleep으로 중첩된 수면 범위를 처리하고, 여러 허브 함께 재우기 절은 외부 Token 하나로 두 허브를 함께 깨운다.

# EventStream 연산자

기본 EventStream에 진단·필터·완료 조건·입력 병합을 더하여 이벤트 경로를 조합하는 연산자 모음이다.

## 목차

1. 역할과 구성
2. 동작 흐름
3. 설계 기준과 고려사항
4. 구현 연결

## 역할과 구성

각 연산자는 EventStream을 상속한 작은 스트림이다. 값 처리는 자신의 OnNext에서 하고, 구독과 상위 연결의 정리는 기본 EventStream에 맡긴다.

| 연산자 | 책임 | 보유 정보 |
| --- | --- | --- |
| Debug | 값을 로그에 남긴 뒤 그대로 전달하여 경로를 관찰한다. | 메시지, LogLevel |
| Skip | 앞에서 정한 개수의 입력을 버린다. | 남은 건너뛰기 횟수 |
| SkipWhile | 조건이 true인 첫 구간을 버린다. | 조건 함수. 첫 false 이후에는 비운다. |
| Where | 입력마다 조건을 검사하여 통과 여부를 정한다. | 조건 함수 |
| Take | 정한 개수만큼 전달한 뒤 완료한다. | 남은 전달 횟수 |
| TakeWhile | 조건이 true인 동안 전달하고 처음 false에서 완료한다. | 조건 함수 |
| Merge | 여러 상위의 입력을 모으고 상위의 완료를 집계한다. | CompletionMode, 아직 완료하지 않은 상위 수 |

조건을 받는 SkipWhile·Where·TakeWhile은 두 형식의 조건을 지원한다. 생성자와 확장 메서드 모두 두 형식을 받는다.

| 조건 형식 | 예 | 쓰는 경우 |
| --- | --- | --- |
| `Func<T, bool>` | `value => value > 10` | 들어온 값을 보고 판단할 때 |
| `Func<bool>` | `() => isReady` | 값과 관계없이 외부 상태로 판단할 때 |

카운터와 조건 상태는 연산자 인스턴스에 속한다. 같은 인스턴스를 여러 수신자가 구독하면 상태도 함께 쓰며, 구독마다 새 구간이나 횟수가 생기지 않는다. 독립된 구간이 필요하면 소스에 연산자를 따로 연결한다.

## 동작 흐름

모든 연산자의 OnNext는 같은 앞부분을 가진다. 먼저 폐기 여부를 검사하고, Enabled가 false이면 입력을 처리하지 않고 반환한다. 아래 설명은 그 다음 단계이다.

### Debug

1. 값과 메시지를 '값: 메시지' 형식으로 로그에 남긴다. 기본 메시지는 'Debug', 기본 수준은 LogLevel.Log이다.
2. 로그 출력 중 스트림이 폐기되지 않았으면 같은 값을 전달한다.

발신자나 수신자 코드를 고치지 않고 관찰 단계를 끼워 넣는 용도이다. 필터 앞에 두면 필터 전 입력을, 뒤에 두면 통과한 값만 기록한다.

### Skip

1. 남은 건너뛰기 횟수가 있으면 하나 줄이고 값을 버린다.
2. 남은 횟수가 없으면 값을 전달한다.

count의 기본값은 1이다. 0 이하로 만들면 첫 입력부터 전달한다. 건너뛰기를 마친 뒤에는 카운터가 더 이상 바뀌지 않으므로, 입력이 아무리 많아도 다시 건너뛰기 시작하지 않는다. Enabled가 false인 동안 들어온 입력은 세지 않는다.

### SkipWhile

1. 조건이 true이면 값을 버린다.
2. 조건이 처음 false가 되면 그 값부터 전달하고 조건 함수를 비운다.
3. 이후에는 조건을 검사하지 않고 모든 값을 전달한다.

조건을 다시 보지 않으므로 외부 상태가 바뀌어도 버리는 단계로 돌아가지 않는다.

### Where

1. 입력마다 조건을 평가한다.
2. true인 값만 전달한다. false는 그 값만 버리며 스트림을 완료하지 않는다.

첫 구간만 검사하는 SkipWhile과 달리, 이후 입력도 계속 검사한다.

### Take

1. 남은 전달 횟수가 0 이하이면 값을 전달하지 않고 완료한다.
2. 값을 전달하고 남은 횟수를 하나 줄인다.
3. 남은 횟수가 0이 되면 완료한다.

완료는 OnCompleted로 알리며, 그 결과 자신과 상위 연결이 정리된다. 필요한 값을 얻은 뒤 입력 연결이 남지 않게 하는 완료 조건이다.

- 0 이하로 만들면 생성 즉시가 아니라 첫 활성 입력에서 완료한다.
- 확장 메서드는 count를 생략하면 1을 사용한다. 생성자로 만들 때는 count를 지정한다.
- 하위 콜백의 예외가 호출자에게 전달되는 경우에는 그 값을 센 것으로 치지 않는다.

### TakeWhile

1. 입력마다 조건을 평가한다.
2. true이면 값을 전달한다.
3. 처음 false이면 그 값을 전달하지 않고 완료한다.

조건 실패를 그 값에만 적용하는 Where와 달리, 경로의 수명을 끝내고 상위 연결도 정리한다. 처음 false인 값부터 전달을 시작하는 SkipWhile과는 반대 방향이다.

### Merge

1. 생성할 때 null인 상위는 건너뛴다. 나머지는 폐기 여부를 확인하고 Connect로 자신을 연결하며, 연결한 상위의 수를 센다. 이미 폐기되었거나 종료·폐기 중인 EventStream은 ObjectDisposedException으로 거부한다.
2. 연결 도중 실패하면 지금까지 만든 연결을 정리하고 예외를 전달한다.
3. 상위에서 들어온 값은 들어온 흐름에서 바로 하위에 전달한다. 동시 입력을 정렬하거나 예약하지 않는다.
4. 상위가 완료되면 CompletionMode에 따라 처리한다.
5. 상위에서 오류가 오면 CompletionMode와 관계없이 오류를 알리고 폐기한다.
6. 폐기될 때는 아직 남은 상위와의 연결도 해제한다.

| CompletionMode | 상위 하나가 완료되면 |
| --- | --- |
| All (기본값) | 남은 상위 수를 줄인다. 0이 되면 완료한다. |
| Any | 바로 완료한다. |

- CompletionMode는 상위 완료를 언제 자신의 완료로 볼지 정하고, TerminationMode는 하위 구독이 모두 떠났을 때 폐기할지 정한다. 두 정책은 따로 고른다.
- 연결할 상위가 하나도 없어도 생성하자마자 완료하지는 않는다.
- 완료 집계는 Merge 형식이나 IObserver·IEventStream 형식으로 OnCompleted를 호출할 때 적용된다. EventStream 형식의 변수로 OnCompleted를 직접 호출하면 집계 없이 바로 완료한다.
- 상위를 Dispose로 끝내면 완료 통지가 없으므로 All의 남은 상위 수가 줄지 않는다.
- 상위와의 연결 해제는 상위 객체의 폐기가 아니다. 상위가 함께 폐기되는지는 상위의 TerminationMode가 정한다.

## 설계 기준과 고려사항

입력 처리와 그 상태를 작은 하위 스트림에 두어, 진단·선택·완료·병합을 필요한 순서대로 조합하게 한다. 경로 구성은 [EventStreamExtensions](EventStreamExtensions.md)가 돕고, 구독과 연결 수명은 [모듈 개요](README.md)의 공통 규칙을 따른다.

- 모든 연산자의 기본 종료 정책은 NoSubscribers이다.
- Enabled가 false이면 입력 처리와 카운터·조건 평가를 진행하지 않는다.
- 조건 평가나 로그 출력 중 스트림이 폐기되면 그 값은 전달하지 않는다.
- 완료·오류 통지는 Enabled와 관계없이 처리하며, 통지 뒤의 폐기와 연결 정리는 기본 EventStream을 따른다.
- 전파 중 변경과 콜백 예외 처리는 [EventStream](EventStream.md)을 따른다.

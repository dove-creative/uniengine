# 경로 연산자

연산자는 값을 즉시 받아 처리하는 개체를 만들지 않는다. 호출 순서대로 경로를 기록하고, Subscribe 또는 활성 Branch가 연결될 때 해당 노드를 만든다.

| 연산 | 값이 노드에 도달할 때의 동작 | 상태를 공유하는 범위 |
| --- | --- | --- |
| Where(filter) | 참일 때만 하위를 방문한다. | 같은 부모 아래 같은 Filter 참조 |
| Skip(n) | 처음 n개를 버리고 이후 값을 전달한다. 0 이하이면 처음부터 전달한다. | 구독별 |
| SkipWhile(filter) | 처음 거짓인 값부터 전달하며 이후 조건 검사를 멈춘다. | 구독별 |
| Take(n) | n번째 값을 전달한 뒤 하위에 완료를 통지한다. 0 이하이면 처음 도달한 값을 전달하지 않고 완료한다. | 구독별 |
| TakeWhile(filter) | 참인 동안 전달한다. 처음 거짓인 값은 전달하지 않고 완료한다. | 구독별 |
| Debug | 값과 메시지를 로그로 기록하고 다음 노드로 전달한다. | 해당 경로 등록 |

## 조건과 카운터

Filter.Name은 진단용이다. 이름이나 람다 본문이 같아도 서로 다른 객체는 별도 조건으로 평가한다. 반대로 같은 Filter를 서로 다른 순서 그룹에 사용하면 각 그룹에서 한 번씩 평가한다.

상태가 있는 경로를 저장해 두고 두 번 구독하면 늦게 구독한 사람은 자신의 첫 값부터 센다. 먼저 적용한 Where가 거짓인 값은 뒤의 Take·Skip에 도달하지 않는다. 마지막 값을 처리하는 동안 추가된 구독은 그 값을 받지 않는다. 종료되는 하위에 이미 연결된 활성 수신자는 마지막 값을 받았는지와 관계없이 완료를 받는다.

필터가 예외를 던지면 해당 노드와 하위를 통지 없이 정리한다. 형제 경로는 계속 진행한다. Debug는 값을 문자열로 포맷해 로그를 쓰므로 그 비용은 일반 Where·Take의 무할당 전파 측정에서 제외한다. [전파와 실패 규칙](EventStream.md)

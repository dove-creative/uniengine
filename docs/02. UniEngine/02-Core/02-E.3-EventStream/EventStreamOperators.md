# 경로 연산자

연산자는 두 종류이다. 상태가 없는 Where와 Debug는 경로를 기록하고, 상태가 있는 Take·TakeWhile·Skip·SkipWhile은 새 EventStream을 시작한다. 그래서 그래프에는 상태가 없다.

| 연산 | 값이 도달할 때의 동작 | 결과 | 공유 범위 |
| --- | --- | --- | --- |
| Where(filter) | 참일 때만 하위를 방문한다. | EventPath | 같은 부모 아래 같은 Filter 참조 |
| Debug | 값과 메시지를 로그로 기록하고 다음 노드로 전달한다. | EventPath | 해당 경로 등록 |
| Skip(n) | 처음 n개를 버리고 이후 값을 전달한다. 0 이하이면 처음부터 전달한다. | EventStream | 반환된 스트림 |
| SkipWhile(filter) | 처음 거짓인 값부터 전달하며 이후 조건 검사를 멈춘다. | EventStream | 반환된 스트림 |
| Take(n) | n번째 값을 전달한 뒤 완료한다. 0 이하이면 처음 도달한 값을 전달하지 않고 완료한다. | EventStream | 반환된 스트림 |
| TakeWhile(filter) | 참인 동안 전달한다. 처음 거짓인 값은 전달하지 않고 완료한다. | EventStream | 반환된 스트림 |

## 조건과 공유

Filter.Name은 진단용이다. 이름이나 람다 본문이 같아도 서로 다른 객체는 별도 조건으로 평가한다. 같은 Filter를 서로 다른 순서 그룹이나 다른 스트림에서 쓰면 각각 평가한다. SkipWhile과 TakeWhile의 조건은 공유하지 않는다.

## 상태 있는 연산자

상태는 연산자를 호출할 때 만들어진 스트림이 가진다. 같은 스트림을 구독한 쪽끼리 남은 횟수와 진행 상태를 공유하고, 연산자를 다시 호출하면 새 상태로 시작한다.

- 스트림은 첫 구독 때 상위에 연결되고, 그때부터 값을 센다. 늦게 구독한 쪽은 남은 상태를 이어받는다.
- 먼저 적용한 Where가 거짓인 값은 뒤의 Take·Skip에 도달하지 않는다. 스트림에 직접 넣은 값은 위에서 온 값과 같게 센다.
- Take·TakeWhile이 끝나면 일반 종료 규칙에 따라 활성 구독에 완료를 통지하고 폐기된다. 마지막 값을 처리하는 동안 추가된 구독은 그 값을 받지 않고 완료만 받는다. 상위에서는 그 스트림으로 가는 연결만 빠진다.
- 끝난 스트림에 구독하면 ObjectDisposedException이 발생한다.

## 실패와 비용

Where 조건이 예외를 던지면 해당 노드와 하위를 통지 없이 정리한다. SkipWhile·TakeWhile 조건이 예외를 던지면 그 스트림을 통지 없이 폐기한다. 어느 쪽이든 형제 경로는 계속 진행한다.

상태 있는 연산자는 호출할 때마다 스트림을 하나 만든다. 고정된 구독에서는 전파 할당이 없지만, 매 프레임 Take(1)을 만드는 코드는 그만큼 할당이 늘어난다. Debug는 값을 문자열로 포맷해 로그를 쓰므로 그 비용은 무할당 전파 측정에서 제외한다. [전파와 실패 규칙](EventStream.md)

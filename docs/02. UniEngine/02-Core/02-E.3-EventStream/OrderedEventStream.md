# OrderedEventStream

구독자를 순서 그룹으로 나누어, 한 번의 전파 안에서 그룹 순서대로 호출하는 EventStream이다.

## 역할과 구성

- 책임: 구독한 시점과 관계없이 수신자를 정해진 실행 단계 순서로 호출한다.
- Orders: 실행할 순서 그룹의 목록이다. 그룹은 열거형 TOrder의 값으로 나타낸다.
- DefaultOrder: 순서를 지정하지 않은 구독이 들어갈 그룹이다.
- 그룹별 호출 목록: 그룹마다 하나씩 둔 AdaptiveAction이다.
- 추가 대기 목록: 전파 중에 들어온 구독을 전파가 끝날 때까지 보관한다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| 순서를 받는 Subscribe·Chain·Connect | 수신자를 특정 실행 단계에 배치한다. |
| AddOrder | 아직 없는 그룹을 목록 끝에 추가한다. |
| Append(order) | 지정한 그룹에 새 기본 EventStream을 연결하고 반환한다. |
| OnNext | 모든 그룹을 한 번의 전파로 묶어 순서대로 호출한다. |

순서 인자는 보통 맨 앞에 두며, 콜백이나 Observer 뒤에 두는 오버로드도 있다. 순서를 받지 않는 일반 Subscribe·Chain·Connect는 DefaultOrder 그룹을 사용한다.

## 동작 흐름

### 그룹 목록 결정

생성자는 순서 목록과 기본 그룹을 다음과 같이 정한다.

| 생성자 인자 | 순서 목록 | 기본 그룹 |
| --- | --- | --- |
| 없음 | Enum.GetValues의 결과 | 목록의 첫 값 |
| defaultOrder | Enum.GetValues의 결과 | defaultOrder |
| orders | 지정한 orders | orders의 첫 값 |
| defaultOrder, orders | 지정한 orders | defaultOrder |

1. 지정한 목록이 비어 있으면 Enum.GetValues의 결과를 사용한다.
2. 목록의 값을 앞에서부터 그룹으로 등록한다. 중복 값은 한 번만 등록한다.
3. 기본 그룹이 목록에 없으면 목록 끝에 추가한다.

Enum.GetValues는 소스 코드의 선언 순서가 아니라 값의 크기순으로 결과를 돌려준다. 정확히는 내부 값을 부호 없는 정수로 보고 오름차순으로 정렬하므로, 음수 값은 모든 양수 값 뒤에 온다. 예를 들어 PreUpdate = 0, Update = 1, PostUpdate = 2이면 이 순서로 실행하지만, 여기에 Late = -1을 더하면 Late는 맨 뒤에서 실행된다. 선언 순서와 실행 순서를 확실히 맞추려면 순서 목록을 직접 넘긴다.

### 구독

1. 순서를 지정하지 않으면 DefaultOrder 그룹에 넣는다.
2. 목록에 없는 그룹을 지정하면 그 그룹을 목록 끝에 새로 만든다.
3. 같은 그룹 안에서는 등록한 순서대로 호출한다.

### 전파

1. OnNext가 시작될 때 그룹 수를 고정하고, 목록 순서대로 각 그룹의 구독을 호출한다.
2. 전파 중 추가한 구독은 추가 대기 목록에 두었다가, 모든 그룹의 호출이 끝난 뒤 해당 그룹에 넣는다.
3. 대기 중에 해제된 구독은 넣지 않는다.

그래서 아직 실행하지 않은 뒤쪽 그룹에 구독을 추가해도 이번 전파에는 참여하지 않는다. 전파 중 새로 만든 그룹도 다음 전파부터 호출한다.

## 설계 기준과 고려사항

추가 대기를 그룹 단위가 아닌 전체 전파 단위로 둔다. 그룹별 AdaptiveAction의 지연 추가만 쓰면, 앞 그룹의 콜백이 아직 순회하지 않은 뒤쪽 그룹에 넣은 구독은 같은 전파에서 실행되어 버린다. 전파 전체가 끝날 때까지 미루어 '추가한 수신자는 다음 전파부터' 원칙을 그룹 사이에서도 지킨다.

- 명시한 순서 목록을 그대로 보존한다. 목록을 생략한 경우에만 Enum.GetValues의 정렬을 따른다.
- AddOrder나 새 그룹 구독으로 생긴 그룹은 목록 끝에 추가된다.
- Append(order)가 만드는 스트림은 기본 EventStream이며 종료 정책은 Complete이다.
- 콜백 안에서 같은 스트림의 OnNext를 다시 호출하면 InvalidOperationException이다. 바깥 전파는 이를 그 콜백의 실패로 처리한다.
- [EventHub](../03-E-EventHub/EventHub.md)가 연결 수신자와 직접 구독자의 두 단계를 나누는 데 사용한다.

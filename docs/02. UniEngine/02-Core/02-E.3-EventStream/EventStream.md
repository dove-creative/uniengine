# EventStream

EventStream은 값을 받아 구독 그래프로 전달하는 기본 단위이다. 같은 이벤트를 기다리는 구독자들이 조건을 공유하도록 Where 경로, 같은 target의 When 경로, 같은 마스크의 ForFlags 경로를 합치고, 마지막 수신자가 떠나면 그 경로를 정리한다.

## 입력

모든 EventStream은 OnNext로 값을 직접 받는다. 스트림마다 다른 것은 그 밖의 입력과 폐기할 때 정리하는 연결이다.

| 만드는 방법 | 다른 입력 | 폐기할 때 |
| --- | --- | --- |
| 기본 생성자 | 없음 | 구독을 해제한다. |
| 외부 IObservable을 전달한 생성자 | 외부 공급원 | 구독과 공급원 연결을 해제한다. 공급원은 폐기하지 않는다. |
| Take·TakeWhile·Skip·SkipWhile·Branch | 호출한 지점의 값 | 구독과 상위 연결을 해제한다. |
| Merge | 호출한 스트림과 인수로 받은 스트림 | 구독과 모든 입력 연결을 해제한다. |

직접 넣은 값은 구독 여부와 관계없이 위에서 온 값과 같게 처리하고 그 스트림 아래로만 흐른다. 첫 구독 전에도 Take·Skip의 횟수와 TakeWhile·SkipWhile의 조건 상태에 반영되며, 상위 연결을 만들지는 않는다. Enabled가 false이면 어느 입력의 값도 받지 않고 조건도 평가하지 않는다. 완료·오류는 계속 전달한다.

## 내부 구조

값은 입구, 경로, 출구를 차례로 지난다.

| 구성 | 형식 | 역할 |
| --- | --- | --- |
| 입구 | InputGate | 상위 하나당 하나씩 둔다. 첫 구독 전에는 연결할 위치를, 연결 후에는 해제 핸들을 가진다. 상위의 값·완료·끊김을 받아 스트림에 전달한다. 트리에 속하지 않는다. |
| 연산 | 파생 스트림의 중첩 노드 | TakeStream, TakeWhileStream, SkipStream, SkipWhileStream이 자기 노드를 중첩 클래스로 가진다. 횟수를 세는 쪽은 Counter, 조건을 보는 쪽은 Condition이다. 스트림을 만들 때 그래프의 루트로 주입되어 상태를 가지고, 끝나면 스트림의 완료 처리를 호출한다. 스트림마다 하나이며 경로 병합의 대상이 아니다. |
| 경로 | NodeBase 파생 형식 | 자식을 추가 순서로 두는 Node와 순서 값으로 두는 OrderedNode, 값 조건을 묶는 WhenNode, 비트 조건을 묶는 FlagsNode가 있다. 루트와 순서별 노드는 Node 자체이고 Where·Debug·WhenEntry·FlagsEntry는 Node를 상속한다. 같은 위치의 순서 그룹은 OrderedNode 하나에 모인다. 값을 거르거나 통과시킬 뿐 구독자를 갖지 않는다. |
| 값 조건 | WhenNode·WhenEntry | 같은 위치의 동등한 target은 WhenEntry 하나를 공유한다. null이 아닌 target은 EqualityComparer&lt;T&gt;.Default를 사용하는 사전으로, null target은 별도 필드로 관리한다. 등록 검색과 발행 분기 모두 이 구조를 사용하며 값에 해당하는 항목 하나만 방문한다. 항목은 생성 순서의 자식 체인에도 두어 종료와 폐기를 모두 전달한다. |
| 비트 조건 | FlagsNode·FlagsEntry | FlagsNode는 같은 위치에 하나만 두고, 마스크를 가진 FlagsEntry만 자식으로 가진다. 같은 마스크 비트의 항목을 공유하고 생성 순서로 방문하며, 값과 비트가 하나라도 겹친 항목만 통과시킨다. enum 형식이 달라도 비트가 같으면 공유하고, 순서 그룹이 다르면 공유하지 않는다. |
| 출구 | OutputGate | 구독 목록을 가진 말단이다. Node가 아니지만 NodeChild를 상속해 노드의 자식 자리에 들어간다. 같은 위치의 구독자는 Gate 하나를 공유한다. 새 스트림으로 가는 연결은 연결마다 Gate를 따로 둔다. |

## 전파와 변경

같은 위치의 구독자를 등록 순서대로 먼저 호출한 뒤 자식을 방문한다. 구독자의 Gate를 항상 첫 자식으로 두어 이 순서를 지킨다. 전파 중 추가한 노드·구독은 다음 값부터 보인다. 구독 해제는 즉시 반영하므로 같은 값에서 차례를 기다리는 콜백도 건너뛴다. 완료와 오류는 조건과 관계없이 활성 구독을 순회한 뒤 폐기한다. 명시적 Dispose는 값을 보내거나 완료를 통지하지 않는다.

같은 스트림에 콜백 안에서 다시 값을 넣으면 InvalidOperationException이 발생한다. 콜백의 실패는 해당 구독만, 조건의 실패는 그 아래 경로를 해제한다. 실패를 ExceptionHandler.Report에 넘기며 보고가 예외를 던져도 나머지 구독을 계속 방문한다. 순회를 마친 뒤 첫 보고 예외를 값을 넣은 쪽에 전달한다. 스트림 사이의 연결은 이 예외 때문에 끊기지 않는다. 외부 Observable이 관찰자 예외를 잡거나 구독을 종료하는 방식은 그 공급원의 계약을 따른다.

When의 비교가 발행 중 실패하면 그 위치의 WhenNode와 모든 target 경로를 통지 없이 해제하고 형제 경로는 계속 방문한다. 등록 중 비교 예외는 Subscribe 호출자에게 전파하며, 실패한 등록으로 새로 만든 빈 노드는 정리한다. WhenNode와 다른 형제 사이에는 묶음의 생성 순서를 적용하고, 선택한 항목도 연결 상태와 발행 시작 시점의 등록 범위 안에 있어야 방문한다. 발행 중 제거한 target을 다시 등록해도 새 항목은 다음 값부터 받는다.

## 구독과 연결의 수명

구독 핸들을 해제하면 더는 쓰지 않는 노드가 부모에서 제거된다. 사용자가 만든 EventStream은 마지막 구독이 떠난 뒤에도 다시 구독할 수 있고, 상위가 폐기되어도 살아 있다.

연산자·Branch·Merge가 만든 스트림은 첫 구독 때 상위와 연결되고 마지막 구독이 떠나면 스스로 폐기된다. 상위가 완료·오류로 끝나면 같은 신호를 받고, 상위가 폐기되면 통지 없이 폐기된다. 입력이 여럿인 Merge의 수명은 [Branch와 Merge](BranchAndMerge.md)에 있다.

## 경로 크기

- Where 조건이 적은 부모에서는 자식을 훑어 같은 대리자를 찾고, 조건 수가 임계값을 넘으면 그 부모에만 해시 색인을 만든다. 기준은 구독자 수가 아니라 서로 다른 Where 조건 수이다. 색인은 대리자 동등성을 유지하며 등록 검색에만 사용한다. 발행 순서와 조건 평가 횟수는 바뀌지 않는다.
- 조건 수가 줄어도 색인을 유지하고, 마지막 Where 조건이 제거되면 색인도 해제한다. 따라서 임계값 부근의 등록·해제가 색인 생성과 폐기를 반복하지 않으며, 사용하지 않는 경로를 색인이 붙잡지 않는다.
- ForFlags는 위치마다 하나의 FlagsNode 안에서 마스크 비트가 같은 항목을 선형 검색하며 별도 색인을 두지 않는다. 빈 항목과 FlagsNode는 다른 경로 노드처럼 정리한다. 노드 수는 FlagsNode와 각 FlagsEntry를 각각 세지만, 경로 깊이는 ForFlags 호출 하나를 한 단계로 센다.
- When은 위치마다 WhenNode 하나를 두고 target별 항목을 사전과 null 전용 필드로 관리한다. 빈 항목은 자식 체인과 검색 구조에서 함께 제거하고, 마지막 항목이 사라지면 WhenNode도 정리한다. NodeCount는 WhenNode와 각 WhenEntry를 각각 세지만 경로 깊이는 When 호출 하나를 한 단계로 센다.
- 경로 깊이는 연산·순서 그룹·스트림 연결을 합쳐 256단계까지 허용한다. 등록·전파·종료가 깊이만큼 호출 스택을 쓰기 때문이다. 이를 넘는 경로는 구성할 때 InvalidOperationException이 발생한다.

## 설계 기준

- **공유되는 경로 노드에는 상태를 두지 않는다.** 경로 노드는 여러 구독자가 공유하므로 횟수 같은 상태를 두면 공유 기준이 상태까지 넓어진다. 상태 있는 연산자는 새 스트림을 시작하고, 상태는 그 스트림의 그래프 입구에 주입한 노드에 둔다. 이 노드는 스트림마다 하나라서 공유되지 않는다. 그래서 경로 중간의 종료도 스트림 종료 한 가지로 표현된다.
- **공급원 객체를 따로 두지 않는다.** 모든 스트림의 루트가 값을 직접 받으므로, 구독 목록을 가진 공급원은 값을 넘기는 단계만 늘린다. 외부 입력은 표준 `IObservable<T>`로 받는다.
- **Where는 대리자 동등성으로 공유한다.** 람다는 내용이 같은지 비교할 수 없고, 이름으로 묶으면 다른 조건이 조용히 합쳐질 수 있다. 그래서 메서드와 대상이 같은 대리자만 같은 조건으로 본다. 참조로 비교하지 않는 것은 C# 9에서 메서드 그룹을 넘길 때마다 대리자가 새로 만들어지기 때문이다. 같은 조건을 공유하려면 외부에 정의한 함수를 넘긴다.
- **When은 값 동등성으로 공유한다.** EqualityComparer&lt;T&gt;.Default로 같은 target을 한 항목으로 합친다. 참조 형식과 Nullable&lt;T&gt;의 null도 유효한 값이다. 부모나 순서 그룹이 다르면 공유하지 않으며, 등록 후 target의 Equals·GetHashCode 결과가 바뀌는 경우는 지원하지 않는다. ulong에서도 전체 값을 비교하므로 ForFlags와 별개의 경로이다.
- **ForFlags는 마스크 비트로 공유한다.** ulong 스트림에서 서로 다른 flags enum의 마스크를 함께 사용한다. 같은 위치에서 같은 마스크 비트는 한 항목으로 합치며, FlagsNode 묶음과 다른 형제는 생성 순서를 따른다. 완료·오류·폐기는 비트 판정을 거치지 않는다.
- **구독자는 출구에서만 관리한다.** 경로 노드는 값을 거르는 일만 맡고 구독 목록은 OutputGate 한 곳에 둔다. 그 대가로 구독 위치마다 노드가 하나 늘어난다.
- **상위 연결은 InputGate로 받는다.** 스트림 자신을 상위에 등록하면 사용자가 부른 OnCompleted와 상위의 완료를 구분할 수 없고, 상위가 완료 없이 폐기된 것도 알 수 없다. InputGate가 상위의 신호를 따로 받으므로 Merge는 입력별로 완료를 셀 수 있다.
- **그래프 안에 합류 노드를 두지 않는다.** 그래프를 트리로 유지해야 순회와 노드 정리가 단순하다. 여러 입력은 Merge가 만든 새 스트림이 받는다.
- **경로 등록은 스트림이 그래프에 연결한다.** EventPath와 EventStream은 같은 등록 계약(IRegistrable)을 구현한다. 경로는 자기 단계를 PathInfo로 만들어 앞 단계(Source)로 넘기고, 끝의 스트림이 받은 PathInfo 체인을 따라 그래프의 노드 기능으로 노드를 찾거나 만든다. PathInfo는 등록 한 번에만 쓰는 객체라 공유되지 않는다. 그래프는 경로를 모르고 노드 단위 기능만 제공한다. Where·When·Debug·ForOrder는 EventStream과 EventPath의 인스턴스 메서드이며, 스트림도 반환형인 EventPath를 참조한다. ForFlags는 ulong 스트림·경로에만 제공하므로 EventPathExtensions의 확장 메서드로 남긴다.

각 기준을 정하기 전에 쓰거나 검토한 형태와 그 대가, 보류 항목은 [설계 결정](Design%20Decisions.md)에 있다.

When의 성능은 측정하지 않았으며 Unity Mono·IL2CPP에서의 할당도 검증하지 않았다. 이전 구현의 측정 결과를 When의 성능 근거로 사용하지 않는다.

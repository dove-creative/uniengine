# EventStream

값·완료·오류를 구독자에게 전달하고, 구독과 연결의 수명을 관리하는 기본 스트림이다.

## 역할과 구성

- 책임: 입력을 받아 구독자에게 전달하고, 각 구독과 상위 연결이 언제 끊기는지 관리한다.
- 콜백 목록: 갱신·완료·오류마다 하나씩 둔다. 각각 지연 추가 모드의 [AdaptiveAction](../02-E.2-AdaptiveCollections/AdaptiveAction.md)이다.
- 구독 정보: 구독마다 발급한 핸들과, 등록용 대리자에서 원래 콜백을 찾는 표를 보관한다.
- 상위 연결: 하위로서 넘겨받은 상위 연결 핸들의 집합이다.
- 상태: Enabled, TerminationMode, 종료 중 여부, 폐기 상태를 가진다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| Subscribe | 구독마다 독립된 해제 핸들을 주어, 같은 콜백을 여러 번 등록해도 따로 해제하게 한다. |
| Chain·Connect | Observer를 연결하고, 하위가 IPassiveObserver이면 연결 핸들을 넘겨 하위가 연결을 정리하게 한다. |
| OnNext·OnCompleted·OnError | 값 전달과 종료 통지를 구분하여 알맞은 콜백 목록을 호출한다. |
| Enabled·Dispose | 값 전달의 일시 중지와 영구적인 정리를 구분한다. |
| With | 종료 정책을 바꾸고 같은 스트림을 반환하여 구성 식을 이어 쓰게 한다. |

## 동작 흐름

### 구독

1. Subscribe는 받은 콜백을 감싸는 등록용 대리자를 새로 만들고, 그 대리자에 묶인 핸들을 발급한다.
2. 등록용 대리자를 갱신 목록에 추가한다. 완료·오류 콜백은 지정한 경우에만 해당 목록에 추가한다.
3. 핸들을 Dispose하면 세 목록에서 그 등록만 제거한다. TerminationMode가 NoSubscribers이고 남은 구독이 없으면 스트림도 폐기한다.

등록용 대리자를 따로 만드는 이유는 같은 콜백을 두 번 구독한 경우에도 두 등록을 구별하기 위해서이다.

### 값 전달

1. OnNext는 폐기 여부를 먼저 검사한다. 이미 폐기되었거나 종료 중이면 ObjectDisposedException이다.
2. Enabled가 false이면 아무것도 하지 않고 반환한다.
3. 등록 순서대로 구독을 방문하여 원래 콜백을 호출한다. 원래 콜백이 여러 대리자를 합친 멀티캐스트이면 하나씩 호출하며, 매 호출 전에 구독과 스트림이 아직 유효한지 확인한다.

### 콜백 실패

1. 실패한 콜백의 구독을 해제한다.
2. 예외를 ExceptionHandler에 보고한다.
3. 보고가 정상 반환하고 스트림이 폐기되지 않았으면 다음 구독으로 진행한다.

처리기가 없거나 처리기가 예외를 던지면 그 예외가 호출자에게 전달되고 전파는 중단된다. 구독 해제 중에도 예외가 났다면, 원래 예외를 먼저 보고하고 보고가 정상 반환한 뒤 해제 예외를 전달한다.

### 종료와 폐기

1. OnCompleted·OnError는 종료 중 상태로 바꾼 뒤 완료 또는 오류 콜백을 호출한다. 이때부터 새 구독과 OnNext는 ObjectDisposedException이다.
2. 통지가 끝나면 Dispose를 호출한다. 통지 중 예외가 났더라도 폐기한 뒤 그 예외를 전달한다.
3. Dispose는 콜백 목록을 비우고, 보관한 상위 연결 핸들과 자신이 발급한 구독 핸들을 모두 해제한 뒤 폐기 상태로 바꾼다.

정리 중 일부 핸들의 해제가 실패해도 나머지를 계속 정리하고, 상태를 정리한 뒤 첫 번째 예외를 전달한다. 전파 중 변경과 연결 수명의 공통 규칙은 [모듈 개요](README.md)를 따른다.

## 설계 기준과 고려사항

콜백 목록과 구독 핸들을 함께 관리하여, 전달 대상에서 빠지는 시점과 연결이 끊기는 시점을 일치시킨다. 한 구독이 실패하면 그 구독만 해제하고, 나머지 구독을 계속 호출할지는 공통 예외 정책에 맡긴다.

- 구독은 등록 순서대로 호출한다. AdaptiveAction이 새 항목을 목록 끝에 추가하고, 제거할 때 남은 항목의 순서를 유지하기 때문이다. 전파 중 추가한 구독은 다음 전파부터 기존 구독 뒤에서 호출된다.
- 콜백 예외는 OnError 통지로 바뀌지 않는다. 그 구독의 해제와 ExceptionHandler 보고로만 처리한다.
- Dispose는 완료 통지를 보내지 않으며 하위에도 알리지 않는다. Chain으로 연결된 하위 스트림은 연결만 끊긴 채 남는다.
- 전파 중 폐기하면 실행 중인 콜백은 끝까지 실행되지만 뒤의 구독은 호출하지 않는다.
- 콜백 안에서 같은 스트림의 OnNext를 다시 호출하면, 진행 중인 순회와 겹치므로 AdaptiveAction이 InvalidOperationException으로 거부한다. 이 예외는 바깥 전파에서 그 콜백의 실패로 처리되어 구독 해제와 보고로 이어진다.
- 폐기 후 OnNext·Subscribe·Chain·Connect는 Enabled 값과 관계없이 ObjectDisposedException이다. 반면 OnCompleted·OnError·Dispose를 다시 호출하면 무시한다.
- Enabled를 true로 바꾸는 것은 폐기 후 예외이고, false로 바꾸는 것은 언제나 허용한다.
- 종료나 폐기가 진행 중일 때는 TerminationMode 변경을 무시한다.
- Chain·Connect에 자기 자신을 넘기면 ArgumentException이다.
- 기본 값 전달 경로는 구독 구성이 유지되고 사용자 콜백·조건·마스크 변환 함수가 할당하지 않는 경우 관리 힙 할당 없이 동작한다. 구독 직후의 첫 전달도 포함하며, 값 형식 이벤트를 박싱하지 않는다. OrderedEventStream의 그룹 전달과 EventRouter의 마스크 검사도 같은 기준을 따른다. 전파 중 구독 변경, 완료·폐기, 예외, Debug 로그의 할당은 이 범위에 포함하지 않는다. Take의 마지막 값처럼 완료를 유발하는 입력도 정리 비용이 발생할 수 있다.
- 이 할당 특성은 .NET 런타임의 컬렉션·대리자 구현을 전제로 한다. Unity의 Mono·IL2CPP처럼 구현이 다른 런타임에서는 결과가 달라질 수 있다.
- 파생 구현은 상태 인자를 받는 Dispatch를 사용하여 캡처를 피할 수 있다. 기존 호출 대리자·필터만 받는 Dispatch도 호환성을 위해 유지하지만, 호출자가 만든 캡처의 할당까지 없애지는 않는다.

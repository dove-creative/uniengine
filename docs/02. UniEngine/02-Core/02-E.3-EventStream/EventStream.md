# EventStream

EventStream은 값을 받아 구독 그래프로 전달하는 기본 단위이다. 같은 이벤트를 기다리는 구독자들이 조건을 공유하도록 Where 경로, 같은 target의 When 경로, 같은 마스크의 ForFlags 경로를 합치고, 마지막 수신자가 떠나면 그 경로를 정리한다.

## 입력

모든 EventStream은 OnNext로 값을 직접 받는다. 스트림마다 다른 것은 그 밖의 입력과 폐기할 때 정리하는 연결이다.

| 만드는 방법 | 다른 입력 | 폐기할 때 |
| --- | --- | --- |
| 기본 생성자 | 없음 | 구독을 해제한다. |
| 외부 IObservable을 전달한 생성자 | 외부 공급원 | 구독과 공급원 연결을 해제한다. 공급원은 폐기하지 않는다. |
| Take·TakeWhile·Skip·SkipWhile·Branch | 호출한 지점의 값 | 구독과 상위 연결을 해제한다. |
| Merge | 호출한 스트림과 인수로 받은 스트림 | 구독과 모든 입력 연결을 해제한다. |

직접 넣은 값은 구독 여부와 관계없이 위에서 온 값과 같게 처리하고 그 스트림 아래로만 흐른다. 첫 구독 전에도 Take·Skip의 횟수와 TakeWhile·SkipWhile의 조건 상태에 반영되며, 상위 연결을 만들지는 않는다. Enabled가 false이면 어느 입력의 값도 받지 않고 조건도 평가하지 않는다. 완료·오류는 계속 전달한다.

## 내부 구조

값은 입구, 경로, 출구를 차례로 지난다.

| 구성 | 형식 | 역할 |
| --- | --- | --- |
| 입구 | InputGate | 상위 하나당 하나씩 둔다. 첫 구독 전에는 연결할 위치를, 연결 후에는 해제 핸들을 가진다. 상위의 값·완료·끊김을 받아 스트림에 전달한다. 트리에 속하지 않는다. |
| 연산 | 파생 스트림의 중첩 노드 | TakeStream, TakeWhileStream, SkipStream, SkipWhileStream이 자기 노드를 중첩 클래스로 가진다. 횟수를 세는 쪽은 Counter, 조건을 보는 쪽은 Condition이다. 스트림을 만들 때 그래프의 루트로 주입되어 상태를 가지고, 끝나면 스트림의 완료 처리를 호출한다. 스트림마다 하나이며 경로 병합의 대상이 아니다. |
| 키가 있는 경로 | WhereNode·WhenNode·FlagsNode·OrderedNode | 같은 부모 연결 위치마다 종류별 노드 하나를 두고, 노드 안에 키별 행을 둔다. 같은 위치의 같은 키는 구독자와 리스너가 달라도 행을 공유한다. 다른 부모 위치의 행은 공유하지 않는다. |
| 키 행 | 각 키 노드의 내부 클래스 | 키 하나와 그 뒤의 연결을 가진다. 행은 NodeBase나 NodeChild를 상속하지 않으며 NodeCount에도 포함하지 않는다. 행은 Gate와 다음 단계 노드를 참조할 뿐, 다음 노드가 행이나 앞 노드의 일부가 되는 것은 아니다. |
| 키가 없는 경로 | 루트·DebugNode·Counter·Condition | 자기 연결 하나를 가진다. Debug는 등록마다 별도 노드이며 공유하지 않는다. Counter·Condition은 파생 스트림마다 하나이다. |
| 연결 | Connection | 행과 키 없는 노드가 함께 쓰는 형식이다. 구독자 Gate 우선 순서, 자식 체인, Registration과 정리를 맡는다. 등록할 때 다음 단계와 Gate가 참조될 위치는 이 연결이다. |
| 출구 | OutputGate | 구독 목록을 가진 말단이다. Node가 아니지만 NodeChild를 상속해 연결의 자식 자리에 들어간다. 같은 위치의 구독자는 Gate 하나를 공유한다. 새 스트림으로 가는 연결은 연결마다 Gate를 따로 둔다. |

키 검색과 행 방문은 서로 다른 책임이다. 검색 색인을 사용하더라도 발행과 종료의 방문 순서는 행 체인으로 유지한다.

| 노드 | 행 키 | 발행 | 등록 검색 |
| --- | --- | --- | --- |
| WhereNode | predicate의 대리자 동등성 | 등록 순서로 조건이 참인 모든 행 | 16행 이하는 선형, 17번째 행 등록 시 해시 색인 생성 |
| FlagsNode | enum 형식과 무관한 mask 비트 | 생성 순서로 값과 비트가 겹치는 모든 행. 값 0은 방문하지 않는다. | 16행 이하는 선형, 17번째 행 등록 시 해시 색인 생성 |
| WhenNode | EqualityComparer&lt;T&gt;.Default로 비교한 target | 사전에서 찾은 행 하나 | 항상 사전과 별도의 null 행 사용 |
| OrderedNode | order 값 | 순서 값이 작은 행부터 | 정렬 색인 |

Where·Flags의 색인은 행이 줄어도 유지하고 마지막 행을 제거할 때 해제한다. When의 null 검사는 값 형식에서 박싱하지 않는다. When 행 체인은 생성 순서이고, OrderedNode 행 체인은 순서 값 순서이다.

예를 들어 `stream.Where(a).Where(b).Subscribe(x)`는 `root → where[a] → where[b] → x`이다. 첫 WhereNode의 a행이 두 번째 WhereNode를 참조하고, 두 번째 노드의 b행이 x의 Gate를 참조한다. `stream.Where(a).Subscribe(x1)`과 `stream.Where(c).Subscribe(y)`는 `root → where[a → x1, c → y]`로 같은 위치의 WhereNode 하나에 모인다.

## 전파와 변경

연결 하나에서는 Gate의 구독자를 구독 순서대로 먼저 호출한 뒤, WhereNode·FlagsNode·WhenNode·OrderedNode·Debug·스트림 연결 자식을 생성 순서대로 깊이 우선 방문한다. 각 노드 안에서는 위 표의 행 순서를 따른다. 완료·오류·폐기도 같은 순서이며, 조건·키와 관계없이 모든 행의 연결에 전달한다. 명시적 Dispose는 값을 보내거나 완료를 통지하지 않는다.

같은 위치에 Where(a), ForFlags(m), Where(b) 순서로 등록하면 WhereNode의 a, b행을 먼저 방문한 뒤 FlagsNode를 방문한다. 이전의 a → flags → b 순서는 유지하지 않는다. ForFlags(a) 한 번, ForFlags(b) 두 번, ForFlags(c) 두 번을 등록하면 `root → flags[a, b → b1 b2, c → c1 c2]`이며, 발행 비트가 b와 c에 겹치면 b1 → b2 → c1 → c2 순서로 호출한다.

발행 중 추가한 행·노드·구독은 다음 발행부터 보인다. 제거는 즉시 반영하며, 제거한 뒤 같은 키로 다시 만든 행도 이번 값은 받지 않는다. 현재 행이나 다음 행을 제거해도 남은 행과 형제는 계속 방문한다. 방문 대상은 연결 상태와 발행 시작 시점의 Registration 범위 안에 있어야 하며, When이 사전에서 찾은 행도 같은 검사를 거친다.

같은 스트림에 콜백 안에서 다시 값을 넣으면 InvalidOperationException이 발생한다. 콜백의 실패는 해당 구독만, 조건의 실패는 그 아래 경로를 해제한다. 실패를 ExceptionHandler.Report에 넘기며 보고가 예외를 던져도 나머지 구독을 계속 방문한다. 순회를 마친 뒤 첫 보고 예외를 값을 넣은 쪽에 전달한다. 스트림 사이의 연결은 이 예외 때문에 끊기지 않는다. 외부 Observable이 관찰자 예외를 잡거나 구독을 종료하는 방식은 그 공급원의 계약을 따른다.

Where 조건 예외는 해당 행의 연결만 통지 없이 해제하며, 같은 WhereNode의 다른 행은 유지한다. Debug 로그 예외는 그 Debug의 연결을 해제하고 TakeWhile·SkipWhile 조건 예외는 그 스트림을 폐기한다.

When의 비교가 발행 중 실패하면 그 위치의 WhenNode와 모든 target 행의 연결을 통지 없이 해제하고 형제 경로는 계속 방문한다. 정리 중 중첩된 When이 실패한 비교를 다시 호출하지 않도록 검색 사전을 먼저 비운다. 등록 중 비교 예외는 Subscribe 호출자에게 전파하며, 실패한 등록으로 새로 만든 빈 행과 노드는 정리한다. 이 정리로 구독이 하나도 남지 않은 연산자·Branch·Merge 스트림은 아래 수명 규칙에 따라 폐기된다.

## 구독과 연결의 수명

구독 핸들을 해제하면 더는 쓰지 않는 행과 노드가 제거된다. 자식은 자기가 속한 연결을 알고 행은 자기 키를 안다. 연결이 비면 소유 노드가 행의 키로 바로 제거하며, 마지막 행이 사라지면 그 노드도 부모 연결에서 제거한다. 역방향 표는 두지 않는다. When 사전에서 행을 지울 때도 키 비교가 필요하므로 등록 뒤 target의 Equals·GetHashCode 결과가 바뀌는 경우는 지원하지 않는다. 사용자가 만든 EventStream은 마지막 구독이 떠난 뒤에도 다시 구독할 수 있고, 상위가 폐기되어도 살아 있다.

연산자·Branch·Merge가 만든 스트림은 첫 구독 때 상위와 연결되고 마지막 구독이 떠나면 스스로 폐기된다. When의 target 비교 예외처럼 첫 구독이 등록 중 실패해 남은 구독이 없을 때도 같은 규칙으로 상위 연결을 해제하고 폐기되며, 이후 구독은 ObjectDisposedException으로 거부한다. 상위가 완료·오류로 끝나면 같은 신호를 받고, 상위가 폐기되면 통지 없이 폐기된다. 입력이 여럿인 Merge의 수명은 [Branch와 Merge](BranchAndMerge.md)에 있다.

## 경로 크기

- Where·Flags의 적응형 색인 기준은 구독자 수가 아니라 해당 노드의 서로 다른 키 행 수이다. 색인은 등록 검색에만 사용하며 발행 순서와 조건 평가 횟수를 바꾸지 않는다.
- NodeCount는 각 경로 노드와 스트림 연결 전용 OutputGate를 세고, 루트·공유 구독 Gate·키 행·Connection은 세지 않는다. 같은 위치에 키가 늘어도 종류별 노드는 하나이며, 다음 경로 단계에는 별도 노드가 생긴다.
- 경로 깊이는 연산·순서 그룹·스트림 연결을 합쳐 256단계까지 허용한다. 등록·전파·종료가 깊이만큼 호출 스택을 쓰기 때문이다. 이를 넘는 경로는 구성할 때 InvalidOperationException이 발생한다.

## 설계 기준

- **공유되는 경로 노드에는 상태를 두지 않는다.** 경로 노드는 여러 구독자가 공유하므로 횟수 같은 상태를 두면 공유 기준이 상태까지 넓어진다. 상태 있는 연산자는 새 스트림을 시작하고, 상태는 그 스트림의 그래프 입구에 주입한 노드에 둔다. 이 노드는 스트림마다 하나라서 공유되지 않는다. 그래서 경로 중간의 종료도 스트림 종료 한 가지로 표현된다.
- **공급원 객체를 따로 두지 않는다.** 모든 스트림의 루트가 값을 직접 받으므로, 구독 목록을 가진 공급원은 값을 넘기는 단계만 늘린다. 외부 입력은 표준 `IObservable<T>`로 받는다.
- **Where는 대리자 동등성으로 공유한다.** 람다는 내용이 같은지 비교할 수 없고, 이름으로 묶으면 다른 조건이 조용히 합쳐질 수 있다. 그래서 메서드와 대상이 같은 대리자만 같은 조건으로 본다. 참조로 비교하지 않는 것은 C# 9에서 메서드 그룹을 넘길 때마다 대리자가 새로 만들어지기 때문이다. 같은 조건을 공유하려면 외부에 정의한 함수를 넘긴다.
- **When은 값 동등성으로 공유한다.** EqualityComparer&lt;T&gt;.Default로 같은 target을 한 항목으로 합친다. 참조 형식과 Nullable&lt;T&gt;의 null도 유효한 값이다. 부모나 순서 그룹이 다르면 공유하지 않으며, 등록 후 target의 Equals·GetHashCode 결과가 바뀌는 경우는 지원하지 않는다. ulong에서도 전체 값을 비교하므로 ForFlags와 별개의 경로이다.
- **ForFlags는 마스크 비트로 공유한다.** ulong 스트림에서 서로 다른 flags enum의 마스크를 함께 사용한다. 같은 위치에서 같은 마스크 비트는 한 항목으로 합치며, FlagsNode 묶음과 다른 형제는 생성 순서를 따른다. 완료·오류·폐기는 비트 판정을 거치지 않는다.
- **구독자는 출구에서만 관리한다.** 경로 노드는 값을 거르는 일만 맡고 구독 목록은 OutputGate 한 곳에 둔다. 그 대가로 구독 위치마다 Gate 객체가 하나 늘어난다. 공유 구독 Gate는 NodeCount에서 제외하고 스트림 연결 전용 Gate는 포함한다.
- **상위 연결은 InputGate로 받는다.** 스트림 자신을 상위에 등록하면 사용자가 부른 OnCompleted와 상위의 완료를 구분할 수 없고, 상위가 완료 없이 폐기된 것도 알 수 없다. InputGate가 상위의 신호를 따로 받으므로 Merge는 입력별로 완료를 셀 수 있다.
- **그래프 안에 합류 노드를 두지 않는다.** 그래프를 트리로 유지해야 순회와 노드 정리가 단순하다. 여러 입력은 Merge가 만든 새 스트림이 받는다.
- **경로 등록은 스트림이 그래프에 연결한다.** EventPath와 EventStream은 같은 등록 계약(IRegistrable)을 구현한다. 경로는 자기 단계를 PathInfo로 만들어 앞 단계(Source)로 넘기고, 끝의 스트림이 받은 PathInfo 체인을 따라 그래프의 노드 기능으로 노드를 찾거나 만든다. PathInfo는 등록 한 번에만 쓰는 객체라 공유되지 않는다. 그래프는 경로를 모르고 노드 단위 기능만 제공한다. Where·When·Debug·ForOrder는 EventStream과 EventPath의 인스턴스 메서드이며, 스트림도 반환형인 EventPath를 참조한다. ForFlags는 ulong 스트림·경로에만 제공하므로 EventPathExtensions의 확장 메서드로 남긴다.

각 기준을 정하기 전에 쓰거나 검토한 형태와 그 대가, 보류 항목은 [설계 결정](Design%20Decisions.md)에 있다.

When의 성능은 측정하지 않았으며 Unity Mono·IL2CPP에서의 할당도 검증하지 않았다. 이전 구현의 측정 결과를 When의 성능 근거로 사용하지 않는다.

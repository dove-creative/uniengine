# EventStream

EventStream은 값을 받아 구독 그래프로 전달하는 기본 단위이다. 같은 이벤트를 기다리는 구독자들이 조건을 한 번만 평가하도록 Where 경로나 같은 마스크의 ForFlags 경로를 합치고, 마지막 수신자가 떠나면 그 경로를 정리한다.

## 입력

모든 EventStream은 OnNext로 값을 직접 받는다. 스트림마다 다른 것은 그 밖의 입력과 폐기할 때 정리하는 연결이다.

| 만드는 방법 | 다른 입력 | 폐기할 때 |
| --- | --- | --- |
| 기본 생성자 | 없음 | 구독을 해제한다. |
| 외부 IObservable을 전달한 생성자 | 외부 공급원 | 구독과 공급원 연결을 해제한다. 공급원은 폐기하지 않는다. |
| Take·TakeWhile·Skip·SkipWhile·Branch | 호출한 지점의 값 | 구독과 상위 연결을 해제한다. |
| Merge | 호출한 스트림과 인수로 받은 스트림 | 구독과 모든 입력 연결을 해제한다. |

직접 넣은 값은 구독 여부와 관계없이 위에서 온 값과 같게 처리하고 그 스트림 아래로만 흐른다. 첫 구독 전에도 Take·Skip의 횟수와 TakeWhile·SkipWhile의 조건 상태에 반영되며, 상위 연결을 만들지는 않는다. Enabled가 false이면 어느 입력의 값도 받지 않고 조건도 평가하지 않는다. 완료·오류는 계속 전달한다.

## 내부 구조

값은 입구, 경로, 출구를 차례로 지난다.

| 구성 | 형식 | 역할 |
| --- | --- | --- |
| 입구 | InputGate | 상위 하나당 하나씩 둔다. 첫 구독 전에는 연결할 위치를, 연결 후에는 해제 핸들을 가진다. 상위의 값·완료·끊김을 받아 스트림에 전달한다. 트리에 속하지 않는다. |
| 연산 | 파생 스트림의 중첩 노드 | TakeStream, TakeWhileStream, SkipStream, SkipWhileStream이 자기 노드를 중첩 클래스로 가진다. 횟수를 세는 쪽은 Counter, 조건을 보는 쪽은 Condition이다. 스트림을 만들 때 그래프의 루트로 주입되어 상태를 가지고, 끝나면 스트림의 완료 처리를 호출한다. 스트림마다 하나이며 경로 병합의 대상이 아니다. |
| 경로 | NodeBase 파생 형식 | 자식을 추가 순서로 두는 Node와 순서 값과 실행 방식으로 두는 OrderedNode, 비트 조건을 묶는 FlagsNode가 있다. 루트와 동기 순서별 노드는 Node 자체이고 병렬 순서별 노드는 ParallelGroup이다. Where·Debug·FlagsEntry는 Node를 상속한다. 같은 위치의 순서 그룹은 OrderedNode 하나에 모인다. 값을 거르거나 통과시킬 뿐 구독자를 갖지 않는다. |
| 비트 조건 | FlagsNode·FlagsEntry | FlagsNode는 같은 위치에 하나만 두고, 마스크를 가진 FlagsEntry만 자식으로 가진다. 같은 마스크 비트의 항목을 공유하며, 값과 비트가 하나라도 겹친 항목만 통과시킨다. enum 형식이 달라도 비트가 같으면 공유하고, 순서 그룹이 다르면 공유하지 않는다. |
| 출구 | OutputGate | 구독 목록을 가진 말단이다. Node가 아니지만 NodeChild를 상속해 노드의 자식 자리에 들어간다. 같은 위치의 구독자는 Gate 하나를 공유한다. 새 스트림으로 가는 연결은 연결마다 Gate를 따로 둔다. |

## 전파와 변경

ForOrder·ForOrderAsync의 명시적인 Order 사이에서만 실행 순서를 보장한다. 일반 노드·구독 사이에는 등록·생성 순서 보장이 없다. 전파 중 등록·삭제는 루트·Order 종료 때 반영하며, 실행 중인 상위 단위의 변경은 그 상위 종료까지 미룬다. 추가한 구독은 소유 스트림의 다음 발행부터 참여한다. 완료·오류는 조건과 관계없이 통지하며 명시적 Dispose는 완료를 통지하지 않는다.

같은 스트림에 콜백 안에서 다시 값을 넣으면 InvalidOperationException이 발생한다. 폐기 요청 이후의 새 발행·구독은 ObjectDisposedException으로 거부한다. 콜백의 실패는 해당 구독만, 조건의 실패는 그 아래 경로를 정리한다. ExceptionHandler.Report가 정상 반환하면 계속하고, 예외를 다시 던지면 새 호출을 중단한다. 이미 시작한 병렬 작업과 필요한 정리를 마친 뒤 첫 미처리 예외를 전달한다. 스트림 사이의 연결은 내부 구독자의 예외 때문에 끊기지 않는다. 외부 Observable의 예외 처리 방식은 공급원의 계약을 따른다.

ForOrderAsync 경로에서는 다음 대기 지점까지 구독을 수집해 작업 스레드에서 병렬 실행한다. 작업 완료 대기와 구조 변경 반영은 서로 다른 경계이다. 같은 Order의 Async·Sync가 변경 큐를 공유하며, 일반 동기 경로도 같은 지연 반영 규칙을 따른다. 자세한 계약은 [순서 그룹](OrderGroups.md)을 따른다.

## 구독과 연결의 수명

구독 핸들을 해제하면 더는 쓰지 않는 노드가 부모에서 제거된다. 사용자가 만든 EventStream은 마지막 구독이 떠난 뒤에도 다시 구독할 수 있고, 상위가 폐기되어도 살아 있다.

연산자·Branch·Merge가 만든 스트림은 첫 구독 때 상위와 연결되고 마지막 구독이 떠나면 스스로 폐기된다. 상위가 완료·오류로 끝나면 같은 신호를 받고, 상위가 폐기되면 통지 없이 폐기된다. 입력이 여럿인 Merge의 수명은 [Branch와 Merge](BranchAndMerge.md)에 있다.

## 경로 크기

- Where 조건이 적은 부모에서는 자식을 훑어 같은 대리자를 찾고, 조건 수가 임계값을 넘으면 그 부모에만 해시 색인을 만든다. 기준은 구독자 수가 아니라 서로 다른 Where 조건 수이다. 색인은 대리자 동등성을 유지하며 등록 검색에만 사용한다. 발행 순서와 조건 평가 횟수는 바뀌지 않는다.
- 조건 수가 줄어도 색인을 유지하고, 마지막 Where 조건이 제거되면 색인도 해제한다. 따라서 임계값 부근의 등록·해제가 색인 생성과 폐기를 반복하지 않으며, 사용하지 않는 경로를 색인이 붙잡지 않는다.
- ForFlags는 위치마다 하나의 FlagsNode 안에서 마스크 비트가 같은 항목을 선형 검색하며 별도 색인을 두지 않는다. 빈 항목과 FlagsNode는 다른 경로 노드처럼 정리한다. 노드 수는 FlagsNode와 각 FlagsEntry를 각각 세지만, 경로 깊이는 ForFlags 호출 하나를 한 단계로 센다.
- 경로 깊이는 연산·순서 그룹·스트림 연결을 합쳐 256단계까지 허용한다. 등록·전파·종료가 깊이만큼 호출 스택을 쓰기 때문이다. 이를 넘는 경로는 구성할 때 InvalidOperationException이 발생한다.

## 설계 기준

- **공유되는 경로 노드에는 상태를 두지 않는다.** 경로 노드는 여러 구독자가 공유하므로 횟수 같은 상태를 두면 공유 기준이 상태까지 넓어진다. 상태 있는 연산자는 새 스트림을 시작하고, 상태는 그 스트림의 그래프 입구에 주입한 노드에 둔다. 이 노드는 스트림마다 하나라서 공유되지 않는다. 그래서 경로 중간의 종료도 스트림 종료 한 가지로 표현된다.
- **공급원 객체를 따로 두지 않는다.** 모든 스트림의 루트가 값을 직접 받으므로, 구독 목록을 가진 공급원은 값을 넘기는 단계만 늘린다. 외부 입력은 표준 `IObservable<T>`로 받는다.
- **Where는 대리자 동등성으로 공유한다.** 람다는 내용이 같은지 비교할 수 없고, 이름으로 묶으면 다른 조건이 조용히 합쳐질 수 있다. 그래서 메서드와 대상이 같은 대리자만 같은 조건으로 본다. 참조로 비교하지 않는 것은 C# 9에서 메서드 그룹을 넘길 때마다 대리자가 새로 만들어지기 때문이다. 같은 조건을 공유하려면 외부에 정의한 함수를 넘긴다.
- **ForFlags는 마스크 비트로 공유한다.** ulong 스트림에서 서로 다른 flags enum의 마스크를 함께 사용한다. 같은 위치에서 같은 마스크 비트는 한 항목으로 합치며, FlagsNode 묶음과 다른 형제 사이에는 순서를 보장하지 않는다. 완료·오류·폐기는 비트 판정을 거치지 않는다.
- **구독자는 출구에서만 관리한다.** 경로 노드는 값을 거르는 일만 맡고 구독 목록은 OutputGate 한 곳에 둔다. 그 대가로 구독 위치마다 노드가 하나 늘어난다.
- **상위 연결은 InputGate로 받는다.** 스트림 자신을 상위에 등록하면 사용자가 부른 OnCompleted와 상위의 완료를 구분할 수 없고, 상위가 완료 없이 폐기된 것도 알 수 없다. InputGate가 상위의 신호를 따로 받으므로 Merge는 입력별로 완료를 셀 수 있다.
- **그래프 안에 합류 노드를 두지 않는다.** 그래프를 트리로 유지해야 순회와 노드 정리가 단순하다. 여러 입력은 Merge가 만든 새 스트림이 받는다.
- **의존은 EventPath → EventStream → EventGraph 한 방향이다.** EventPath와 EventStream은 같은 등록 계약(IRegistrable)을 구현한다. 경로는 자기 단계를 PathInfo로 만들어 앞 단계(Source)로 넘기기만 하고, 끝의 스트림이 받은 PathInfo 체인을 따라 그래프의 노드 기능으로 노드를 찾거나 만든다. PathInfo는 등록 한 번에만 쓰는 객체라 공유되지 않는다. 등록 시에는 경로에 해당하는 기존 변경 반영 단위를 조회하여 안전한 반영 경계를 정한다. Where·ForFlags·Debug·ForOrder·ForOrderAsync는 EventPath 쪽의 확장 메서드라서 스트림에서 호출하는 방법은 같다. ForFlags는 ulong 경로에서만 쓸 수 있도록 EventPath에서도 확장 메서드로 제공한다.

각 기준을 정하기 전에 쓰거나 검토한 형태와 그 대가, 보류 항목은 [설계 결정](Design%20Decisions.md)에 있다.

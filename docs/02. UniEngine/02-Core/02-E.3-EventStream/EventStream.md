# EventStream

EventStream은 값을 받아 구독 그래프로 전달하는 기본 단위이다. 같은 이벤트를 기다리는 구독자들이 조건을 한 번만 평가하도록 Where 경로를 합치고, 마지막 수신자가 떠나면 그 경로를 정리한다.

## 입력

모든 EventStream은 OnNext로 값을 직접 받는다. 스트림마다 다른 것은 그 밖의 입력과 폐기할 때 정리하는 연결이다.

| 만드는 방법 | 다른 입력 | 폐기할 때 |
| --- | --- | --- |
| 기본 생성자 | 없음 | 구독을 해제한다. |
| 외부 IObservable을 전달한 생성자 | 외부 공급원 | 구독과 공급원 연결을 해제한다. 공급원은 폐기하지 않는다. |
| Take·TakeWhile·Skip·SkipWhile·Branch | 호출한 지점의 값 | 구독과 상위 연결을 해제한다. |
| Merge | 호출한 스트림과 인수로 받은 스트림 | 구독과 모든 입력 연결을 해제한다. |

직접 넣은 값은 위에서 온 값과 같게 처리하고 그 스트림 아래로만 흐른다. Take는 직접 넣은 값도 횟수에서 차감한다. Enabled가 false이면 어느 입력의 값도 받지 않고 조건도 평가하지 않는다. 완료·오류는 계속 전달한다.

## 전파와 변경

각 노드는 먼저 자신의 구독을 등록 순서대로 호출하고 자식을 방문한다. 전파 중 추가한 노드·구독은 다음 값부터 보인다. 구독 해제는 즉시 반영하므로 같은 값에서 차례를 기다리는 콜백도 건너뛴다. 완료와 오류는 조건과 관계없이 활성 구독을 순회한 뒤 폐기한다. 명시적 Dispose는 값을 보내거나 완료를 통지하지 않는다.

같은 스트림에 콜백 안에서 다시 값을 넣으면 InvalidOperationException이 발생한다. 콜백의 실패는 해당 구독만, 조건의 실패는 그 아래 경로를 해제한다. 실패를 ExceptionHandler.Report에 넘기며 보고가 예외를 던져도 나머지 구독을 계속 방문한다. 순회를 마친 뒤 첫 보고 예외를 값을 넣은 쪽에 전달한다. 스트림 사이의 연결은 이 예외 때문에 끊기지 않는다. 외부 Observable이 관찰자 예외를 잡거나 구독을 종료하는 방식은 그 공급원의 계약을 따른다.

## 구독과 연결의 수명

구독 핸들을 해제하면 더는 쓰지 않는 노드가 부모에서 제거된다. 사용자가 만든 EventStream은 마지막 구독이 떠난 뒤에도 다시 구독할 수 있고, 상위가 폐기되어도 살아 있다.

연산자·Branch·Merge가 만든 스트림은 첫 구독 때 상위와 연결되고 마지막 구독이 떠나면 스스로 폐기된다. 상위가 완료·오류로 끝나면 같은 신호를 받고, 상위가 폐기되면 통지 없이 폐기된다. 입력이 여럿인 Merge의 수명은 [Branch와 Merge](BranchAndMerge.md)에 있다.

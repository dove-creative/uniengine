# EventRouter

이벤트의 비트 마스크와 구독 마스크가 겹치는 수신자에게만 값을 전달하는 EventStream이다.

2. 동작 흐름

4. 구현 연결

## 역할과 구성

- 책임: 수신자가 관심 있는 이벤트 분류만 받도록 값을 받을 대상을 고른다.
- 마스크 변환 함수: 이벤트 값을 uint 마스크로 바꾼다. 생성자에서 받는다.
- 구독 마스크 표: 대상을 지정한 구독마다 관심 마스크를 기록한다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| 대상을 받는 Subscribe | 대상 하나 또는 여러 개의 마스크를 구독에 묶는다. |
| 대상을 받는 Chain·Connect | 라우팅 조건을 유지한 채 Observer를 경로에 연결한다. |
| OnNext | 마스크가 겹치는 구독만 호출한다. |

## 동작 흐름

1. 구독할 때 대상 값을 변환 함수로 마스크로 바꾸어 기록한다. 대상이 여러 개이면 각 마스크를 OR로 합친다.
2. OnNext가 들어온 값의 마스크를 계산한다.
3. 구독마다 두 마스크에 공통 비트가 하나라도 있는지 HasAny로 확인하고, 있으면 호출한다. 대상 없이 등록한 일반 구독은 항상 호출한다.
4. 구독 핸들을 해제하면 그 구독의 마스크도 지운다.

예를 들어 [Flags] 열거형 Changes가 Health = 1, Mana = 2, Inventory = 4이고 변환 함수가 값을 그대로 uint로 바꾼다고 하자. Health와 Mana를 대상으로 한 구독의 마스크는 3이다.

| 들어온 값 | 마스크 | 마스크 3인 구독 |
| --- | --- | --- |
| Health | 1 | 받는다 |
| Inventory | 4 | 받지 않는다 |
| Health, Inventory | 5 | 받는다 |

OrderedEventStream이 실행 단계를 정하는 것과 달리, 라우터는 한 입력을 받을 수신자를 고른다. 연결·구독 수명과 전파 중 변경은 [모듈 개요](README.md)의 공통 규칙을 따른다.

## 설계 기준과 고려사항

같은 값인지 비교하지 않고, 비트가 하나라도 겹치는지를 본다. 한 이벤트가 여러 분류에 동시에 속하는 경우를 하나의 마스크로 표현하기 위해서이다. 마스크의 의미는 변환 함수가 정하므로 라우터는 특정 이벤트 형식을 알지 못한다.

- 변환 함수가 없으면 모든 값의 마스크가 uint.MaxValue가 되어, 빈 대상 목록으로 등록한 구독을 제외하면 모든 값을 받는다.
- 대상 목록이 비어 있으면 구독 마스크가 0이 되어 어떤 값도 받지 않는다. 마스크가 0인 이벤트도 대상을 지정한 구독에는 전달되지 않는다.
- 대상을 지정하지 않은 Subscribe·Chain·Connect는 기본 EventStream 구독 경로를 사용한다. 이 구독에는 마스크 정보가 없으므로 같은 전파 순회에서 마스크 제한 없이 모든 값을 받는다.
- 완료·오류 통지는 마스크와 관계없이 모든 구독에 전달한다.
- 변환 함수를 실행하는 도중 스트림이 폐기되면 그 값은 전달하지 않는다.

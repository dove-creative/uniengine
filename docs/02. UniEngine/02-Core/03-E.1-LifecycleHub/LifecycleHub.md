# LifecycleHub

갱신 이벤트 없이 객체의 폐기 완료만 연결된 수신자에게 알리는 허브이다.

## 목차

- 역할과 구성
- 동작 흐름
- 설계 기준과 고려사항

## 역할과 구성

- 책임: 갱신 전달이 필요 없는 객체에 폐기 완료 연결만 제공한다.
- 보유 정보: 식별자별 Action을 보관하는 하나의 사전과 폐기 상태를 보관한다.

| 등록 경로 | 식별자 | 완료 콜백 |
| --- | --- | --- |
| Connect(client).OnDisposed(callback) | client | callback |
| OnDisposed += callback | callback | callback |

| 제공 서비스 | 제공 이유 |
| --- | --- |
| Connect·Builder.OnDisposed | 수신자별 완료 반응을 구성하여 소유자의 끝을 관찰하게 한다. |
| Disconnect | 종료 전에 더 이상 필요 없는 수신자 연결을 제거한다. |
| Dispose·OnDisposed | 완료 상태를 통지하고 허브가 보관한 연결 참조를 정리한다. |

## 동작 흐름

Dispose는 IsDisposed를 먼저 true로 바꾸고 하나의 사전에 등록된 Action을 호출한다. 직접 구독과 client 연결은 같은 순회를 사용하며 경로별 알림 단계를 두지 않는다. 콜백이 실패하면 해당 Action의 나머지 멀티캐스트 호출은 생략하고 ExceptionHandler에 보고한다. 보고가 정상 반환하면 나머지 등록을 계속 통지하며, 보고가 예외를 전파하면 순회를 중단한다. 정상 종료든 예외로 중단되든 전체 참조를 비운다.

직접 구독의 -=는 대리자를 식별자로 하여 Disconnect와 같은 해제 경로를 사용한다. 멀티캐스트를 한 번에 등록했다면 같은 묶음으로 해제해야 하며 내부 콜백만 따로 제거하지 않는다. 식별자를 공유하므로 직접 구독도 Disconnect(callback)으로 해제할 수 있고, 대리자를 client로 사용한 연결은 같은 대리자를 -=에 넘겨 해제할 수 있다.

## 설계 기준과 고려사항

완료 알림만 필요한 객체에 갱신·수면·필터 상태를 추가하지 않도록 [EventHub](../03-E.2-EventHub/EventHub.md)보다 작은 책임을 가진다. 완료 상태를 먼저 확정한 뒤 연결별 알림을 통지하여 완료 알림 안에서 새 연결이 생기지 않게 한다.

- client 연결은 Builder.OnDisposed에서, 직접 구독은 +=에서 등록이 확정된다. 같은 식별자의 중복 등록은 경로에 관계없이 InvalidOperationException으로 거부하고 기존 등록을 유지한다. 따라서 같은 대리자의 직접 중복 구독도 거부한다.
- 직접 +=와 -=에 전달한 null은 활성 상태에서 무시한다. client 연결의 null 콜백은 등록할 수 있으며 통지할 때 건너뛴다.
- 등록 간 통지 순서는 사전 순회를 따르며, 등록 순서나 client·직접 구독 사이의 우선순위를 공개 계약으로 보장하지 않는다. 멀티캐스트 Action 내부의 호출 순서는 유지한다.
- 폐기 중·완료 후 Disconnect는 무시하므로 통지 중 다른 연결의 완료 알림을 취소하는 용도로 사용할 수 없다.
- 폐기 중·완료 후 반복 Dispose는 무시한다.
- IsDisposed가 true로 전환된 뒤에는 직접 이벤트의 -=도 무시한다. 폐기 중 새 등록은 거부한다.
- 공개 Dispose 메서드는 있지만 현재 형식 선언에 IDisposable 구현은 없다.

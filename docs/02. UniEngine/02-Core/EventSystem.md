# Event System

객체 사이의 연결을 유지하고 변경·실패·폐기 상황에서도 이벤트 전달 상태를 정리하는 기능 묶음이다.

## 목차

- 소개
- 구성과 책임
- 연결과 전파
- 실패와 폐기

## 소개

| 항목 | 설명 |
| --- | --- |
| 개요 | 연결된 객체 사이에서 이벤트를 전달하고 구독·종료의 수명을 관리한다. |
| 목적 | 수신자 변경이나 실패, 객체 폐기가 다른 연결의 정합성을 훼손하지 않게 한다. |
| 구현 | 해제 동작, 변경 가능한 순회, 스트림 전파, 객체별 허브를 각각의 책임으로 구성한다. |

## 구성과 책임

## 연결과 전파

Subscribe는 연결 해제 핸들을 반환한다. Take·Skip·Branch·Merge가 만든 스트림은 상위와의 연결을 스스로 소유하며, 자신이 폐기될 때 그 연결을 해제한다.

기본 틱은 호스트가 EventStream.Main에 직전 틱 이후의 경과 시간(float, 초)을 발행한다. 호스트는 이벤트 전파 밖에서 ResetMain으로 세션을 준비하고 구독을 등록하며, 종료 시 Main을 폐기한다. 초기화로 교체된 스트림의 구독은 새 Main으로 이전하지 않는다. 시간 계산과 실행 루프는 호스트의 책임이다.

EventStream은 UE 이벤트 전파 규칙을 루트·Order 단위에 적용한다. 같은 위치의 Order 값 오름차순과 같은 값의 Async → Sync 순서를 보장하며 일반 노드·구독의 등록 순서는 보장하지 않는다. 등록·삭제는 루트·Order 종료 때 반영하고 새 구독은 소유 스트림의 다음 발행부터 참여한다. 실행 중인 상위 단위의 변경은 그 상위 종료까지 미룬다.

EventHub는 모든 리스너와 직접 Updated 구독을 내부 스트림의 그래프 하나에 등록한다. Builder는 OnUpdated·OnUpdatedWhere·OnUpdatedWhen·OnUpdatedForFlags로 루트 또는 단일 조건의 콜백을 등록하고 같은 인스턴스를 반환한다. 각 등록은 독립되며, 복합 판정은 조건 함수 안에서 표현한다. Connection이 조건을 스트림 경로로 연결하고, 갱신 등록 사이의 순서는 보장하지 않으며 구독 변경은 내부 루트 종료 때 반영한다. 같은 위치의 같은 조건 대리자, 동등한 target, 같은 마스크 비트는 리스너가 달라도 공유된다. 객체별 구독 핸들과 생애주기는 Hub가, 갱신 전파·변경 반영·실패한 구독 해제와 예외 보고는 스트림이 담당한다.

## 실패와 폐기

EventStream은 실패한 구독·경로를 정리하고 ExceptionHandler에 보고한다. 처리되면 계속하고 재전파되면 새 호출을 중단한다. 이미 시작한 병렬 작업과 변경 큐 정리를 끝낸 뒤 첫 미처리 예외를 발행자에게 전달한다.

폐기 요청 후 새 전파·연결은 거부한다. 반복 Dispose와 완료 후 해제는 안전하게 무시한다. EventStream의 완료·오류 입력은 통지 후 폐기로 이어지며 명시적인 Dispose가 완료 이벤트를 대신 발생시키지는 않는다.

각 객체의 알림 시점은 별도로 확인해야 한다. Handle은 콜백 전에 IsDisposed를 전환한다. EventHub는 Disposing과 Disposed 사이에 전환한다. LifecycleHub는 완료 상태를 먼저 전환하고 연결별 완료 알림을 통지한다. 생애주기 콜백 도중 예외가 재전파되면 뒤의 통지가 생략될 수 있다.

설계 원칙은 [이벤트](../../01.%20Concepts/04.%20이벤트.md)와 [객체 활동과 연결 원칙](../../01.%20Concepts/03.%20객체%20활동과%20연결%20원칙.md)을 따른다. 재진입 정책은 객체별로 다르며, AdaptiveCollection과 이를 사용하는 EventStream 계열은 중첩 순회를 거부하고 EventHub.Update는 재진입 호출을 생략한다.

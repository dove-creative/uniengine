# Usm

USM(Unified State Machine)은 다음 행동을 결정하는 규칙을 전이기(Transitioner)라는 독립된 객체로 표현하여, 유한 상태 기계(FSM)·계층형 유한 상태 기계(HFSM)의 명시적 전이와 행동 트리(BT)의 행동 조합을 한 노드 트리에서 다루는 제어 모델이다.

## 목차

- 소개
- FSM과 행동 트리를 함께 쓰는 이유
- 전이기의 1급화
- 트리의 구성과 소유
- 한 번의 갱신
- 전이기 선택

## 소개

| 항목 | 설명 |
| --- | --- |
| 개요 | 노드는 작업 결과를 반환하고, 부모의 전이기는 그 결과와 자신의 규칙에 따라 다음 행동을 결정한다. |
| 목적 | 전환 경로가 중요한 구간은 상태로 표현하고, 행동의 순서나 우선순위가 중요한 구간은 트리로 조합할 수 있게 한다. |
| 구현 | 각 Node에 작업을 수행할 Work와 자식을 제어할 전이기를 조립한다. 호스트는 루트를 초기화하고 Update 또는 Stop을 호출한다. |

## FSM과 행동 트리를 함께 쓰는 이유

게임 AI에서 경비병의 행동을 FSM으로 표현하면 '순찰 중 적을 발견하면 추적으로 전환한다'처럼 현재 상태와 다음 상태를 명시할 수 있다. HFSM은 한 상태 안에 하위 상태를 두어 행동을 세분화한다. 상태와 예외 경로가 늘어나면 행동 하나를 추가할 때도 여러 상태의 진입·이탈 조건을 함께 검토해야 한다.

BT는 조건과 행동을 우선순위나 실행 순서에 따라 조합한다. 예를 들어 '목적지 선정 → 이동 → 주변 확인'을 순서대로 묶으면 순찰 행동이 된다. 다만 여러 분기에 걸쳐 예외를 처리하는 트리에서는 지금 실행 중인 행동이 '순찰'인지 '추적'인지 알려면 선택 경로를 따라가야 할 수 있다.

상위 모드에는 HFSM을, 세부 행동에는 BT를 쓰면 두 표현의 장점을 살릴 수 있다. 둘을 별도 실행기로 구성하면 하위 트리의 어느 결과가 상위 상태의 어떤 전이를 일으키는지도 따로 정해야 한다. USM은 두 모델이 공통으로 답하는 질문, 즉 '지금 얻은 정보로 다음에 무엇을 실행할 것인가'를 전이기에 맡긴다.

## 전이기의 1급화

USM에서 전이기를 1급 객체로 다룬다는 말은 개발자가 선택 규칙 자체를 객체로 만들어 노드를 구성할 때 전달할 수 있다는 뜻이다. Work는 행동을 수행하고, 전이기는 ITransitioner 계약에 따라 자식을 진행하고 부모에게 결과를 반환한다. 상태 전이표를 읽는 MatrixTransitioner와 자식을 차례로 실행하는 Sequence가 같은 자리에 들어갈 수 있는 이유이다.

노드가 반환하는 OperationInfo는 실행의 진행·종료를 나타내는 상세 상태와 작업이 산출한 값인 Result를 함께 담는다. 경비병의 순찰과 추적은 다음과 같이 연결할 수 있다.

1. 상위 노드의 MatrixTransitioner가 '순찰' 노드를 선택한다. 순찰 노드의 Sequence는 목적지 선정, 이동, 주변 확인을 차례로 실행한다.
2. 주변 확인은 조사를 마치면 Success를 반환하고, 관찰 결과인 '적 발견' 또는 '이상 없음'을 Result에 담는다. 순찰의 세 단계가 모두 성공하면 Sequence는 ChildCompleted와 마지막 관찰 결과를 상위로 전달한다.
3. 상위 결정표는 같은 ChildCompleted를 받아도 '적 발견'이면 '추적'으로 전환하고, '이상 없음'이면 다음 갱신에 다시 '순찰'을 실행하도록 정할 수 있다.

이렇게 구성하면 상위에서는 '순찰 → 추적'이라는 상태 전이를 읽을 수 있고, 순찰 내부의 단계를 바꾸더라도 상위가 받는 결과의 의미가 같으면 결정표를 그대로 쓸 수 있다.

## 트리의 구성과 소유

| 구성 요소 | 보유 정보와 책임 |
| --- | --- |
| Node | ID, 자식 목록, Work, 선택적 Transitioner를 소유한다. IsActive와 LastResult로 현재 수명과 최근 결과를 드러낸다. |
| Work | 진입 조건과 시작·갱신·정지 동작을 정의한다. 기본 Work는 입력을 그대로 반환하며 Running을 유지하므로 자식 조정만 담당하는 노드에도 쓸 수 있다. |
| Transitioner | 부모의 자식 목록을 받아 어떤 자식을 갱신할지, 그 결과로 부모를 계속 실행할지 결정한다. |
| FrameContext | 외부 갱신 한 번의 입력·출력과 방문한 노드별 기록을 담는다. 트리 전체가 하나의 갱신 예산을 공유한다. |

Node를 생성할 때 자식 목록이 확정된다. 자식이 있는 노드에는 전이기가 필요하다. 형제끼리는 대소문자를 구분해 고유한 ID를 사용하며, 다른 가지에서는 같은 ID를 쓸 수 있다. 자식·Work·Transitioner 인스턴스는 트리 안팎에서 소유자가 하나여야 한다. 결정표인 DecisionMatrix는 완성한 뒤 여러 전이기가 공유할 수 있다.

루트의 Initialize를 한 번 호출하면 트리 구조를 검사하고 각 Work와 Transitioner에 같은 Owner와 Blackboard를 전달한다. 중복 ID, 순환, 실행 객체 공유는 초기화 오류이다. 구조 검사나 초기화가 실패하면 새 객체로 트리를 구성한다.

공개 구현과 IFrameContext는 `BlackThunder.UniEngine.StateMachines.Usm`에 있고, INode·IWork·ITransitioner와 FrameContext는 하위 `Core` 네임스페이스에 있다. 상위 StateMachineNames.GetName은 문자열은 그대로, Type은 Name으로, 그 밖의 객체는 ToString 결과로 이름을 구한다. null이나 공백뿐인 이름은 거부한다.

## 한 번의 갱신

1. 호스트가 입력을 담은 새 FrameContext로 루트의 Update를 호출한다. 루트 진입에 조건을 둘 때는 호출자가 먼저 CheckCondition을 확인한다.
2. 노드는 자신의 Work를 갱신한다. Work가 Running이면 전이기가 그 출력을 받아 자식을 진행한다. Work가 종료 상태를 반환하면 그 결과로 노드가 끝난다.
3. 자식과 전이기의 결과가 부모로 돌아온다. 호스트는 루트의 OperationInfo로 계속 진행할지 판단하고, 어느 자식이 그 결과를 냈는지는 FrameContext에서 확인한다.

Running인 루트는 다음 외부 갱신에서 수명을 이어 간다. 종료된 루트에 다시 Update를 호출하면 새 실행을 시작한다. 호출 시점은 호스트가 정하며 EventStream 구독이나 Bootstrapper 초기화는 필요하지 않다. 데이터 전달, 정지와 예외 처리의 상세 동작은 [USM 실행](Execution.md)에 있다.

## 전이기 선택

| 결정 기준 | 전이기 | 대표 동작 |
| --- | --- | --- |
| 현재 자식의 상태·출력과 결정표 | MatrixTransitioner | 순찰 결과가 '적 발견'이면 추적으로 전환한다. |
| 호스트나 콜백의 명시적 요청 | DirectTransitioner | 입력 장치가 요청한 모드로 전환한다. |
| 조건을 만족하는 자식의 우선순위 | Selector | 회피와 순찰 중 실행할 행동을 고른다. |
| 정해진 작업 순서 | Sequence | 목적지 선정이 성공하면 이동을 진행한다. |
| 여러 자식의 완료 여부 | Parallel | 여러 작업을 매 갱신에 진행하고, 전부 또는 하나가 성공할 때까지 기다린다. |

전이·선점·반복 규칙은 [USM 전이 정책](Transitions.md), 실제 조립과 결과 조회는 [USM 사용 예제](Usage.md)에서 다룬다.

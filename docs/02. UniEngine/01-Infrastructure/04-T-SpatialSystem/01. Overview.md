# Spatial System Overview

Spatial System은 이미 검증된 외부 엔진을 UniEngine에 맞게 감싸, 공간 시스템의 기능을 일관된 방법으로 제공하는 공통 래퍼이다.

## 목차

- 소개
- 제공하는 기능
- 구성과 책임
- 독립 월드와 대표 흐름
- 엔진 간 차이의 처리
- 수명과 확장
- 현재 범위
- 상세 문서

## 소개

감지 영역, 이동 경로 검사, 객체 간 접촉 같은 기능에는 공간 탐색과 충돌 판정을 수행하는 엔진이 필요하다. 이를 특정 엔진의 객체와 콜백에 직접 연결하면 월드 구성과 알림 중계를 그 엔진에 맞추어 작성해야 하고, 엔진을 바꿀 때 소비자의 처리 방식도 함께 바뀐다. Spatial System은 이 연결을 대신 맡아 공간 시스템의 기능을 바로 사용할 수 있는 형태로 제공한다.

| 항목 | 설명 |
| --- | --- |
| 개요 | 외부 엔진의 독립된 월드·충돌 형상·공간 질의·접촉 및 Trigger 알림을 2D·3D 공통 API로 제공하는 래퍼 시스템이다. |
| 목적 | 이미 검증된 외부 엔진을 UniEngine에 맞는 일관된 방법으로 사용하여, 소비자가 엔진별 타입과 구성 방법을 다루지 않게 하는 것이다. |
| 구현 | 실제 계산은 외부 엔진에 위임하고, 공통 공간·핸들과 엔진별 연결이 기능 호출·값 변환·객체 대응·알림·수명을 맡는다. |

물리 엔진을 직접 구현하고 검증하는 데에는 큰 부담이 따른다. Spatial System은 이를 새로 만드는 대신, 이미 검증된 외부 엔진을 UniEngine에 맞게 일관되게 사용하는 것을 목적으로 한다. 공간 탐색과 충돌 판정은 외부 엔진에 맡기고, 래퍼는 엔진마다 다른 객체·값·알림·수명의 사용 방법을 UniEngine의 방식으로 맞춘다.

## 제공하는 기능

공간 시스템의 기능은 충돌을 다루는 Collision System과 물리 운동을 다루는 Physical System으로 나눈다. 현재는 Collision System을 제공하며, Physical System은 그 위에 추가할 후속 범위이다.

Collision System의 기능은 월드에서 시작한다. 소비자는 월드 안에 형상을 만들고, 그 형상을 대상으로 질의하거나 알림을 받는다.

| 구분 | 기능 | 제공 내용 |
| --- | --- | --- |
| Collision System | 월드 | 독립된 월드를 만들고 해제하며, 호출자가 전달한 시간만큼 진행한다. |
| Collision System | 충돌 형상 | 상자, 원(2D)·구(3D), 캡슐을 만들고 자세·크기·활성 상태·Trigger·레이어를 읽고 바꾼다. |
| Collision System | 레이어 정책 | 월드마다 레이어 사이의 충돌 허용 여부를 정한다. |
| Collision System | 공간 질의 | Raycast로 경로에 닿는 형상을, Overlap으로 영역과 겹치는 형상을 찾는다. 대상은 레이어와 Trigger 포함 여부로 제한할 수 있다. |
| Collision System | 접촉·Trigger 알림 | 형상 사이의 접촉과 Trigger 겹침의 시작·종료를 알린다. |
| Physical System | 물리 운동 | 중력·질량·속도·힘·토크와 공개 강체이다. 후속 범위이며 아직 제공하지 않는다. |

2D와 3D는 같은 구성의 기능을 서로 다른 타입으로 제공하여, 차원이 다른 객체와 값을 섞지 않는다.

## 구성과 책임

소비자는 공간과 그 공간에 속한 Collider를 사용한다. 공간은 객체의 소속과 질의·알림을 묶고, Collider는 하나의 충돌 형상을 나타낸다. 엔진별 연결은 이 공통 객체를 외부 엔진의 월드와 객체에 연결한다.

~~~text
소비자
  ↕  공통 API 호출, 질의 결과와 알림
공통 공간·핸들    CollisionSpace, Collider
  ↕  C# 대리자
엔진별 연결       Unity, Rapier(후속)
  ↕  엔진 호출, 엔진의 결과와 알림
외부 엔진
~~~

| 구성 | 역할 |
| --- | --- |
| CollisionSpace | 독립 충돌 월드를 소유하고 형상 생성, 시간 진행, 레이어 정책, 질의와 알림을 제공한다. |
| Collider | 월드 안의 충돌 형상을 나타내며 자세·형상·활성 상태의 조작과 접촉·Trigger 알림을 제공한다. |
| 엔진별 연결 | 외부 월드와 객체를 구성하고, 공통 API의 호출과 엔진의 결과·알림을 서로 연결한다. |
| 외부 엔진 | 공간 탐색, 형상 간 접촉·겹침 판정과 필요한 시뮬레이션을 수행한다. |
| 애플리케이션 조립부 | 사용할 엔진을 선택하고 공간을 생성하여 소비자에게 전달한다. |

공통 핸들은 생성 시 연결한 C# 대리자를 통해 외부 상태와 기능에 접근한다. 소비자가 이러한 대리자를 구성하거나 엔진 콜백을 직접 중계할 필요는 없다. 질의 결과와 알림은 같은 월드의 동일한 객체를 같은 핸들로 가리킨다.

공통 값에는 System.Numerics와 기존 Transform 타입을 사용한다. 자세는 월드 좌표, 형상의 크기와 중심은 로컬 형상 기준이다. 공간은 화면에 표시하는 객체를 소유하지 않으며, 화면 객체와 충돌 객체의 자세를 연결하는 일은 애플리케이션이 맡는다.

## 독립 월드와 대표 흐름

공간 인스턴스마다 별도의 월드를 사용한다. 서로 다른 월드의 객체는 좌표가 같아도 충돌하지 않으며, 한 월드의 시간 진행과 공통 레이어 정책이 다른 월드를 바꾸지 않는다. 외부 엔진의 전역 설정까지 모두 월드별로 바꿀 수 있다는 의미는 아니며, 공통으로 보장하는 범위와 엔진 고유 제한을 구분한다.

호출자는 Update에 델타타임을 전달하여 해당 월드를 명시적으로 진행한다. 질의는 엔진이 반영한 상태를 조회하며, 질의를 호출했다는 이유로 시간이 흐르거나 접촉 관계가 갱신되지는 않는다.

1. 조립부가 엔진별 공간을 생성하고 소비자에게 공통 CollisionSpace를 전달한다.
2. 소비자가 공간 안에 형상을 만들고 자세·활성 상태·Trigger·레이어를 설정한다.
3. 호출자가 Update로 월드를 진행하고, 외부 엔진이 충돌 상태를 계산한다.
4. 시스템이 엔진의 결과를 공통 핸들의 관계에 반영하여 시작·종료 알림을 전달한다.
5. 소비자가 Raycast·Overlap 결과나 알림의 공통 핸들을 사용하여 자신의 동작을 결정한다.
6. 월드가 필요 없어지면 Dispose하여 소속 객체와 연결을 함께 정리한다.

공간의 알림 연결은 엔진별 연결이 자동으로 구성한다. 소비자가 에디터에서 중계 컴포넌트를 붙이거나 외부 콜백을 공통 공간에 수동으로 전달하는 절차를 요구하지 않는다.

## 엔진 간 차이의 처리

외부 함수를 같은 이름으로 노출하는 것만으로는 엔진을 바꿀 때 소비자의 처리가 달라질 수 있다. 래퍼는 소비자의 처리에 영향을 주는 부분을 같은 의미로 맞추고, 계산의 특성은 외부 엔진을 따른다.

| 구분 | 대상 |
| --- | --- |
| 래퍼가 맞추는 부분 | 값의 기준과 단위, 핸들의 동일성, 알림의 시작과 종료, 핸들의 유효 상태와 해제 알림 |
| 외부 엔진을 따르는 부분 | 충돌 판정의 허용 오차, 지원 형상의 제약, 자세 변경이 질의에 반영되는 시점, 접촉의 순서와 빈도, 외부 자원이 파괴되는 시점 |

예를 들어 감지 영역 안의 객체가 비활성화되고 그 상태가 Update에 반영되면, 소비자는 사용 중인 엔진과 관계없이 종료 알림을 받아 감지 대상에서 제외할 수 있어야 한다. 공통 종료 처리는 소스에 반영했으며 Unity 실행 검증은 남아 있다. 설정 변경·알림·수명의 공통 기준은 [Rules](02.%20Rules.md)에서, 엔진별 제한은 [Engine Binding](04.%20Engine%20Binding.md)에서 설명한다.

## 수명과 확장

월드는 소속 핸들과 엔진 연결의 수명 단위이다. 보통 월드가 끝날 때 하위 객체를 함께 해제하며, 필요한 경우 개별 Collider를 먼저 해제할 수 있다. Disposed는 해제를 알리는 공통 이벤트이다. 해제된 핸들을 새 객체처럼 재사용하거나 늦은 엔진 알림으로 다시 활성화하지 않는다.

엔진 고유의 복잡한 형상이나 설정은 엔진별 래퍼의 확장 기능으로 제공한다. Collider의 Source는 명시적으로 제공한 형상 데이터 편집 범위에서 사용하며, 일반 소비자가 공통 기능을 사용하기 위한 전제 조건이 아니다. 외부 객체의 수동 등록과 월드의 직접 조작은 허용하지 않고, 월드 구성과 진행은 시스템이 제공하는 API와 어댑터가 맡는다.

Physical System의 PhysicalSpace는 충돌 기능 위에 물리 운동을 추가하기 위한 후속 범위이다. 이후 물리 운동을 추가하더라도 충돌만 필요한 소비자의 사용 흐름을 유지한다.

## 현재 범위

| 대상 | 상태 |
| --- | --- |
| CollisionSpace 2D·3D와 기본 Collider | 공통 소스가 있으며 남은 이슈를 검토 중이다. |
| Unity 연결 | 독립 월드와 자동 알림 연결 소스가 있으며 엔진 실행 검증이 남아 있다. |
| 비활성화 시 공통 종료 보장 | 공통 소스에 구현하고 .NET 테스트를 통과하였다. Unity 실행 검증이 남아 있다. |
| Rapier 연결 | 후속 구현이다. |
| PhysicalSpace·공개 강체 | 미구현이다. |

이 문서는 시스템이 제공하는 기능과 전체 구조를 소개한다. 검증이 필요한 동작은 상세 문서의 기준에 따라 확인하며, 테스트 절차와 실행 결과는 각각 [테스트 계획](../../../../tests/01-Infrastructure/04-T-SpatialSystem/docs/02.%20Plans.md)과 [테스트 결과](../../../../tests/01-Infrastructure/04-T-SpatialSystem/docs/03.%20Results.md)에 둔다.

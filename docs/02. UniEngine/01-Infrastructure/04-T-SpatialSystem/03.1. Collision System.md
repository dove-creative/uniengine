# Collision System

Collision System은 외부 엔진의 충돌 객체와 공간 질의·접촉 알림을 공통 핸들로 제공한다.

- 공간 질의

- 대표 흐름
- 설계 기준
- 공개 API와 값 계약

## 소개

| 항목 | 설명 |
| --- | --- |
| 개요 | 외부 Collider를 조회·조작하고 외부 공간의 질의 결과와 충돌 알림을 전달한다. |
| 목적 | 물리 운동 기능을 요구하지 않는 소비자도 충돌 기능을 독립적으로 사용하게 한다. |
| 구현 | CollisionSpace가 외부 월드 연결과 핸들 대응을 관리하고, Collider 계열은 주입받은 대리자로 외부 객체에 접근한다. |

Collision은 시스템의 기능과 발생한 충돌을, Collider는 충돌 형상을 가진 객체의 핸들을 가리킨다. 인터페이스 이름은 ICollisionComponent로 유지하고 구체 핸들에는 Collider를 사용한다.

## 구성과 역할

| 대상 | 책임 | 보유 정보와 연결 | 대표 서비스와 제공 이유 |
| --- | --- | --- | --- |
| ICollisionComponent | 충돌 계열 핸들의 공통 계약 | 공간 소속과 외부 대상의 유효성을 확인할 연결 | 충돌 시스템의 참여 핸들을 공통으로 다루게 한다. |
| Collider2D·Collider3D | 차원별 Collider의 공통 기능 | 외부 자세·설정에 접근하는 대리자, 공간 연결, 닿은 상대와의 관계 | 자세와 충돌 설정을 읽고 바꾸며 알림의 대상을 나타낸다. |
| BoxCollider2D | 2D 상자 형상의 핸들 | Collider2D의 연결, 상자 크기 접근 대리자 | 공통 크기 표현으로 외부 상자를 읽고 바꾼다. |
| SphereCollider3D | 3D 구 형상의 핸들 | Collider3D의 연결, 반지름 접근 대리자 | 반지름으로 외부 구 형상을 읽고 바꾼다. |
| CollisionSpace2D·CollisionSpace3D | 외부 충돌 공간의 공개 핸들 | 외부 월드 연결, 질의 대리자, 외부 객체와 핸들의 대응, 알림 연결 | Raycast·Overlap 등의 질의와 접촉·겹침 알림을 제공한다. |

Collider2D·Collider3D는 ICollisionComponent를 구현하고 형상별 핸들은 해당 차원의 Collider를 상속한다. 인터페이스는 모든 형상의 속성을 한곳에 모으지 않는다. BoxCollider2D와 SphereCollider3D는 확장 구조를 설명하는 대표 형상이다.

Collider는 공개 강체 없이 사용한다. 공통 생성 API에는 강체 연결 인자가 없다. 물리 운동과 공개 강체 기능은 [Physical System](03.2.%20Physical%20System.md)의 후속 범위이다.

공통 생성 API가 해당 월드 안에 새 외부 Collider를 만들고 핸들을 반환한다. 개발자가 직접 만든 native 객체를 월드에 넣거나 Wrap으로 등록하는 흐름은 지원하지 않는다. 엔진 객체의 등록과 공통 핸들 대응은 시스템이 생성한 객체를 대상으로 어댑터 내부에서 수행한다. [Rules](02.%20Rules.md)의 월드 조작의 경계 절을 따르며, 공개 Wrap·월드 원본 접근 경로는 제거하였다.

## 월드 생성과 진행

| API | 계약 |
| --- | --- |
| `Update(float deltaTime)` | 양의 유한 초를 받아 해당 월드를 한 단계 진행한다. 0·음수·NaN·무한대를 거부한다. 같은 월드의 중첩 Update는 금지한다. |
| `GetLayerCollision(first, second)` | 0~31 레이어 두 개의 충돌 허용 여부를 읽는다. |
| `SetLayerCollision(first, second, enabled)` | 대칭적인 월드별 레이어 충돌 정책을 바꾼다. 기본은 모든 레이어 쌍 허용이다. |
| `CreateBoxCollider(size, pose = null)` | 로컬 전체 크기의 상자를 생성한다. |
| `CreateCircleCollider(radius, pose = null)` / `CreateSphereCollider(...)` | 2D 원·3D 구를 생성한다. |
| 2D `CreateCapsuleCollider(size, direction = Vertical, pose = null)` | 로컬 전체 크기와 방향의 캡슐을 생성한다. |
| 3D `CreateCapsuleCollider(radius, height, direction = Y, pose = null)` | 반지름·전체 높이·로컬 장축으로 생성한다. |

pose는 월드 자세이며 생략하면 원점·기본 회전이다. 생성한 Collider의 자세를 직접 설정하며, 강체 연결이나 강체의 로컬 원점으로 해석하지 않는다.

CollisionSpace도 명시적으로 Update한다. Unity의 기본 형상은 내부 고정 강체로 native 접촉·Trigger 발생 조건을 충족하며, 이 내부 객체는 공통 API에 노출하지 않는다.

레이어 충돌 정책은 접촉·물리 반응에 적용한다. 질의의 `SpatialQueryFilter`는 별도이며, 충돌 금지 레이어도 질의 필터에 포함하면 검색할 수 있다.

## 공간 질의

| 질의 | 입력의 의미 | 결과의 의미 |
| --- | --- | --- |
| Raycast | 해당 차원의 시작점·방향·검색 범위 | 외부 엔진이 판정한 Collider와 교차 정보 |
| Overlap | 해당 차원의 검사 영역·자세 | 외부 엔진이 실제로 겹친다고 판정한 Collider |

질의 결과의 외부 객체는 같은 공간의 공통 핸들로 대응시킨다. 반환된 핸들에서 외부 포인터나 엔진 타입을 알아야 공통 기능을 사용할 수 있는 구조를 만들지 않는다. 대응할 수 없는 외부 객체를 정상적인 빈 결과로 숨기지 않으며, 엔진별 연결이 처리할 대상 범위와 실패를 드러낸다.

질의는 외부 엔진이 조회에 반영한 상태를 읽는다. 외부 자세 변경이 질의에 반영되는 시점은 해당 엔진의 동기화 규칙을 따르며, 연결 구현은 이 규칙을 설명해야 한다. 모든 엔진에서 변경 직후 같은 상태가 보인다고 보장하지 않는다.

질의가 물리 시간을 진행하거나 전체 접촉 상태를 갱신하지 않는다. 공간 탐색과 충돌 계산은 외부 엔진에 위임하며, 래퍼가 별도의 공간 인덱스나 전체 객체 쌍 검사를 구현하지 않는다.

## 접촉과 겹침 알림

접촉은 외부 엔진이 접촉으로 보고한 관계이며, 겹침 알림은 센서·트리거 등 물리 반응과 분리된 관계를 다룬다. 공통 알림은 관련 Collider와 관계의 시작·종료를 전달한다. [Rules](02.%20Rules.md)에 따라 Update에 반영한 비활성화도 기존 관계의 종료로 다룬다. 설정 적용 시점, Trigger 전환과 수명 종료의 공통 규칙은 Rules에서 정의한다. 해당 규칙은 소스에 반영하였으며 실행 검증은 별도이다.

| 연결 단계 | 책임 |
| --- | --- |
| 외부 엔진 | 접촉·겹침을 계산하고 알림을 발생시킨다. |
| 엔진별 연결 | 외부 알림과 상태 변경을 공통 계약에 연결하고 대상 식별과 값을 변환한다. |
| 공통 공간·핸들 | 접촉 관계를 관리하고 연결된 소비자에게 공통 계약의 알림을 전달한다. |

Unity 연결은 native 시뮬레이션 중 알림을 순서대로 모으고, 해당 단계가 반환한 뒤 Update가 끝나기 전에 전달한다. 이때 객체 생성·해제는 가능하지만 같은 월드의 Update 재진입은 거부한다. 서로 다른 엔진의 접촉 순서나 빈도까지 같게 보장하지 않는다.

관계는 시작을 전달하고 종료를 아직 전달하지 않은 상대이며, 각 Collider가 자신의 관계를 직접 가진다. 시작할 때 양쪽에 적고 종료·해제할 때 양쪽에서 지우므로 끝난 관계의 기록은 남지 않는다. 비활성화와 해제는 해당 Collider의 관계만 확인하며 월드 전체의 쌍을 훑지 않는다.

질의 결과와 알림은 같은 공간의 동일한 외부 객체를 일관된 핸들로 가리킨다. 질의를 반복한 결과로 접촉 이벤트를 만들어내거나, 질의 한 번으로 외부 엔진의 전체 접촉 이력이 갱신되었다고 취급하지 않는다.

## 대표 흐름

1. 조립부가 엔진별 공간을 생성하고 소비자에게 공통 공간을 전달한다.
2. 공통 생성 API로 형상을 만들고 자세·형상·Trigger·레이어를 설정한다.
3. 호출자가 Update로 native 월드를 진행한다.
4. 연결 코드가 접촉·Trigger를 같은 핸들 식별로 전달한다.
5. 질의는 시간을 진행하지 않고 외부 엔진의 현재 결과를 읽는다.
6. 개별 Collider Dispose는 해당 객체를 해제하고, 월드 Dispose는 소속 전체를 해제한다.

## 설계 기준

- 2D·3D의 값과 객체를 혼용하지 않으며 다른 외부 월드의 핸들을 같은 공간의 대상으로 취급하지 않는다.
- CollisionSpace는 외부 엔진의 충돌 기능을 사용하며 물리 운동 기능에 의존하지 않는다.
- 후속 물리 기능을 추가할 때에도 충돌 질의·알림·수명 계약을 유지하는 방향으로 검토한다.
- 원본이 사라진 핸들은 정상 질의 대상이나 정상 알림 대상으로 사용하지 않는다. 외부 객체 소멸과 래퍼 해제의 구분은 Engine Binding을 따른다.
- 엔진이 제공하지 않는 고유 질의나 알림은 공통 계약에 빈 동작으로 추가하지 않는다.

## 공개 API와 값 계약

`ICollisionComponent`는 `Space`, `IsValid`, `IsDisposed`, `Dispose()`, `Disposed`를 제공한다. `Collider2D/3D`는 `SpatialHandle`을 상속하고 `Disposed` 이벤트와 다음 기능을 제공한다.

| API | 계약 |
| --- | --- |
| `Space` | 생성 시 연결한 차원의 CollisionSpace이다. |
| `Pose` | `Transform2D/3D`의 월드 자세이다. |
| `Enabled`, `IsTrigger`, `Layer` | Collider 자체 사용 여부, Trigger 설정, 0~31 레이어이다. Enabled·IsTrigger는 마지막 예약값을 읽고 다음 Update에 적용한다. GameObject 활성 여부와 Enabled는 별개이다. |
| `CollisionEnter/Exit`, `TriggerEnter/Exit` | 공간과 Collider가 제공하는 `Action<CollisionPair2D/3D>`이다. `First`, `Second`, `Other(collider)`로 양쪽 핸들을 확인한다. |

형상 값은 **로컬 형상 기준**이다. 크기·반지름은 0 이상의 유한 값, 중심·오프셋은 유한 벡터이다. 엔진의 추가 제약과 보정은 해당 엔진을 따른다.

| 2D 형상 | 추가 속성 | 3D 형상 | 추가 속성 |
| --- | --- | --- | --- |
| `BoxCollider2D` | `Size`, `Offset` | `BoxCollider3D` | `Size`, `Center` |
| `CircleCollider2D` | `Radius`, `Offset` | `SphereCollider3D` | `Radius`, `Center` |
| `CapsuleCollider2D` | `Size`, `Offset`, `Direction` | `CapsuleCollider3D` | `Radius`, `Height`, `Center`, `Direction` |

2D 방향은 `CapsuleDirection2D.Horizontal/Vertical`, 3D 방향은 `CapsuleDirection3D.X/Y/Z`이다. Box Size와 Capsule Height는 전체 길이이다.

| 공간 API | 입력과 결과 |
| --- | --- |
| `Raycast(origin, direction, out hit, maxDistance, filter)` | 최근접 결과가 있으면 true. 기본 최대 거리는 양의 무한대이다. |
| `RaycastAll(origin, direction, maxDistance, filter)` | 거리 오름차순 `IReadOnlyList<SpatialRaycastHit2D/3D>`. 결과는 `Collider`, `Point`, `Normal`, `Distance`를 가진다. |
| `OverlapBox(pose, size, filter)` | 월드 자세와 전체 크기로 질의한다. |
| `OverlapCircle(center, radius, filter)` / `OverlapSphere(center, radius, filter)` | 각각 2D·3D 구형 영역이다. |
| 2D `OverlapCapsule(pose, size, direction, filter)` | 월드 자세, 전체 크기, 로컬 장축 방향이다. |
| 3D `OverlapCapsule(firstCenter, secondCenter, radius, filter)` | 양 끝 반구의 월드 중심이다. 전체 높이의 끝점이 아니다. |

결과는 읽기 전용 스냅샷이며 Overlap은 중복 Collider를 제거한다. 필터 생략 시 `SpatialQueryFilter.Default`의 전체 레이어(-1)·Trigger 포함(true)을 사용한다. `new SpatialQueryFilter(mask, includeTriggers)`로 명시한다. `default(SpatialQueryFilter)`는 0 레이어·Trigger 제외이므로 기본 정책과 다르다. Ray 방향은 유한한 0 아닌 벡터를 받아 정규화한다. 거리에는 양의 무한대만 추가 허용하며 음수·NaN을 거부한다.

쌍의 역순·중복 시작과 중복 종료는 한 전이로 처리한다. 접촉과 Trigger 상태는 별도이다. 같은 프레임의 종료 후 재진입은 유지한다. 연결 이전의 접촉이나 Stay를 합성하지 않는다. 비활성화 시 종료 보장과 지연 알림의 구분은 [Rules](02.%20Rules.md)를 따른다. Dispose·외부 소멸에서는 Disposed로 수명 종료를 통지하며 Exit를 보장하지 않는다.

알림은 공간, 쌍의 First, Second 순으로 동기 전달하며 First/Second의 물리적 방향은 정의하지 않는다. 각 콜백 전에 양쪽 핸들과 공간의 유효성을 확인한다. 중간 해제 이후 전달은 중단한다. 시스템 측 오류는 ExceptionHandler에 보고한 뒤 실패한 핸들을 제외한다. 어댑터의 잘못된 알림은 그 알림만 버리고, 월드 진행 중 식별되지 않은 예외는 그 Update만 끝내며 월드를 유지한다. 처리기가 정상 반환하면 유효한 나머지 객체의 작업을 계속하며, 처리기가 없거나 다시 예외를 던지면 정리를 보장한 뒤 현재 호출을 중단한다. 공간에 등록한 콜백의 예외는 그 구독을 해제하고, Collider에 등록한 콜백의 예외는 그 알림의 양쪽 Collider를 제외한다. 세부 기준은 [Rules](02.%20Rules.md)의 오류 처리와 유효성 조회 절을 따른다. 해제 중 구조 정리는 모두 시도하지만 미처리 예외 이후의 나머지 알림은 전달하지 않는다.

공통 생성자는 `ColliderBindings2D/3D`, 공간 생성자는 `CollisionSpaceBindings2D/3D`를 받는다. 공간 바인딩은 생성·Update·레이어 정책을 묶은 필수 `CollisionWorldBindings2D/3D`를 포함한다. 생성 대리자가 해당 공간의 유효한 핸들을 반환하지 않으면 그 핸들을 해제하고 InvalidOperationException으로 거부한다. 속성은 `SpatialProperty<T>(read, write)`로 묶는다. 공간의 Subscribe 대리자는 수신자를 연결하고 해제용 Action을 반환한다. 대리자 구성은 엔진 연결 코드의 책임이며 일반 소비자에게 수동 알림 전달을 요구하지 않는다.

ColliderBindings의 선택적 `IsActive`는 GameObject 활성 등 Enabled 외의 실제 참여 조건을 확인하고, `Prepare`는 갱신 시 객체별 연결 점검을 수행한다. 실패한 속성 쓰기는 핸들을 제외하며 처리기가 정상 반환하면 호출을 마친다. 읽기 실패는 처리기가 정상 반환해도 값을 만들어내지 않고 ObjectDisposedException으로 해제된 상태를 알린다. IsValid 실패는 같은 정리 후 false를 반환한다.

연결용 `CollisionNotification2D/3D(pair, isTrigger, isEntering, relationshipId)`는 양의 관계 식별자를 요구한다. 새 관계에는 새 식별자를 사용하고 중복 알림과 종료에는 시작의 식별자를 재사용한다. 이미 종료한 관계의 시작을 다시 보내지 않는다. 공통 계층은 끝난 관계를 기억하지 않으므로 이 조건은 어댑터가 지킨다. 공통 소비자가 받는 CollisionPair에는 엔진 타입이나 식별자 관리가 노출되지 않는다.

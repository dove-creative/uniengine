# ExceptionHandler

모듈에서 처리하지 못한 예외를 애플리케이션의 공통 처리기로 전달하는 정적 객체이다.

## 목차

- 역할과 구성
- 동작 흐름
- 설계 기준

## 역할과 구성

- 책임: 예외를 발견하는 모듈과 최종 보고·처리 방식을 분리하여 애플리케이션이 처리 정책을 선택하게 한다.

보유 정보는 다음과 같다.

- 등록된 처리기: `Action<Exception>`이며 null이면 재전파 정책을 사용한다.
- 교체·조회 잠금: 처리기 참조를 일관되게 읽고 바꾸는 데 사용한다.

| 제공 서비스 | 제공 이유 |
| --- | --- |
| SetHandler | 공통 처리기를 교체하거나 해제하여 실행 환경에 맞는 보고 정책을 연결한다. |
| Report | 호출자가 넘긴 예외를 처리기에 전달하고, 처리기가 없으면 원래 스택 정보와 함께 재전파한다. |
| SafeInvoke | Action 계열의 호출 대상을 개별 실행하고 실패를 Report로 전달하여 처리된 실패 뒤의 호출을 이어 갈 수 있게 한다. |

## 동작 흐름

이벤트 소유자가 실패한 수신자를 제거한 뒤 Report를 호출한다. ExceptionHandler는 잠금 안에서 처리기 참조를 얻고 잠금 밖에서 실행한다. 처리기가 정상 반환하면 이벤트 소유자가 다음 수신자로 진행하며, 예외를 던지면 호출 경로로 전파한다.

## 설계 기준

- 처리기 호출 자체를 잠금에 가두지 않으므로 외부 처리기의 동작과 설정 잠금을 분리한다.
- SafeInvoke는 호출만 분리하며 구독을 제거하지 않는다. 실패한 수신자의 제거는 AdaptiveAction·EventStream 등 구독 소유자가 담당한다.

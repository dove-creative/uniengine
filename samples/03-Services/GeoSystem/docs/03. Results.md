# GeoSystem 시각화 예제 검증 결과

## 2026-11-16

[검증 계획](02.%20Plans.md)에 따라 Windows·.NET 10에서 확인했다.

| 검증 | 결과 |
| --- | --- |
| 시각화 예제 Release 빌드 | 통과, 경고 0·오류 0. 최종 산출물은 `bin/Verified`에서 확인. |
| `help` | 사용 방법 출력, 종료 코드 0 |
| `verify` | POCO 시나리오 17개 조건 통과, 종료 코드 0 |
| 알 수 없는 명령 | 사용 방법 안내, 종료 코드 1 |
| 기존 콘솔 예제 Release 빌드 | 통과, 경고 0·오류 0 |
| 기존 `event-stream` 실행 | 예상한 이벤트 순서·분기·병합·병렬 결과 출력, 종료 코드 0 |
| 전체 회귀 테스트 | 1,496개 모두 통과. 실패·오류·건너뜀 0개, 종료 코드 0. 약 12분 6초 소요. |
| 수동 GUI 검증 | 사용자 요청으로 보류. 실제 창 배치와 마우스·키보드 조작은 검증하지 않음. |

창 없는 검증은 화면 렌더링·입력 이벤트 배선의 성공을 보장하지 않는다. Linux·macOS 실행은 확인하지 않았다.

첫 샌드박스 실행은 문서 폴더의 Configuration 디렉터리 생성 권한이 없어 실패했다. 일반 사용자 권한으로 다시 실행한 시나리오 검증은 통과했다.

최종 빌드 시 기존 `bin/Release/net10.0`의 실행 파일이 잠겨 복사가 실패했다. PC 조작 보류 요청에 따라 창이나 프로세스를 조작하지 않고 아래 명령으로 별도 출력 폴더에 빌드했다. 이 최종 DLL에서 `help`·`verify`·알 수 없는 명령의 결과를 다시 확인했다.

```powershell
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release --no-restore -o samples/03-Services/GeoSystem/bin/Verified
dotnet samples/03-Services/GeoSystem/bin/Verified/UniEngine.GeoSystem.Sample.dll verify
```

## Tracer와 Wheel 비교 시나리오 — 2026-11-18

GeoSystem 시각화 프로젝트의 Release 빌드는 경고·오류 0개로 완료했다. `help`는 tracer 명령을 표시하고 종료 코드 0을, 알 수 없는 명령은 종료 코드 1을 반환했다. `verify`는 기존 장면 17개와 새 Tracer 장면 9개 조건을 모두 통과했다. 두 위치 기준, Route 해제 후 상태, 실패 정책, 분기 예약의 소비, 기본 분기 선택과 끝점 잔여 거리를 확인했다.

기존 장면의 최초 실행에서 노드 이동 후 역방향 0% 조회가 정확한 끝점과 일치하지 않았다. 말단 조회가 Route의 반올림된 전체 길이와 실제 자식 구간의 끝점을 각각 보관하도록 수정했다. 전체 길이가 위·아래로 반올림되는 신규 사례를 포함한 GeoSystem 테스트 182개가 모두 통과했다.

사용자 요청에 따라 Tracer 창의 수동 버튼·드래그 조작은 검증하지 않았다.

## 샘플 로컬 패키지 복원 — 2026-11-26

Windows·.NET SDK 10.0.404에서 [로컬 패키지 복원 계획](02.%20Plans.md)에 따라 확인했다.

| 검증 | 결과 |
| --- | --- |
| 보관된 외부 패키지 | 33개, 298,283,792바이트. source-manifest.json의 SHA-256과 모두 일치 |
| 빈 캐시 복원 | HTTP·HTTPS 프록시를 연결 불가능한 127.0.0.1:9로 지정하고 --no-http-cache 및 샘플 NuGet 설정을 사용. 본체·GeoSystem·콘솔 샘플 복원 성공 |
| 복원 원본 | 외부 패키지 33개는 samples/packages, 자사 패키지 1개는 루트 packages. 복원된 .nupkg.metadata에서 확인 |
| Release 빌드 | 본체와 두 샘플 성공, 경고·오류 0개 |
| GeoSystem verify | 기본 장면 17개와 Tracer·Wheel 9개 조건 통과, 종료 코드 0 |
| 콘솔 event-stream | 이벤트·분기·병합·병렬 결과 출력, 종료 코드 0 |
| README 실행 명령 | 같은 프록시 조건에서 RestoreConfigFile을 지정한 두 dotnet run 명령 성공 |
| 일반 캐시 복귀 | 세 프로젝트의 복원 경로가 사용자 기본 NuGet 캐시이며, 샘플 설정과 두 로컬 피드만 참조함을 확인 |
| 전체 회귀 | 장시간 실행 승인 대기. 이번 작업에서는 아직 실행하지 않음 |
| GUI·다른 운영체제 실행 | 이번 패키지 보관 변경에서는 실행하지 않음 |

최초 빈 캐시 검증에서는 샘플 디렉터리의 NuGet.config만으로 참조하는 본체의 설정까지 바뀌지 않아 본체의 NuGet.org 접근이 실패했다. 실행 명령에 RestoreConfigFile을 명시한 뒤 새 빈 캐시에서 본체까지 로컬 피드로 복원되는 것을 확인했다. 일반 캐시 복귀 후 검증용 캐시를 제거했다. 패키지 버전과 시나리오 코드는 이번 작업에서 변경하지 않았다.

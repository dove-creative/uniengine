# Bootstrapper 테스트 계획

## 실행 구성

[BootstrapperTests](../BootstrapperTests.cs)의 NUnit 직접 사례 17개가 [상태·동작 표](01.%20Tables.md)의 B1–B9를 검증한다. [BootstrapperScenarios](../BootstrapperScenarios.cs)를 기존 InfrastructureProcess로 실행하여 각 사례의 Configuration·Bootstrapper·Log·ExceptionHandler·Main 정적 상태를 독립시킨다. 테스트 전용 상태 초기화 API와 private 상태 변경은 추가하지 않는다.

기본값 사례는 테스트 프로세스에서만 진입 어셈블리를 GUID 이름의 런타임 어셈블리로 지정한다. 기본 ID 추론을 그대로 실행하면서 데이터 경로가 테스트 소유 영역을 벗어나지 않게 한다. 진입 어셈블리 부재도 별도 프로세스에서 검증한다. 이 설정 API는 .NET 10 테스트에서만 사용한다.

동시 호출 사례는 신호로 첫 콜백을 유지한 상태에서 두 번째 호출이 즉시 거부되는지 검사한다. 신호 대기의 10초 한도와 프로세스의 30초 한도는 교착 시 실패 종료를 위한 제한이다. 재진입은 콜백에서 예외를 처리하는 경우와 전파하는 경우를 나눈다.

정리 실패는 구독 Handle의 내부 Disposed 이벤트에 실패 콜백을 연결하여 유도한다. Handle이 자신의 정리 예외를 보고하는 기존 계약은 유지하며, Bootstrapper가 애플리케이션 초기화 실패를 보고하지 않고 두 예외를 보존하는지 확인한다.

## 실행과 기록

Configuration의 기존 API와 설치 경로 사례, 새 Bootstrapper 사례, 전체 일반 테스트를 Release로 검증한다. 기존 UniTest 랜덤 연속 검증도 전체 실행에 포함한다. 새 Bootstrapper 사례는 고정 경로 NUnit 검증이며 UniTest 모델을 추가하지 않는다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --logger "trx;LogFileName=all-final.trx" --results-directory tests/obj/Bootstrapper/20261115
```

로그와 TRX는 위 결과 디렉터리에 보관하고 [검증 결과](03.%20Results.md)에 성공·실패·범위를 구분하여 기록한다. 코드 LF, 변경 문서의 링크와 기존 수학 문서·다이어그램 보존을 함께 확인한다.

## 격리와 정리

부모 실행기는 GUID 기반 애플리케이션 경로를 검증하고 정확한 테스트 소유 경로만 정리한다. 설치 경로의 명시값·상대 경로·파일 차단·기존 리소스 보존은 같은 소유 디렉터리 안에서 검증한다. 호스트의 실제 설치 경로는 읽기만 한다.

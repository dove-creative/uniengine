# Bootstrapper 상태와 동작

## 검증 기준

정적 설정과 초기화 상태를 새 프로세스마다 격리하고 공개 API로 검증한다. 프로세스 내부에서 직접 성공·실패 경로를 실행하며 랜덤 경로 선택에 의존하지 않는다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| B1 | 기본값으로 초기화한다. | 설치 경로는 AppContext.BaseDirectory, ID는 진입 어셈블리 이름이며 콘솔 로거와 기본 재전파 정책을 사용한다. |
| B2 | 명시적 경로·로거·정책과 콜백을 전달한다. | 콜백에서 설정·로그·새 Main을 사용할 수 있고 IsInitialized는 false이다. 콜백 반환 후 true이며 기존 Main 구독은 정리된다. |
| B3 | 잘못된 ID·설치 경로, 진입 어셈블리 부재 또는 데이터 경로 생성 실패 후 재호출한다. | 설정과 Main을 확정·변경하지 않고 실패를 직접 전파하며 원인 수정 후 성공한다. |
| B4 | Configuration을 직접 초기화한 뒤 Bootstrapper를 호출한다. | 기존 설정을 인수하지 않고 거부한다. 기존 설정과 Main은 유지한다. |
| B5 | 완료 후 중복 호출하거나 초기화 중 다른 스레드에서 호출한다. | 두 번째 초기화는 거부하고 첫 초기화의 상태·설정·Main을 유지한다. |
| B6 | 콜백에서 재진입을 잡거나 밖으로 전파한다. | 잡으면 외부 초기화는 성공하고, 전파하면 실패 상태가 되며 Main을 정리하고 재시도를 거부한다. |
| B7 | 애플리케이션 콜백 또는 그 콜백이 호출한 로거가 실패한다. | 원래 예외를 전달하고 Bootstrapper는 Report를 호출하지 않는다. 설정과 로그는 남으며 Main은 폐기되고 재시도는 거부된다. |
| B8 | 초기화 실패 후 Main 정리도 실패한다. | 최초 실패, 정리 실패 순서의 AggregateException이다. 정리 대상 Handle 자체의 예외 보고 동작은 유지되며 초기화 실패를 추가 보고하지 않는다. |
| B9 | 동기·병렬·완료·오류 전파 중 초기화를 시도한다. | 설정을 변경하기 전에 거부한다. 전파 종료 후 초기화할 수 있다. |

## 랜덤 연속 테스트

EventHub의 아래 실행은 seed마다 깊이 100/100에 도달했으며 실패·취소가 없었다. 시간은 빌드·복원을 제외한 실제 실행시간이다.

| 검증 대상 | seed 0 (ms) | seed 1 (ms) | seed 2 (ms) | 합계 (ms) |
| --- | ---: | ---: | ---: | ---: |
| 이름별 갱신 등록 | 5.493 | 1.535 | 1.510 | 8.538 |
| 조건·콜백 결합형 등록 | 40.987 | 17.730 | 14.698 | 73.415 |
| When 통합 | 8.127 | 2.322 | 2.241 | 12.690 |

비트 조건 검증의 기존 랜덤 30개와 When 통합의 전체 랜덤 39개도 모두 목표 깊이에 도달했다.

전체 실행에 포함된 Log의 세 seed 합계는 비트 조건 72.340초, Builder 분리 85.162초, 결합형 등록 145.060초, When 통합 55.146초였다. Builder 분리는 중간 확인 후 계속 실행했다. 비트 조건·결합형 등록은 완료 후 합계를 확인하여 실행 중 60초 초과를 확인하지 못했다. When 통합에서는 어느 대상도 60초를 넘지 않았다.

이름별 갱신 등록의 전체 실행에 포함된 랜덤 연속 사례 39개가 모두 통과했다. 대상별 세 seed의 NUnit 실행시간 합계는 모두 60초 이내였으며 가장 긴 Log는 56.875초였다. 전체 테스트는 예상 소요시간을 안내하고 사용자 확인을 받은 뒤 실행했다. EventHub의 위 시간은 각 사례 출력의 측정 구간이다.

## 검증 범위와 한계

- 결과는 각 날짜의 .NET 실행에 한정된다. Unity Mono·IL2CPP의 동작·할당·스택 여유는 검증하지 않았다.
- 성능 비교는 해제 알림 전환 당시의 간단한 측정이다. 이후 Builder·조건·When·키 행 구조 변경의 처리량이나 PathInfo 크기를 나타내지 않는다. CPU 0·1의 물리 코어 토폴로지도 확인하지 않았다.
- 별도 Builder 구현의 NotSupportedException은 코드 검토만 했으며 직접 실행 사례에 포함하지 않았다.
- EventStream의 상세 결과는 [EventStream 검증 결과](../02-E.3-EventStream/docs/03.%20Results.md)에 있다.


## 2026-11-14 루트 경계 계약 검증

Release 전체 1,243개가 통과했으며 EventHub는 166/166, LifecycleHub는 18/18이다. 갱신 중 등록·해제·폐기, 멀티캐스트 완료, 실패 등록의 경계 전 중복 거부와 경계 후 재등록, 조건 공유와 참조 회수, 기존 첫·반복 무할당 사례를 포함한다. EventHub의 고정 seed 0·1·2와 깊이 100의 랜덤 연속 검증도 통과했다.

초기 실패와 검증 범위·한계는 [EventStream 실행 결과](../02-E.3-EventStream/docs/03.%20Results.md)의 같은 날짜 기록을 따른다.

## 2026-11-24 onSleep 계약 검증

Release 전체 1,703개가 실패·건너뜀 없이 통과했으며 EventHub는 172/172, LifecycleHub는 18/18과 UniTest 4/4이다.

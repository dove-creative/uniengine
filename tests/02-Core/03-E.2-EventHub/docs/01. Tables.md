## 연결과 Builder 수명

EventHub는 리스너 연결과 생애주기를 소유하고 갱신 전달은 하나의 EventStream 그래프에 위임한다. LifecycleHub의 검증 기준은 별도의 [상태·동작 표](../../03-E.1-LifecycleHub/docs/01.%20Tables.md)에 둔다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 새 리스너, null, 기존 직접 구독 키를 Connect한다. | 새 연결만 등록하며 null과 중복은 거부한다. ConnectionCount·HasListener는 직접 구독 연결도 포함한다. |
| C2 | 연결된 리스너, 없는 리스너, null을 Disconnect한다. | 해당 리스너의 모든 경로 구독과 생애주기 콜백을 해제하고 없는 연결은 무시한다. |
| C3 | 명시적 해제나 마지막 등록 제거 뒤 같은 키를 다시 연결한다. | 새 Builder만 사용할 수 있고 이전 Builder의 모든 메서드는 InvalidOperationException이다. |
| C4 | 해제된 Builder와 연결 상태였던 Builder를 허브 폐기 후 사용한다. | typed·object·생애주기 인터페이스 모두 ObjectDisposedException이다. 폐기 전 해제된 Builder는 InvalidOperationException이다. null 인자보다 수명 검사를 우선한다. |
| C5 | 생성자 콜백과 직접·Builder 등록이 같은 대리자 키를 사용한다. | 하나의 연결로 계산한다. -=는 해당 이벤트만, Disconnect는 모든 등록을 제거한다. |
| C6 | 아직 등록하지 않은 빈 연결과 마지막 구독이 실패한 연결을 갱신한다. | 빈 Connect 연결은 유지하며 실패로 비워진 연결은 루트 종료 시 실제 구독 해제와 함께 제거한다. null 등록은 새 연결을 만들지 않는다. |

## 갱신 경로와 직접 구독

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| U1 | 루트의 여러 리스너·직접 구독과 조건별 경로에 등록한다. | 일치하는 구독 모두에 전달하며 리스너·직접 구독·조건 경로 간 등록 순서를 보장하지 않는다. 한 리스너의 콜백을 별도로 묶지 않는다. |
| U2 | 두 리스너가 같은 조건 대리자를 OnUpdatedWhere에 등록하고 한 연결씩 해제한다. | 한 갱신에 조건을 한 번만 평가한다. 한 연결의 해제는 다른 연결을 유지하고 마지막 해제 뒤에는 조건을 평가하지 않는다. |
| U3 | 기존 콜백이 있는 typed·object Builder의 OnUpdatedWhere에 null 조건 대리자를 등록한다. | 등록 시 ArgumentNullException이며 기존 연결은 다음 갱신도 계속 받는다. object 조건은 변환 전에 검증하며 null 콜백도 조건 오류를 숨기지 않는다. |
| U5 | typed·object Builder에서 OnUpdated·OnUpdatedWhere·OnUpdatedWhen·생애주기 등록을 호출한다. | 값 사용·인자 없음 콜백 모두 같은 Builder 인스턴스를 반환한다. 앞의 등록 조건은 다음 등록에 영향을 주지 않는다. |
| U6 | 전파 중 Builder·직접 구독을 추가하고, 리스너를 해제하거나 Update에 재진입한다. | 등록·삭제는 내부 루트 종료 때 반영한다. 기존 구독은 현재 값까지 받고 새 구독은 다음 갱신부터 받는다. 재진입 Update는 생략한다. |
| U7 | OnUpdatedWhen으로 값 형식·참조 형식 target에 같은 값·다른 값·null을 발행한다. null 리터럴을 형변환 없이 target으로 넘긴다. | EqualityComparer&lt;T&gt;.Default로 같은 값일 때만 전달한다. null target은 유효하며 OnUpdatedWhere의 null 조건 대리자와 명확히 구분한다. |
| U9 | 같은 target 인스턴스와 별도로 만든 동등한 target을 여러 리스너의 OnUpdatedWhen에 등록한다. | 같은 위치의 같은 target은 하나의 When 행을 공유한다. 값 사용·인자 없는 콜백 모두 갱신마다 비교가 한 번이며, 연결별 해제는 남은 구독을 유지하고 마지막 해제는 경로를 정리한다. 공개 Equals 호출 횟수와 null을 포함한 수신 이력으로 검증한다. |
| U11 | 대리자 형식 페이로드에서 OnUpdatedWhen과 OnUpdatedWhere를 함께 사용한다. | When은 대리자 값의 동등성을 비교하고 Where는 페이로드를 입력으로 받는 조건 함수를 실행한다. 서로 다른 등록의 수신 결과를 확인한다. |
| D1 | 같은 직접 Updated 콜백을 중복 등록하고 해제한다. | 중복은 InvalidOperationException이며 기존 등록은 유지한다. 전파 중 -=는 루트 종료 때 실제 구독과 빈 연결을 제거하며 전파 밖에서는 즉시 제거한다. |
| D2 | typed·object Updated에 멀티캐스트를 등록하고 내부 항목 또는 전체 묶음을 해제한다. | 전달한 묶음 하나가 등록 하나이다. 전체 묶음으로만 해제하며 부분 해제는 무시한다. |
| D3 | 갱신 중 앞 구독이 실패한 뒤 -=를 수행하거나 현재 멀티캐스트를 해제한다. | 실패한 등록은 현재 멀티캐스트의 뒤 항목을 생략한다. 명시적 해제 요청은 현재 루트 단위의 나머지 구독·항목을 마친 뒤 반영한다. |
| D4 | 같은 원본 대리자를 typed/object Updated에 등록한다. | 같은 연결 안의 별도 등록이며 각각 중복을 거부하고 별도로 해제한다. |
| D5 | 같은 콜백을 같은 target·동등한 조건 대리자로 다시 등록한다. | 같은 연결·콜백 형식·원본 콜백·조건의 중복은 InvalidOperationException이다. 조건 종류와 값을 비교하며 When은 target 동등성, Where는 원본 대리자 Equals를 사용한다. 조건이나 콜백 형식이 다르면 허용한다. |
| D6 | object 조건·콜백을 변환 어댑터를 통해 다시 등록하거나 직접 Updated를 해제한다. | object 중복은 원본 조건·콜백 대리자로 검사한다. typed/object 콜백 형식은 구분한다. 직접 -=는 루트의 해당 콜백 형식만 제거하고 조건 등록은 유지한다. |

## 비트 조건 경로

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| K1 | ulong Builder의 단일·복합 마스크에 일치·불일치·0 값을 발행한다. 부호 비트와 최상위 비트를 포함한다. | 공통 비트가 하나라도 있을 때 원래 ulong 값을 전달한다. enum의 선언 비트 폭을 보존하며 인자 없는 콜백도 같은 판정을 따른다. |
| K2 | 정상·해제·재연결·폐기 상태의 Builder에서 0·비Flags 마스크를 OnUpdatedForFlags에 넘기거나 null Builder로 호출한다. | 정상 연결의 잘못된 마스크는 null 콜백 여부와 무관하게 ArgumentException이며 기존 구독을 유지한다. 해제된 연결은 InvalidOperationException, 폐기된 허브는 ObjectDisposedException이 우선한다. null Builder는 ArgumentNullException이다. |
| K3 | 서로 다른 enum의 같은 마스크를 여러 리스너에서 등록하고 한 연결씩 해제한다. 다른 마스크와 Where 경로를 섞는다. | 같은 부모·마스크의 경로를 공유하며 다른 연결은 유지한다. 일치하는 Where·Flags의 수신 집합을 검사하고 생성 순서에 의존하지 않는다. |
| K4 | OnUpdatedForFlags·OnUpdatedWhere·루트 구독을 연속 등록한다. | 모든 등록은 같은 Builder를 반환하며 각 등록의 조건을 독립적으로 적용한다. 이전 마스크나 조건이 뒤의 등록으로 누적되지 않는다. |
| K5 | 갱신 중 같은·다른 마스크 경로에 구독을 추가하고 다른 리스너를 해제한다. | 새 구독은 다음 갱신부터 호출하며 해제 요청한 기존 구독은 현재 루트 전파까지 받는다. |
| K6 | 비트 경로의 콜백을 실패시키고 재연결하거나 생애주기 등록으로 연결을 유지한다. 수면과 폐기를 수행한다. | 실패한 구독과 빈 연결은 루트 종료 때 제거한다. 다른 등록·리스너는 유지하며 처리된 실패만 현재 전파를 계속한다. 수면 중 갱신은 생략하고 생애주기 알림은 마스크와 무관하다. |
| K7 | 별도 허브로 예열한 뒤 고정된 비트 경로의 첫·반복 갱신을 측정한다. | typed·인자 없는 콜백의 갱신 구간에 관리 힙 할당이 없다. 등록·object 박싱은 측정에서 제외한다. |
| K8 | 같은 단일 비트를 OnUpdatedForFlags의 마스크와 OnUpdatedWhen의 target으로 등록한 뒤 복합 비트 값을 발행한다. | OnUpdatedForFlags는 공통 비트로 통과하고 target은 전체 값이 다르므로 통과하지 않는다. 값 사용·인자 없음 모두 같다. |
| K9 | 서로 다른 enum의 같은 비트를 OnUpdatedForFlags로 같은 콜백에 등록한다. | 등록 순서와 enum 형식에 관계없이 같은 마스크 비트는 중복이다. 다른 마스크는 허용한다. |

## 실패와 참조 정리

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| F1 | 직접·Builder 멀티캐스트의 항목 하나가 실패한다. | 한 번 보고하고 등록 묶음 전체를 해제한다. 같은 연결의 다른 갱신·생애주기 등록은 유지한다. |
| F2 | 처리기가 없거나 보고기가 예외를 던지는 상태에서 여러 구독이 실패한다. | 새 호출을 중단하고 루트 경계에서 실패 등록·빈 연결·변경 큐를 정리한 뒤 첫 미처리 예외를 전달한다. 미실행 구독은 다음 발행에 남는다. |
| F3 | typed·object 직접 구독이 실패하고 같은 콜백을 -=로 제거한다. | 실패 구독만 해제하며 한 번 보고하거나 순회 후 원래 예외를 전달한다. 이후 -=와 다음 갱신은 안전하다. |
| F4 | 여러 리스너가 공유하는 Where 조건이 실패한다. | 해당 경로를 정리 대상으로 삼고 한 번 보고한다. 생애주기 등록이 있는 연결은 유지하며 빈 연결은 루트 종료 때 제거한다. 같은 Update 안에서는 기존 연결 상태를 유지한다. |
| F5 | 실패하거나 명시적으로 해제된 콜백의 대상 참조를 버린다. | 허브나 해제된 Builder가 살아 있어도 제거된 대리자 키·콜백 대상은 GC로 수거할 수 있다. |
| F6 | 직접·Builder 생애주기 콜백이 실패한다. | 연결 전체를 해제하고 한 번 보고한다. 자신을 해제한 직후 실패해도 원래 예외를 보고한다. |
| F7 | 마지막 갱신 콜백이 실패한 뒤 같은 Update 안에서 다시 등록한다. | 루트 종료 전에는 아직 남은 등록과 중복되어 거부한다. 종료 후 남은 연결은 재등록할 수 있고 비어서 제거된 Builder는 거부한다. 직접 +=는 새 연결을 만들 수 있다. |
| F8 | 생애주기 콜백으로 연결을 유지한 채 갱신 콜백이 실패하고 같은 경로에 같은 콜백을 다시 등록한다. | 루트 종료 전에는 중복으로 거부하며 실패 등록의 실제 해제 후 같은 경로에 재등록할 수 있다. 새 구독은 다음 갱신부터 호출하고 생애주기 알림은 유지한다. |

## 수면과 폐기

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| S1 | Sleep·Sleep(Token)·TrySleep으로 재운 뒤 Token을 폐기한다. | 수면 중 갱신은 보류 없이 생략하고 깨어난 뒤부터 전달한다. onAwake는 깨어난 상태에서 한 번 호출한다. |
| S2 | 이미 수면 중인 허브에 Sleep·TrySleep을 적용한다. | Sleep은 거부하고 TrySleep은 기존 수면을 유지한다. 보조 핸들은 해제할 때 전달받은 onAwake만 실행한다. |
| S3 | null·폐기된 Token으로 재우거나 수면 중 허브를 폐기한다. | 잘못된 Token은 거부하고 활성 상태를 유지하며 onSleep을 호출하지 않는다. 폐기된 허브는 이후 Token이 끝나도 깨우기 콜백을 실행하지 않는다. |
| S4 | onSleep을 지정한 허브를 네 진입점으로 재우고, 수면 중 Sleep·TrySleep을 다시 적용한 뒤 깨워서 다시 재운다. | onSleep은 깨어 있던 허브가 실제로 잠들 때마다 수면 상태에서 한 번 호출한다. 콜백 안의 Update는 생략한다. 거부된 Sleep과 중첩된 TrySleep에서는 호출하지 않는다. |
| S5 | onSleep에서 예외를 발생시키거나 연결한 Token을 폐기한다. | 실패하면 수면을 취소하고 원래 예외를 호출자에게 전달한다. Token은 폐기하지 않고 연결만 해제하므로 이후 폐기해도 onAwake를 실행하지 않으며 다음 수면을 깨우지 않는다. Token을 폐기하면 그 시점에 깨어나 onAwake를 실행한다. |
| S6 | onSleep에서 첫째 Token을 폐기하고 onAwake에서 둘째 Token으로 다시 잠든 뒤, 첫째 또는 둘째 onSleep이 실패한다. | 첫째가 실패하면 원래 예외를 첫째 Sleep의 호출자에게 전달하고 둘째 수면과 onAwake를 유지한다. 둘째가 실패하면 둘째 수면만 취소하고 예외는 첫째 Token의 콜백 실패로 보고한다. 처리기가 없으면 첫째 Sleep의 호출자에게 전파한다. |
| L1 | 조건별 갱신을 등록한 Builder와 직접 이벤트에 생애주기 콜백을 등록하고 폐기한다. | 모든 Disposing → IsDisposed 전환 → 모든 Disposed 순서이다. 같은 연결·단계에서는 오버로드와 관계없이 등록 순서이며 연결 간 순서는 보장하지 않는다. |
| L2 | 갱신 콜백에서 Dispose하거나 멀티캐스트 앞 항목에서 Disconnect한다. | 새 작업은 거부하되 현재 루트의 갱신과 멀티캐스트를 마친다. 루트 종료 후 폐기 알림과 정리를 수행한다. |
| L3 | Disposing 중 현재·이후 등록이나 연결을 제거한다. | 제거된 등록의 남은 호출은 생략하며 다른 등록은 유지한다. 반복 Dispose는 무시하고 최종 참조·연결을 정리한다. |
| L5 | 같은 생애주기 이벤트의 동일한 원본 대리자를 중복 등록한다. | 경로와 관계없이 InvalidOperationException이다. -=는 해당 단계의 일치하는 등록만 제거한다. |
| L6 | 직접 생애주기 멀티캐스트의 내부 콜백 또는 전체 묶음을 해제한다. | 내부 콜백만 지정하면 등록은 유지하고, 전체 묶음을 지정하면 해당 등록만 제거한다. |
| L7 | 직접 생애주기 멀티캐스트의 첫 콜백이 실패한다. | 해당 연결의 나머지 등록은 생략한다. 보고가 정상 반환하면 다른 연결을 계속하며, 보고가 예외를 전파해도 최종 참조 정리는 수행한다. |
| L8 | 여러 연결에 갱신·생애주기 콜백을 등록한 뒤 평상시 또는 Update 중에 허브를 폐기한다. | 구독 해제 알림이 연결 순회를 바꾸지 않으며 모든 Disposing·Disposed 콜백을 정해진 순서로 통지한다. 예외 없이 최종 참조·연결을 정리한다. |

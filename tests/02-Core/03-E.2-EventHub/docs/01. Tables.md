## 연결과 Builder 수명

EventHub는 리스너 연결과 생애주기를 소유하고 갱신 전달은 하나의 EventStream 그래프에 위임한다. LifecycleHub의 검증 기준은 별도의 [상태·동작 표](../../03-E.1-LifecycleHub/docs/01.%20Tables.md)에 둔다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 새 리스너, null, 기존 직접 구독 키를 Connect한다. | 새 연결만 등록하며 null과 중복은 거부한다. ConnectionCount·HasListener는 직접 구독 연결도 포함한다. |
| C2 | 연결된 리스너, 없는 리스너, null을 Disconnect한다. | 해당 리스너의 모든 경로 구독과 생애주기 콜백을 해제하고 없는 연결은 무시한다. |
| C3 | 명시적 해제나 마지막 등록 제거 뒤 같은 키를 다시 연결한다. | 새 Builder만 사용할 수 있고 이전 Builder의 모든 메서드는 InvalidOperationException이다. |
| C4 | 해제된 Builder와 연결 상태였던 Builder를 허브 폐기 후 사용한다. | typed·object·생애주기 인터페이스 모두 ObjectDisposedException이다. 폐기 전 해제된 Builder는 InvalidOperationException이다. null 인자보다 수명 검사를 우선한다. |
| C5 | 생성자 콜백과 직접·Builder 등록이 같은 대리자 키를 사용한다. | 하나의 연결로 계산한다. -=는 해당 이벤트만, Disconnect는 모든 등록을 제거한다. |
| C6 | 아직 등록하지 않은 빈 연결과 마지막 구독이 실패한 연결을 갱신한다. | 빈 Connect 연결은 유지하며 실패로 비워진 연결은 제거한다. null 등록은 새 연결을 만들지 않는다. |

## 갱신 경로와 직접 구독

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| U1 | 루트의 여러 리스너·직접 구독과 자식·손자·형제 경로에 등록한다. | 일치하는 모든 경로·구독에 전달한다. 일반 노드·구독 사이의 등록 순서는 보장하지 않는다. |
| U2 | 두 리스너가 같은 대리자로 Where를 구성하고 한 연결씩 해제한다. | 한 갱신에 조건을 한 번만 평가한다. 한 연결의 해제는 다른 연결을 유지하고 마지막 해제 뒤에는 조건을 평가하지 않는다. |
| U3 | 기존 콜백이 있는 typed·object Builder에서 Where(null)을 구성한다. | 등록 시 ArgumentNullException이며 기존 연결은 다음 갱신도 계속 받는다. EH-02의 해결 기준이다. |
| U4 | Where 뒤 Debug에 일치·불일치 값을 보낸다. | 통과한 값만 메시지와 지정한 로그 수준으로 기록하고 원래 값을 콜백에 전달한다. |
| U5 | typed·object Builder의 루트·Where 뒤에서 인자 없는 OnUpdated를 등록한다. | 루트는 모든 값을 받고 조건 경로는 참인 값만 받는다. OnUpdated는 같은 Builder, Where는 새 Builder를 반환한다. |
| U6 | 전파 중 Builder·직접 구독을 추가하고, 리스너를 해제하거나 Update에 재진입한다. | 구독 변경은 내부 루트 종료 때 반영하며 새 구독은 다음 갱신부터 받는다. 현재 단위의 삭제 대상도 이번 갱신은 받는다. 재진입 Update는 생략한다. |
| D1 | 같은 직접 Updated 콜백을 중복 등록하고 해제한다. | 중복은 InvalidOperationException이며 기존 등록은 유지한다. -=로 마지막 등록을 제거하면 연결도 사라진다. |
| D2 | typed·object Updated에 멀티캐스트를 등록하고 내부 항목 또는 전체 묶음을 해제한다. | 전달한 묶음 하나가 등록 하나이다. 전체 묶음으로만 해제하며 부분 해제는 무시한다. |
| D3 | 갱신 중 앞 구독이 실패한 뒤 -=를 수행하거나 현재 멀티캐스트를 해제한다. | 실패한 등록과 해제 요청을 루트 종료 때 정리한다. 명시적인 자기 해제는 현재 멀티캐스트의 나머지를 중단하지 않는다. |
| D4 | 같은 원본 대리자를 typed/object Updated에 등록한다. | 같은 연결 안의 별도 등록이며 각각 중복을 거부하고 별도로 해제한다. |
| D5 | Builder에서 같은 콜백을 같은 경로와 별도로 만든 경로에 등록한다. | 같은 경로 인스턴스·콜백 형식의 중복만 거부한다. object·인자 없음 어댑터도 원본 대리자로 검사한다. |

## 실패와 참조 정리

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| F1 | 직접·Builder 멀티캐스트의 항목 하나가 실패한다. | 한 번 보고하고 등록 묶음 전체를 해제한다. 같은 연결의 다른 갱신·생애주기 등록은 유지한다. |
| F2 | 처리기가 없거나 보고기가 예외를 던지는 상태에서 여러 구독이 실패한다. | 새 콜백을 중단하고 필요한 정리 후 첫 미처리 예외를 전달한다. 미실행 구독은 다음 갱신에도 유지한다. |
| F3 | typed·object 직접 구독이 실패하고 같은 콜백을 -=로 제거한다. | 실패한 구독을 정리하고 처리기 반환 시 계속하거나 재전파 시 중단한다. 이후 해제와 다음 갱신은 안전하다. |
| F4 | 여러 리스너가 공유하는 Where 조건이 실패한다. | 해당 경로의 구독을 해제하고 한 번 보고한다. 다른 등록은 유지하며 빈 연결은 제거한다. |
| F5 | 실패하거나 명시적으로 해제된 콜백의 대상 참조를 버린다. | 허브나 해제된 Builder가 살아 있어도 제거된 대리자 키·콜백 대상은 GC로 수거할 수 있다. |
| F6 | 직접·Builder 생애주기 콜백이 실패한다. | 연결 전체를 해제하고 한 번 보고한다. 자신을 해제한 직후 실패해도 원래 예외를 보고한다. |
| F7 | 실패한 갱신 콜백을 같은 Update 안에서 다시 등록한다. | 반영 전에는 기존 등록이 있으므로 중복 등록을 거부한다. Update 종료 후에는 다시 등록할 수 있다. |

## 수면과 폐기

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| S1 | Sleep·Sleep(Token)·TrySleep으로 재운 뒤 Token을 폐기한다. | 수면 중 갱신은 보류 없이 생략하고 깨어난 뒤부터 전달한다. onAwake는 깨어난 상태에서 한 번 호출한다. |
| S2 | 이미 수면 중인 허브에 Sleep·TrySleep을 적용한다. | Sleep은 거부하고 TrySleep은 기존 수면을 유지한다. 보조 핸들은 해제할 때 전달받은 onAwake만 실행한다. |
| S3 | null·폐기된 Token으로 재우거나 수면 중 허브를 폐기한다. | 잘못된 Token은 거부하고 활성 상태를 유지한다. 폐기된 허브는 이후 Token이 끝나도 깨우기 콜백을 실행하지 않는다. |
| L1 | 서로 다른 경로의 Builder와 직접 이벤트에 생애주기 콜백을 등록하고 폐기한다. | 모든 Disposing → IsDisposed 전환 → 모든 Disposed 순서이다. 같은 연결·단계에서는 오버로드와 관계없이 등록 순서이며 연결 간 순서는 보장하지 않는다. |
| L2 | 갱신 콜백에서 Dispose하거나 멀티캐스트 앞 항목에서 Disconnect한다. | 현재 루트의 구독과 멀티캐스트를 마친 뒤 삭제를 반영한다. 폐기 알림은 루트 전파 종료 후 실행한다. |
| L3 | Disposing 중 현재·이후 등록이나 연결을 제거한다. | 제거된 등록의 남은 호출은 생략하며 다른 등록은 유지한다. 반복 Dispose는 무시하고 최종 참조·연결을 정리한다. |
| L5 | 같은 생애주기 이벤트의 동일한 원본 대리자를 중복 등록한다. | 경로와 관계없이 InvalidOperationException이다. -=는 해당 단계의 일치하는 등록만 제거한다. |
| L6 | 직접 생애주기 멀티캐스트의 내부 콜백 또는 전체 묶음을 해제한다. | 내부 콜백만 지정하면 등록은 유지하고, 전체 묶음을 지정하면 해당 등록만 제거한다. |
| L7 | 직접 생애주기 멀티캐스트의 첫 콜백이 실패한다. | 해당 연결의 나머지 등록은 생략한다. 보고가 정상 반환하면 다른 연결을 계속하며, 보고가 예외를 전파해도 최종 참조 정리는 수행한다. |

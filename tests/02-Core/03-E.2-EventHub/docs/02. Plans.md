## 실행 구성

[EventHubTests](../EventHubTests.cs)와 [EventHubFlagsTests](../EventHubFlagsTests.cs)를 NUnit 직접 사례로 실행하고, [EventHubRandomContinuousTests](../EventHubRandomContinuousTests.cs)에서 이름별 등록의 랜덤 연속 사례를 실행한다. 본체는 ProjectReference로 연결하며, 테스트 프로젝트는 .NET 10·C# 9이다. LifecycleHub 사례는 [별도 테스트](../../03-E.1-LifecycleHub/docs/02.%20Plans.md)로 분리한다. 기준은 [상태·동작 표](01.%20Tables.md)이다.

## 검증 방법

- 테스트 클래스 전체를 NonParallelizable로 두고 각 사례 전후 ExceptionHandler를 초기화한다. 전역 처리기의 상태가 다른 사례에 남지 않게 한다.
- 할당 측정 구간에 등록·단언·출력·대리자 생성을 넣지 않는다. object 박싱은 무할당 측정에서 제외한다.
- 참조 수거 검사는 NoInlining 보조 메서드에서 대상을 등록하여 호출자 스택에 대상의 강한 참조가 남지 않게 한다.
- 해제 알림 전환의 계약은 D1·F4–F8·L8에서 확인한다. 마지막 등록 실패로 끊긴 Builder는 즉시 재등록을 거부하고, 직접 구독은 새 연결로 다음 갱신부터 호출하는지 구분한다.
- OnUpdatedForFlags 통합 사례는 공개 Builder 호출과 수신·조건 평가 이력으로 검증한다. 별도 IEventHubBuilder&lt;ulong&gt; 구현의 NotSupportedException 계약은 위 직접 사례의 실행 범위에 포함하지 않는다.
- 공개 API 변경이나 여러 모듈에 걸친 변경은 전체 Release 테스트로 확인한다. 기능 검증에는 장시간 벤치마크와 외부 장비 테스트를 포함하지 않으며, 과거 성능 비교의 조건은 별도 절에 둔다.
- 랜덤 연속 테스트는 RandomContinuous 범주로 표시한다. seed 0·1·2의 실제 테스트 실행시간 합계가 60초를 넘으면 [공통 테스트 안내](../../../README.md)의 중간 확인 규칙을 따른다. 빌드·복원 시간은 제외하며 seed·도달 깊이·실행시간·이력을 TRX에 기록한다.
- 이름으로 구분한 등록 API는 C1–C6·U1–U3·U5–U7·U9·U11·K1–K9·D4–D6·L1과 R1에서 연결 수명, 조건 값 중복, 노드 공유, 콜백 형식과 생애주기를 확인한다. 기존 갱신·수면·폐기·실패·할당 사례도 함께 유지한다.
- 값 조건은 U7·U9·U11·D5·K8·R1에서 확인한다. 중복 판정은 기존 값 기준을 유지하며 같은 위치의 동등한 target은 경로를 공유한다. EventCondition의 복합 경로·Debug·깊이 제한 사례 U4·U8·U10은 현재 공개 API 범위에서 제외한다. 처리량 비교, 벤치마크 및 Unity Mono·IL2CPP의 할당 검증은 실행 범위에 포함하지 않는다.

## 과거 검증 범위

현재 공개 API 이전 단계의 검증 범위이다. 아래 범위를 현재 코드에 다시 적용하는 것이 아니라, [검증 결과](../../docs/Hub%20Results.md)의 실행별 대상과 기대 계약을 구분하는 데 사용한다. 현재 검증은 앞의 상태·동작 대응을 따른다.

| 검증 대상 | 범위와 기대 계약 |
| --- | --- |
| EventStream 경로 이전 | 공유 Where의 평가 횟수, 루트 우선·자식 생성 순서, null 조건, Debug·콜백 형식, 실패 후 남은 전파와 참조 회수, 수면·폐기를 확인한다. 당시 멀티캐스트는 실패한 호출 항목만 해제하는 계약으로 검사한다. |
| 모듈 분리 | 본체·테스트를 빌드하고 전체 테스트를 실행한다. 이동한 LifecycleHub와 EventHub 사례를 나누어 집계하며 공개 API·행동의 동일성을 확인한다. |
| 직접 생애주기 구독 전환 | 직접 +=의 대리자 묶음 등록, -=의 첫 일치·전체 묶음 해제, 내부 실패 시 묶음의 나머지 생략과 보고 정책, 폐기 중 변경·할당을 두 Hub에서 검사한다. |
| 등록 경로 통합 | C5–C6·D1–D6·F1–F8·L1–L8에서 직접·Builder·생성자 등록의 키 공유, 중복·해제·실패·참조 회수와 생애주기 순서를 확인한다. 멀티캐스트 실패는 등록 묶음 전체를 해제하는 계약으로 검사한다. |
| 중복 등록 예외·메시지 | 두 Hub에서 중복 등록의 InvalidOperationException과 기존 등록 유지를 확인한다. 오래된 Builder의 예외 메시지도 검사한다. |
| 해제 알림 전환·Connection 정리 | 마지막 갱신 제거·실패 직후의 연결 상태, 생애주기 연결의 유지와 재등록, 실패 콜백 대상의 참조 회수, 폐기 알림·첫·반복 갱신 할당을 확인한다. 공개 API로 만들 수 없는 내부 상태의 과거 사례는 현재 범위에 포함하지 않는다. |
| 비트 조건·Builder 분리 | K1–K9와 기존 연결·갱신·실패·수면·생애주기·할당 범위를 실행한다. 첫·반복 할당 측정은 예열과 같은 NoInlining 발행 메서드를 사용한다. |
| 조건·콜백 결합형 등록·When 통합 | C·U·K·D·F·S·L·A의 직접 범위와 R1의 세 seed를 실행한다. When 이전 값 조건과 target 단축형의 공유 차이는 당시 계약으로 구분하고, When 이후에는 동등한 target의 경로 공유를 검사한다. |
| EventStream 키 행 구조 | K3에서 Where(a)→Flags(m)→Where(b)의 a·b→flags 방문과 루트 우선을 확인한다. EventStream·EventHub 선택 실행 후 전체 테스트와 R1을 실행한다. |

When과 키 행 구조의 선택 실행 명령·EventStream 범위는 [EventStream 계획](../../02-E.3-EventStream/docs/02.%20Plans.md)을 따른다. 결과 파일 이름과 폴더는 검증 대상마다 구분하고, 전체 실행의 모듈별 부분집합을 별도 실행처럼 합산하지 않는다.

## 구독 해제 알림 전환의 성능 비교

매 Update 뒤의 구독 정리 순회를 해제 알림으로 바꾼 과거 실험의 계획이다. 이후 공개 API에 맞춘 새 벤치마크나 재실행 계획은 아니다. 현재 소스에 없는 당시 측정 코드는 같은 폴더의 [Historical Code](Historical%20Code.md)에 보존한다.

| 항목 | 측정 조건 |
| --- | --- |
| 비교 대상 | 변경 전은 2a66c2d06ed03d44e5566a06c1b84d74821aa497, 변경 후는 해제 알림 전환 당시 작업 트리의 사본이다. 같은 C# 측정 프로그램을 각각의 Release 라이브러리에 연결하고 실행 파일의 동일성을 확인한다. |
| 프로세스 | 변경 전후를 별도 프로세스로 순서대로 실행한다. affinity 0x3과 High 우선순위를 설정하며 TieredCompilation·TieredPGO를 모두 활성화한다. |
| 시나리오 | 같은 Where 조건을 공유하는 리스너 10·100·1,000명을 등록한다. 항상 거짓인 조건과 모든 리스너에게 전달하는 조건을 각각 측정한다. |

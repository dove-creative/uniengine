# EventStream 상태와 동작

## 목차

1. 공개 계약과 연산자
2. 구독 수명 상태 전이

## 공개 계약과 연산자

공통 계약은 기본 EventStream, OrderedEventStream, EventRouter에 같은 입력을 주고 공개 API를 통해 확인한다. 연산자와 조합 사례는 각 경로에 값을 발행하고 수신 순서와 종료 시점을 관찰한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | Subscribe로 등록한 하위를 폐기한다. | 일반 구독은 상위 핸들을 하위에 인계하지 않는다. 호출자가 핸들을 해제하면 연결이 끝난다. |
| C2 | 같은 하위를 두 번 연결한 뒤 한 핸들을 해제한다. | Chain은 하위를, Connect는 상위를 반환한다. 핸들로 한 등록을 끊을 수 있고, 하위 폐기는 남은 연결을 해제한다. |
| C3 | 기존 구독이 있는 상위에 새 수신자가 연결 핸들 인계를 거부한다. | 새 연결을 정리하고 인계 예외를 호출자에게 전달한다. 기존 구독은 다음 값을 받는다. |
| C4 | 비활성 상위에 값을 발행하고 완료 또는 오류를 통지한다. | 값은 전달되지 않으며 종료 통지는 연결된 하위에 도달한다. 상위와 하위가 폐기된다. |
| C5 | 연결된 상위에 명시적으로 Dispose를 호출한다. | 하위는 종료 통지를 받지 않고 이후 값을 직접 발행할 수 있다. |
| O1 | SkipWhile과 Where에 같은 조건 변화를 준다. | SkipWhile은 첫 false인 값부터 조건을 다시 보지 않고, Where는 활성 입력마다 조건을 평가한다. |
| O2 | Take에 0 이하의 횟수를 지정하거나, 양수 횟수가 일부 소모된 뒤 수신자를 추가한다. | 0 이하는 첫 활성 입력에서 값을 전달하지 않고 완료한다. 양수 횟수는 새 구독자도 같은 잔여 횟수를 공유한다. |
| O3 | 외부 상태를 보는 TakeWhile 조건이 false가 된 뒤 원본에 다시 값을 발행한다. | 조건이 끝난 값은 전달하지 않고 완료한다. 원본의 별도 구독은 이후 값도 받는다. |
| O4 | 같은 원본에서 두 번 Append하고 한 하위의 구독을 해제한 뒤 다시 구독한다. | 두 하위는 별도의 기본 스트림이며 Complete 정책으로 유지된다. 각 분기의 구독은 독립적이다. |
| I1 | 여러 대상을 지정한 라우터를 순서 스트림에 연결했다가 연결 핸들을 해제한다. | 마스크가 겹치는 값만 그룹 순서대로 전달된다. 연결 해제 후에도 하위의 직접 발행은 가능하다. |

## 구독 수명 상태 전이

기본 정책이 Complete인 source에 NoSubscribers 정책의 Where를 연결하고, 조건에 맞는 짝수를 두 구독자에게 전달한다. U1과 U2는 Where를 비활성화하는 단계까지 같은 이력을 가진다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 두 구독자를 연결하고 2를 발행한다. | 두 구독자에게 각각 2가 한 번 전달되고 조건은 한 번 평가된다. |
| 공통 | 첫 구독을 해제하고 3, 4를 발행한다. | 첫 구독자의 수신은 2에서 끝나며, 남은 구독자는 4도 받는다. 조건은 누적 세 번 평가된다. |
| 공통 | Where를 비활성화하고 6을 발행한다. | 조건 평가 횟수와 두 구독자의 수신 목록은 그대로이다. |
| U1 | Where를 다시 활성화하고 8을 발행한 뒤 마지막 구독 핸들을 해제한다. | 남은 구독자가 8을 받고 Where가 폐기된다. source에 새로 구독하면 10을 받을 수 있고 Where 조건은 더 이상 평가되지 않는다. |
| U2 | Where가 비활성인 상태에서 source를 완료한다. | 남은 구독자만 완료를 한 번 받고 두 스트림 모두 폐기된다. 값 조건은 다시 평가되지 않는다. |

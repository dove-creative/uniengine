## UniTest 실행 경로

다섯 프로젝트는 CompactProject와 CompactLab을 Inline 모드에서 실행한다. 각 경로에서 이전 동작을 재현한 상태에 다음 Lab을 적용하며, 값·종료 통지·연결 수·폐기 상태와 실제 종료 이력 목록을 확인한다. 실행 후 모든 재현 모델의 스트림을 정리한다.

[Branch 프로젝트](../UniTest/EventStreamStateProjectTests.cs)는 기존 두 종료 경로를 유지한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | SubscribePair → ReleaseFirst → PublishWhileDisabled |
| U1 | ResumePublication → ReleaseLast |
| U2 | CompleteWhileDisabled |

[Merge 프로젝트](../UniTest/EventStreamMergeStateProjectTests.cs)의 MergeLifetimesSucceedThroughUniTest는 아홉 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | ConnectPair |
| UM1–UM8 | CompleteFirst 또는 DisposeFirst → ContinueRemaining → CompleteLast·DisposeLast·ErrorLast·ReleaseLast 중 하나 |
| UM9 | ReleaseBothInputs |

[상태 연산자 프로젝트](../UniTest/EventStreamOperatorStateProjectTests.cs)의 StatefulOperatorLifetimesSucceedThroughUniTest는 네 연산자를 NUnit 매개변수로 실행하고 합계 여섯 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | PrimeDirectInput → SubscribeAndAdvance → DisableInputs → ResumeAndSubscribeLate |
| US1 | PublishRemaining으로 Take 완료 |
| US2 | PublishRemaining → ReleaseLast |
| US3 | PublishRemaining → CloseCondition |
| US4 | PublishRemaining → PublishAfterOpenAndRelease |
| US5–US6 | FailCondition으로 TakeWhile·SkipWhile 실패 |

[ForFlags 공유와 수명 프로젝트](../UniTest/EventStreamFlagsStateProjectTests.cs)의 FlagsSharingAndLifetimesSucceedThroughUniTest는 비활성과 재활성 상태에서 네 종료 방식을 조합해 여덟 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | RegisterSharedMasks → ReleaseFirst → DisableInputs |
| UF1–UF4 | Complete·Error·Dispose·ReleaseAll 중 하나 |
| UF5–UF8 | ResumePublication → Complete·Error·Dispose·ReleaseAll 중 하나 |

같은 비트의 다른 enum 마스크는 같은 순서 그룹에서 공유하고 그룹 사이에서는 분리되는지 확인한다. 첫 구독 해제·비활성화·재활성화 이후의 수신 이력과 노드 수를 이어서 검사하고, 입력에 맞지 않았던 마스크의 종료 전달과 전체 해제 뒤 Source 재사용도 검증한다. 보고서의 실제 종료 이력은 여덟 기대 경로와 대조한다.

[ForFlags 발행 중 변경 프로젝트](../UniTest/EventStreamFlagsMutationProjectTests.cs)의 FlagsPublicationMutationsSucceedThroughUniTest는 추가·재등록·제거의 세 경로마다 다음 값을 발행하고, 전체 해제와 완료로 나누어 합계 여섯 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | RegisterRoutes |
| UFM1–UFM2 | AddDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |
| UFM3–UFM4 | ReplaceDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |
| UFM5–UFM6 | RemoveDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |

각 변경은 마스크와 일치하는 값의 콜백 안에서 수행한다. 현재 발행의 가시성, 다음 발행의 수신 집합, 공유된 항목 수와 최종 정리를 상태별로 검증하며, 보고서의 실제 종료 이력이 여섯 기대 경로와 일치하는지도 확인한다.

## 랜덤 연속 테스트

다섯 UniTest 프로젝트는 위의 고정 검증에 사용한 Lab과 검증 조건으로 각각 seed 0·1·2를 깊이 100까지 실행한다. 각 seed는 새 프로젝트와 빈 초기 상태에서 시작한다. 한 수명 흐름 안에서는 앞 단계의 구독·발행·종료 상태를 이어 받아 검증한다. 종료 Lab의 검증이 끝나면 해당 스트림을 정리하고 다음 흐름을 시작하므로 같은 실행에서 여러 경로를 이어서 검사한다.

| 범위 | 랜덤 후보 |
| --- | --- |
| Branch U1–U2 | 비활성 상태에서 완료하거나 발행을 재개한 뒤 마지막 구독을 해제한다. |
| Merge UM1–UM9 | 두 입력에서 해제하거나 첫 입력을 완료·폐기한다. 남은 입력에서는 완료·폐기·오류·해제를 검사한다. |
| 상태 연산자 US1–US6 | 새 수명 흐름마다 Take·Skip·TakeWhile·SkipWhile 중 하나로 시작한다. 조건 연산자에서는 일반 발행과 조건 실패를 후보로 둔다. |
| ForFlags 공유·수명 UF1–UF8 | 비활성 상태에서 종료하거나 발행을 재개한다. 완료·오류·폐기·전체 해제는 비활성 상태와 재개 후에 각각 검사한다. |
| ForFlags 발행 중 변경 UFM1–UFM6 | 발행 중 추가·재등록·제거를 적용하고 다음 발행을 확인한 뒤 전체 해제하거나 완료한다. |

첫 실패에서 해당 seed 실행을 종료하며 별도의 자동 취소 시간은 두지 않는다. 각 실행의 깊이·성공·취소 여부를 검사하고 seed, 실제 깊이, 소요 시간과 이력을 NUnit 출력에 남긴다. 프로젝트별 세 seed의 실제 테스트 시간 합계가 60초를 넘으면 [테스트 안내](../../../README.md)의 테스트 작성 기준에 따라 중간 확인한다.

## 실행과 기록

.NET 10 Release에서 본 모듈과 전체 테스트를 실행한다. [검증 결과](03.%20Results.md)에 실행 범위와 결과를 기록한다.

ForFlags와 FlagExtensions의 공개 API 추가는 `tests/UniEngine.Tests.csproj` 전체 실행으로 검증한다. ForFlags 할당 사례는 준비·구독을 측정 구간 밖에서 수행하고 별도 인스턴스의 첫 발행과 10,000회 반복 발행을 각각 확인한다. Where와의 속도 비교나 벤치마크는 이번 검증에 포함하지 않는다.

ForFlags의 UniTest 상태 전이 보강은 테스트와 테스트 문서만 추가·수정하므로 EventStream 모듈 전체를 다시 실행한다. 신규 NUnit 사례 두 개와 그 안의 종료 이력 14개는 구분하여 기록하며, 앞선 공개 API 추가 시점의 전체 테스트 결과도 보존한다.

ForOrderAsync는 NUnit 직접 사례로 동시 진행을 검증한다. CountdownEvent와 ManualResetEventSlim으로 실행 지점을 제어하며, Sleep이나 경과 시간 비교에 의존하지 않는다. 신호 대기의 10초 제한은 구현이 순차화되거나 완료를 놓쳤을 때 테스트 프로세스가 멈추지 않게 하는 실패 한도이다. 공개 API 추가와 그래프 변경이므로 전체 테스트 및 기존 동기 할당 검증을 실행하고 대표 벤치마크를 이전 커밋과 비교한다.

## 루트·Order 경계 검증

[EventStreamBoundaryTests](../EventStreamBoundaryTests.cs)는 Q1–Q6을 동기·병렬 실행, 중첩 Order, 연결 및 명시적 다른 타입 스트림 발행으로 검증한다. 구독 핸들의 실제 반영 상태와 현재·다음 발행의 수신을 함께 확인한다. Exception Handler 재전파는 미실행 호출 중단과 정리 완료를 검사하며, 일반 경로의 수신 집합에는 등록 순서를 요구하지 않는다.

ForFlags 변경 모델도 루트 종료 시점의 상태로 갱신한다. 기존 직접 경로와 seed 0·1·2, 깊이 100의 랜덤 연속 검증을 모두 실행한다. Release 전체 테스트와 기존 할당 검증을 실행하고, 리팩터링 직전 작업 트리 빌드를 기준으로 Quick 벤치마크 6개를 같은 CPU에서 각 2회 비교한다.

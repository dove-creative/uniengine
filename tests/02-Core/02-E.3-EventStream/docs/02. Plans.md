## UniTest 실행 경로

일곱 프로젝트는 CompactProject와 CompactLab을 Inline 모드에서 실행한다. 각 경로에서 이전 동작을 재현한 상태에 다음 Lab을 적용하며, 값·종료 통지·연결 수·폐기 상태와 실제 종료 이력 목록을 확인한다. 실행 후 모든 재현 모델의 스트림을 정리한다.

[Branch 프로젝트](../UniTest/EventStreamStateProjectTests.cs)는 기존 두 종료 경로를 유지한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | SubscribePair → ReleaseFirst → PublishWhileDisabled |
| U1 | ResumePublication → ReleaseLast |
| U2 | CompleteWhileDisabled |

[Merge 프로젝트](../UniTest/EventStreamMergeStateProjectTests.cs)의 MergeLifetimesSucceedThroughUniTest는 아홉 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | ConnectPair |
| UM1–UM8 | CompleteFirst 또는 DisposeFirst → ContinueRemaining → CompleteLast·DisposeLast·ErrorLast·ReleaseLast 중 하나 |
| UM9 | ReleaseBothInputs |

[상태 연산자 프로젝트](../UniTest/EventStreamOperatorStateProjectTests.cs)의 StatefulOperatorLifetimesSucceedThroughUniTest는 네 연산자를 NUnit 매개변수로 실행하고 합계 여섯 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | PrimeDirectInput → SubscribeAndAdvance → DisableInputs → ResumeAndSubscribeLate |
| US1 | PublishRemaining으로 Take 완료 |
| US2 | PublishRemaining → ReleaseLast |
| US3 | PublishRemaining → CloseCondition |
| US4 | PublishRemaining → PublishAfterOpenAndRelease |
| US5–US6 | FailCondition으로 TakeWhile·SkipWhile 실패 |

[ForFlags 공유와 수명 프로젝트](../UniTest/EventStreamFlagsStateProjectTests.cs)의 FlagsSharingAndLifetimesSucceedThroughUniTest는 비활성과 재활성 상태에서 네 종료 방식을 조합해 여덟 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | RegisterSharedMasks → ReleaseFirst → DisableInputs |
| UF1–UF4 | Complete·Error·Dispose·ReleaseAll 중 하나 |
| UF5–UF8 | ResumePublication → Complete·Error·Dispose·ReleaseAll 중 하나 |

같은 비트의 다른 enum 마스크는 같은 순서 그룹에서 공유하고 그룹 사이에서는 분리되는지 확인한다. 첫 구독 해제·비활성화·재활성화 이후의 수신 이력과 노드 수를 이어서 검사하고, 입력에 맞지 않았던 마스크의 종료 전달과 전체 해제 뒤 Source 재사용도 검증한다. 보고서의 실제 종료 이력은 여덟 기대 경로와 대조한다.

[ForFlags 발행 중 변경 프로젝트](../UniTest/EventStreamFlagsMutationProjectTests.cs)의 FlagsPublicationMutationsSucceedThroughUniTest는 추가·재등록·제거의 세 경로마다 다음 값을 발행하고, 전체 해제와 완료로 나누어 합계 여섯 종료 이력을 확인한다.

| 구간 | Lab 순서 |
| --- | --- |
| 공통 | RegisterRoutes |
| UFM1–UFM2 | AddDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |
| UFM3–UFM4 | ReplaceDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |
| UFM5–UFM6 | RemoveDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |

각 변경은 마스크와 일치하는 값의 콜백 안에서 수행한다. 현재 발행의 가시성, 다음 발행의 수신 순서, 공유된 항목 수와 최종 정리를 상태별로 검증하며, 보고서의 실제 종료 이력이 여섯 기대 경로와 일치하는지도 확인한다.

When은 [공유와 수명 프로젝트](../UniTest/EventStreamWhenStateProjectTests.cs)에서 여덟 종료 이력, [발행 중 변경 프로젝트](../UniTest/EventStreamWhenMutationProjectTests.cs)에서 여섯 종료 이력을 각각 직접 실행한다. 별도로 만든 동등한 문자열과 null target을 포함하고, Nullable 값의 공유·재등록·추가·제거 후 실제 종료 이력을 기대 경로와 대조한다.

| 구간 | Lab 순서 |
| --- | --- |
| When 수명 공통 | RegisterSharedTargets → ReleaseFirst → DisableInputs |
| UW1–UW4 | Complete·Error·Dispose·ReleaseAll 중 하나 |
| UW5–UW8 | ResumePublication → Complete·Error·Dispose·ReleaseAll 중 하나 |
| When 변경 공통 | RegisterRoutes |
| UWM1–UWM6 | Add·Replace·RemoveDuringPublication → PublishAfterMutation → ReleaseAll 또는 CompleteAll |

## 랜덤 연속 테스트

일곱 UniTest 프로젝트는 위의 고정 검증에 사용한 Lab과 검증 조건으로 각각 seed 0·1·2를 깊이 100까지 실행한다. 각 seed는 새 프로젝트와 빈 초기 상태에서 시작한다. 한 수명 흐름 안에서는 앞 단계의 구독·발행·종료 상태를 이어 받아 검증한다. 종료 Lab의 검증이 끝나면 해당 스트림을 정리하고 다음 흐름을 시작하므로 같은 실행에서 여러 경로를 이어서 검사한다.

| 범위 | 랜덤 후보 |
| --- | --- |
| Branch U1–U2 | 비활성 상태에서 완료하거나 발행을 재개한 뒤 마지막 구독을 해제한다. |
| Merge UM1–UM9 | 두 입력에서 해제하거나 첫 입력을 완료·폐기한다. 남은 입력에서는 완료·폐기·오류·해제를 검사한다. |
| 상태 연산자 US1–US6 | 새 수명 흐름마다 Take·Skip·TakeWhile·SkipWhile 중 하나로 시작한다. 조건 연산자에서는 일반 발행과 조건 실패를 후보로 둔다. |
| ForFlags 공유·수명 UF1–UF8 | 비활성 상태에서 종료하거나 발행을 재개한다. 완료·오류·폐기·전체 해제는 비활성 상태와 재개 후에 각각 검사한다. |
| ForFlags 발행 중 변경 UFM1–UFM6 | 발행 중 추가·재등록·제거를 적용하고 다음 발행을 확인한 뒤 전체 해제하거나 완료한다. |
| When 공유·수명 UW1–UW8 | 비활성 상태에서 종료하거나 재개한 뒤 완료·오류·폐기·전체 해제를 수행한다. 동등 문자열의 공유와 null 항목의 수명을 함께 확인한다. |
| When 발행 중 변경 UWM1–UWM6 | 값 항목에 추가·재등록·제거를 적용하고 1·null·2의 다음 발행을 확인한 뒤 전체 해제하거나 완료한다. |

첫 실패에서 해당 seed 실행을 종료하며 별도의 자동 취소 시간은 두지 않는다. 각 실행의 깊이·성공·취소 여부를 검사하고 seed, 실제 깊이, 소요 시간과 이력을 NUnit 출력에 남긴다. 프로젝트별 세 seed의 실제 테스트 시간 합계가 60초를 넘으면 [테스트 안내](../../../README.md)의 테스트 작성 기준에 따라 중간 확인한다.

ForFlags·When의 할당 검증은 준비·등록을 측정 구간 밖에서 수행하고, 별도 인스턴스를 예열한 뒤 새 인스턴스의 첫 발행과 10,000회 반복 발행을 측정한다. 기능 검증에는 속도 비교와 PathInfo 크기 측정을 포함하지 않는다. Unity Mono·IL2CPP의 동작·할당·스택 여유와 실게임 프레임 비용은 이 .NET 검증 범위에서 제외한다.

저장소 루트에서 실행한다. TRX가 필요하면 테스트 명령에 `--logger 'trx;LogFileName=<이름>.trx' --results-directory tests/bin/TestResults/<검증명>`을 추가한다. 결과 파일은 버전 관리에서 제외한다.

```powershell
dotnet build src/UniEngine.sln -c Release
dotnet build tests/02-Core/02-E.3-EventStream/Benchmarks/EventStreamBenchmarks.csproj -c Release
dotnet test tests/UniEngine.Tests.csproj -c Release --filter 'FullyQualifiedName~BlackThunder.UniEngine.Tests.EventStream'
dotnet test tests/UniEngine.Tests.csproj -c Release --filter 'FullyQualifiedName~When|FullyQualifiedName~EventHub'
dotnet test tests/UniEngine.Tests.csproj -c Release --filter 'FullyQualifiedName~EventStream|FullyQualifiedName~EventHub'
dotnet test tests/UniEngine.Tests.csproj -c Release
```

## 키 행 구조 개편 검증

1단계는 키 행 OOP를 대상으로 본체 Release 빌드 후 EventStream·EventHub 선택 실행과 전체 테스트를 실행한다. NodeCount는 위치별 키 노드와 스트림 연결을 세고 행을 제외하도록 기존 직접·UniTest 단언을 맞춘다. KR1–KR9의 직접 검증과 일곱 UniTest 기본 검증, seed 0·1·2·깊이 100의 랜덤 연속 검증을 모두 실행한다.

2단계 배열 실험도 같은 전체 테스트를 실행하고, 통과 후에만 벤치마크를 유효한 비교 자료로 사용한다. 테스트는 Connection과 행의 동작을 확인하며 자식·행 체인이나 배열의 필드 배치에는 의존하지 않는다. 두 단계의 전체 시나리오 수치는 측정별 결과 폴더에 기록한다.

배열 단계는 과거 실험의 검증 기준이다. 현재 소스에서 제거된 비교 구현은 재실행 대상으로 두지 않으며, 검증 의도를 이해하는 데 필요한 코드는 [이전 비교 구현 코드](Historical%20Code.md)에 발췌한다.

## 구조별 벤치마크 비교

### 공통 측정 조건

[벤치마크 실행기](../Benchmarks/README.md)의 공개 API 시나리오를 같은 측정 소스로 빌드한다. 라이브러리만 비교 대상 버전으로 교체하며, cb62332에서는 동일 Filter 인스턴스를 공유하도록 API 차이를 맞춘다.

시나리오마다 새 프로세스를 affinity 0x3·High 우선순위로 실행한다. 그래프 구성 후 1.5초 예열하고 0.5초씩 다섯 라운드를 측정한다. 각 라운드에서 기대 수신 횟수를 확인하며 시간의 중앙값·작업당 할당·구성 시간·보존 메모리를 기록한다. 발행 시나리오와 E·T의 구독·해제 시나리오는 나누어 집계한다.

회차별 중앙값의 평균을 비교하고, 회차 편차는 '최댓값 / 최솟값 - 1'로 계산한다. 변화율의 절댓값이 10% 이상이고 양쪽 회차 편차보다 클 때만 빠름·느림으로 판정한다. 10% 미만은 차이 기준 미달, 나머지는 보류이다. 이상 구간을 제외한 보충 집계는 모든 구조에 같은 회차 기준을 적용하고 원본 전체 집계와 구분한다.

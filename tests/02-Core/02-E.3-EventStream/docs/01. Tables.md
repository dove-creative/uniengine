## 스트림과 그래프의 공개 계약

EventStream은 값을 받아 그래프로 전달한다. Where·Debug·ForOrder·ForFlags는 경로를 만들고, Take·TakeWhile·Skip·SkipWhile·Branch·Merge는 새 스트림을 시작한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 새 스트림에 구독한 뒤 구독을 하나씩 해제한다. | 마지막 구독을 해제할 때까지 상위 연결을 유지한다. 해제 후 상위의 노드는 없어지고 상위는 그대로 살아 있다. |
| C4 | 비활성 상위에 값을 보낸 뒤 완료 또는 오류를 알린다. | 값은 건너뛰고 종료 신호는 연결된 스트림에 전달한다. |
| C5 | 상위를 명시적으로 폐기한다. | 상위가 만든 스트림은 통지 없이 폐기된다. 생성자로 상위를 받은 독립 스트림은 살아 있고 값을 직접 받을 수 있다. |
| C6 | 새 스트림과 외부 입력 스트림에 OnNext로 값을 직접 넣는다. | 위에서 온 값과 같게 처리하고 그 스트림 아래로만 전달한다. Take·Skip은 횟수에 포함하고, TakeWhile·SkipWhile은 조건을 평가하며, 비활성 스트림은 값을 세지 않는다. 같은 스트림의 전파 중 입력은 거부한다. |
| C7 | 스트림을 다른 스트림의 Subscribe에 수신자로 넘긴다. | 값과 종료 신호를 받는다. 연결은 반환된 핸들로 해제하고, 폐기된 수신자 스트림은 일반 구독의 실패처럼 해제된다. |
| O1 | Where와 SkipWhile에 같은 조건 변화를 준다. | Where는 들어온 값마다 검사한다. SkipWhile은 첫 false부터 이후 값도 그대로 전달한다. |
| O2 | 양수·0·음수 횟수로 Take·Skip을 만들고 같은 스트림에 뒤늦게 구독한다. | 같은 스트림의 구독자는 상태를 공유하고, 연산자를 다시 호출하면 새 상태로 시작한다. 상위 연결은 첫 구독 때 만들고, 직접 입력은 구독 전에도 횟수에 반영한다. 0 이하의 Take는 첫 활성 입력에서 값 없이 완료한다. 끝난 스트림의 구독은 거부한다. |
| O6 | 첫 구독 전에 네 상태 연산자에 상위·직접 입력을 보내고 비활성화·재활성화한다. | 연결 전 상위 입력은 도달하지 않고 직접 입력만 상태에 반영한다. 비활성 직접 입력은 횟수와 조건을 바꾸지 않는다. 구독 전 Take·TakeWhile이 끝나면 상위 연결 없이 폐기되고 구독을 거부한다. |
| O3 | TakeWhile 조건을 닫은 뒤 다시 연다. | 첫 false에서 그 스트림만 완료·폐기한다. 상위의 다른 구독자는 이후 값도 받는다. |
| O4 | 같은 부모에서 Branch를 두 번 만들고 마지막 구독을 해제한다. | 첫 구독까지 부모의 값 경로를 만들지 않는다. 한 Branch의 마지막 해제는 이웃에 영향을 주지 않는다. 부모 종료는 구독 전 Branch의 수명에도 적용된다. |
| O5 | Where 뒤 Debug에 일치·불일치 값을 전달한다. | 통과한 값만 지정한 메시지로 기록하고 원래 값을 전달한다. |
| I1 | 같은 조건 대리자를 두 순서 그룹에 등록하고 한 그룹에서 다시 사용한다. | 같은 그룹에서 조건을 한 번 평가하고 다른 그룹에서는 따로 평가한다. 그룹 등록 순서대로 방문한다. |
| I3 | 그룹과 순서 없는 구독자를 같은 위치에 등록한다. | 순서 없는 구독자를 먼저 호출한 뒤 그룹을 값 순서로 호출한다. |
| I4 | Where 아래에 순서 그룹을 둔다. | 그 위치의 자식이 값 순서로 호출되고 Where 노드는 공유한다. |
| I2 | 조건이 있는 Branch에 구독한 뒤 마지막 구독을 해제한다. | 조건을 통과한 값만 전달한다. 부모의 빈 경로를 정리하고 부모는 새 값을 발행할 수 있다. |
| G1 | 같은 필터·다른 필터를 같은 부모와 서로 다른 부모에 등록한다. | 같은 부모의 같은 대리자만 공유하고, 형제가 많아도 같다. 구독자는 먼저 만들어진 자식보다 앞서 호출한다. 거짓이면 하위 전체를 건너뛴다. 형제가 많은 곳에서 빈 노드를 제거했다가 다시 등록하면 마지막 형제가 된다. |
| G2 | 필터와 Branch를 합쳐 깊이 256인 경로에서 추가 단계를 만든다. | 256단계까지 전파하고 257단계 경로 생성은 거부한다. |
| F1 | 연결된 스트림의 구독과 상위의 구독이 같은 값에서 실패한다. | 정상 수신자까지 순회한 뒤 처음의 미처리 예외를 값을 넣은 쪽에 전달한다. 실패한 두 구독을 해제하고 다음 값은 계속 전달한다. |
| F2 | SkipWhile·TakeWhile 조건이 예외를 던진다. | 그 스트림만 통지 없이 폐기하고 형제에게 값을 전달한다. 처리기가 없으면 순회 후 값을 넣은 쪽에 예외를 전달한다. |
| F3 | Take의 마지막 값 콜백과 다른 구독자의 완료 콜백이 모두 실패한다. | 직접·상위 입력 모두 정상 값·완료 콜백과 상위 형제 전파를 마치고 연결을 정리한다. 보고기가 처리하면 예외 없이 끝나며, 처리하지 않거나 보고기가 실패하면 첫 보고 예외를 유지한다. 값 실패가 없으면 완료 실패를 전달한다. |
| M1 | Merge에 폐기된 입력을 넘기거나, 입력을 하나씩 완료·폐기한다. | 폐기된 입력은 거부한다. 모든 입력이 완료하면 결과도 완료한다. 입력이 폐기되면 그 입력만 빠지고, 입력이 하나도 남지 않으면 통지 없이 폐기된다. |
| M2 | 같은 값이 Branch 두 개를 모두 통과한 뒤 Merge에 도달한다. | 입력마다 한 번씩 전달한다. |
| R1 | 발행 중 구독을 해제하고 새로 구독하거나, 콜백이 실패하거나, 콜백에서 스트림을 폐기한다. | 해제는 현재 발행부터, 새 구독은 다음 발행부터 반영한다. 콜백이 실패해도 남은 구독자는 값을 받으며, 처리기가 없으면 그 뒤에 값을 넣은 쪽에 예외를 전달한다. 어느 경우든 다음 발행은 전달한다. 콜백에서 폐기하면 남은 콜백을 호출하지 않고 이후 값을 거부한다. |

## ForFlags 경로 계약

ForFlags는 `ulong` 값에 enum 마스크의 비트가 하나라도 겹치면 하위를 방문하는 경로 연산이다. 아래 사례는 노드 수와 수신 이력을 함께 확인한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| B1 | 한 비트·여러 비트·0인 값을 단일·복합 마스크에 발행한다. int 부호 비트와 ulong 최상위 비트도 구분한다. | HasAny 판정으로 원래 값을 전달하고, 0인 값은 전달하지 않는다. int 부호 비트가 상위 32비트로 확장되지 않는다. |
| B2 | 스트림 또는 기존 경로에서 0 마스크나 Flags 특성이 없는 enum으로 ForFlags를 호출한다. | 구독 전 경로 구성 시점에 ArgumentException이 발생하고 그래프 노드는 생기지 않는다. |
| B3 | 같은 부모에서 같은·다른 마스크를 등록하고, enum 형식·부모·순서 그룹을 바꾼다. | 같은 부모와 같은 비트만 항목을 공유하며 enum 형식은 구분하지 않는다. FlagsNode와 항목을 각각 노드 수에 포함하고 그룹 사이에서는 공유하지 않는다. |
| B4 | 마스크·Where·같은 위치의 구독자를 순서를 달리해 등록한다. 항목을 해제한 뒤 다시 등록한다. | 항목은 생성 순서, FlagsNode와 Where 사이는 묶음의 생성 순서를 따른다. 같은 위치의 구독자가 자식보다 먼저 호출되며 재생성한 항목은 끝으로 간다. |
| B5 | 발행 중 FlagsNode·항목·구독을 추가하거나 현재·다음 항목과 같은 항목의 뒤 구독을 해제한다. | 추가는 다음 발행부터 보이고 제거는 즉시 반영된다. 제거된 커서를 지나 남은 형제까지 방문하며 재등록한 항목도 이번 값은 받지 않는다. |
| B6 | 마지막 구독을 해제하거나 완료·오류·폐기로 끝낸다. | 빈 항목과 FlagsNode를 정리한다. 기본 스트림은 재사용할 수 있고 관계 스트림은 빈 루트에서 상위 연결까지 해제한다. 종료는 마스크와 관계없이 모든 하위에 전달하며 폐기는 통지하지 않는다. |
| B7 | ForFlags 앞뒤에 Where·Debug·ForOrder·Take·Skip·Branch를 조합하고 256단계 경로를 만든다. | 각 연산 위치에 도달한 값만 처리하고 기존 순서·수명 규칙을 유지한다. ForFlags는 그래프 노드 두 개를 만들지만 경로 깊이는 한 단계이며 257단계 구성은 거부한다. |

## ForFlags 공유와 수명 상태 전이

Source의 Shape 마스크 경로에서 Branch를 만들고, Branch 아래 Update·Render 순서 그룹을 둔다. Update에는 같은 비트인 서로 다른 enum 마스크로 두 명을 등록하고, Render에는 Shape와 입력에 맞지 않는 최상위 비트 마스크를 등록한다. 비활성 상태와 재활성 상태 각각에서 완료·오류·폐기·전체 해제를 조합해 여덟 종료 이력을 확인한다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 공유 마스크와 서로 다른 순서 그룹을 등록하고 값을 발행한다. | Update의 두 구독은 항목을 공유하고, Render의 같은 비트 항목은 분리된다. Branch.NodeCount는 8, Source.NodeCount는 3이며 순서 그룹과 항목의 방문 순서를 지킨다. |
| 공통 | Update의 첫 구독을 해제한다. | 남은 공유 구독과 다른 그룹은 유지되며 노드 수는 줄지 않는다. 해제한 구독은 이후 값과 종료 통지를 받지 않는다. |
| 공통 | Branch를 비활성화하고 상위 입력과 직접 입력을 보낸다. | 두 입력 모두 수신 이력과 노드 수를 유지하고 완료·오류·폐기는 계속 받을 수 있다. |
| UF1–UF4 | 비활성 상태에서 완료·오류·폐기·전체 해제 중 하나를 수행한다. | 완료·오류는 값이 맞지 않았던 최상위 비트의 구독까지 전달한다. 폐기·전체 해제는 통지하지 않는다. 모든 경로와 핸들을 정리한다. |
| UF5–UF8 | 재활성화하고 값을 발행한 뒤 완료·오류·폐기·전체 해제 중 하나를 수행한다. | 남아 있는 Shape 구독이 다시 값을 받고, 네 종료 방식은 비활성 때와 같은 통지·정리 규칙을 따른다. |
| 전체 해제 | Update의 마지막 구독과 Render의 Shape 구독을 차례로 해제한다. | Branch.NodeCount가 8에서 5, 4로 줄고, 값에 맞지 않았던 최상위 비트 구독만 남아도 Branch와 상위 연결은 살아 있다. |
| 전체 해제 | 마지막 구독을 해제한 뒤 Source에 다시 구독하고 발행한다. | Branch는 폐기되고 Source의 빈 마스크 항목·FlagsNode·연결도 정리된다. Source는 살아 있어 새 ForFlags 경로 두 노드로 일치하는 값만 전달하며, 재구독 해제 후 다시 빈 그래프가 된다. |

## ForFlags 발행 중 변경 상태 전이

Shape=1, Location=2, Both=3인 세 마스크 항목을 등록하고 7을 발행한다. 같은 값이 세 항목을 모두 통과하는 상태에서 현재 Shape 콜백이 구독을 변경한다. 변경 직후와 다음 발행의 수신 순서를 따로 확인하며, 각 변경 경로를 전체 해제와 완료의 두 방식으로 끝낸다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 세 마스크 경로를 등록하고 7을 발행한다. | Shape·Location·Both 순서로 받는다. FlagsNode 하나와 항목 세 개로 NodeCount가 4이다. |
| UFM1–UFM2 | 현재 Shape 콜백에서 기존 Location 항목에 늦은 구독과 새 Payload=4 항목을 추가한다. | 현재 발행은 기존 구독만 받는다. NodeCount는 5이며 다음 발행에는 새 구독과 항목도 생성 순서에 따라 받는다. |
| UFM3–UFM4 | 현재 Shape 콜백에서 뒤의 Location 항목을 제거하고 같은 마스크로 다시 등록한다. | 기존·새 Location 구독 모두 현재 값은 받지 않는다. NodeCount는 4이고, 다음 발행에는 새 Location이 마지막 항목으로 받는다. |
| UFM5–UFM6 | 현재 Shape 콜백에서 현재 항목과 뒤의 Location 항목을 제거한다. | 현재 Shape 콜백 뒤에는 Both만 받으며, 다음 발행도 Both만 받는다. FlagsNode와 Both 항목만 남아 NodeCount는 2이다. |
| UFM1–UFM6 | 변경 후 다음 값을 발행한 뒤 모든 구독을 해제하거나 스트림을 완료한다. | 전체 해제는 통지 없이 빈 그래프를 남기고 스트림은 살아 있다. 완료는 남은 구독에 한 번씩 통지한 뒤 그래프와 핸들을 정리한다. |

## Branch 수명 상태 전이

부모의 루트에서 Branch를 만들고 Branch의 짝수 조건에 두 명을 등록한다. U1과 U2는 Branch를 비활성화하는 단계까지 같은 이력을 갖는다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 두 명을 등록하고 2를 발행한다. | 두 구독자가 2를 받고 조건은 한 번 평가된다. 부모에는 Branch 연결 하나, Branch에는 공유 조건 하나가 있다. |
| 공통 | 첫 구독을 해제하고 3, 4를 발행한다. | 첫 구독은 2에서 끝나며 남은 구독은 4도 받는다. 누적 조건 평가 횟수는 3이다. |
| 공통 | Branch를 비활성화하고 부모에 6을 발행한다. | Branch 안의 조건 평가 횟수와 수신 목록은 그대로이다. |
| U1 | Branch를 다시 활성화하고 8을 발행한 뒤 마지막 구독을 해제한다. | 남은 구독자가 8을 받고 Branch와 부모 경로가 정리된다. 부모에 새로 구독하면 10을 받을 수 있고 조건은 누적 4회에서 멈춘다. |
| U2 | Branch가 비활성일 때 부모를 완료한다. | 남은 구독자만 완료를 한 번 받고 두 스트림이 폐기된다. 조건 평가 횟수는 3이다. |

## Merge 수명 상태 전이

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 두 입력에 연결하고 각각 1, 2를 발행한다. | 수신 이력은 1, 2이고 각 입력에는 연결 하나가 있다. |
| UM1–UM8 | 첫 입력을 완료하거나 폐기한 뒤 남은 입력으로 3, Merge에 직접 4를 발행한다. | 종료 통지 없이 1, 2, 3, 4를 받고 남은 입력 연결을 유지한다. |
| UM1–UM8 | 남은 입력 완료·폐기·오류 또는 마지막 구독 해제로 끝낸다. | 완료는 한 번 완료 통지, 오류는 원본 예외 통지, 폐기와 구독 해제는 무통지이다. Merge와 모든 연결이 정리되며 구독 해제 경로의 남은 입력은 재사용할 수 있다. 두 첫 입력 종료 방식과 네 마지막 동작을 조합한다. |
| UM9 | 두 입력이 모두 살아 있을 때 마지막 구독을 해제한다. | 양쪽 연결을 모두 정리하고 입력 두 개는 계속 사용할 수 있다. |

## 상태 연산자 상태 전이

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | Take(3)·Skip(2)·TakeWhile(value < 4)·SkipWhile(value < 3) 중 하나에 구독 전 1을 직접 넣는다. | 상위 연결 없이 상태를 진행하며, 연결 전 상위의 값은 반영하지 않는다. |
| 공통 | 첫 구독 후 상위에서 2를 발행하고, 비활성 중 상위·직접 입력 99를 보낸다. | Take·TakeWhile만 2를 전달한다. 비활성 입력은 횟수·조건 평가·수신 이력을 바꾸지 않는다. |
| 공통 | 재활성화하고 두 번째 구독을 추가한 뒤 상위에서 3을 발행한다. | 두 구독자 모두 3을 받는다. Take는 남은 횟수를 공유하여 완료한다. SkipWhile은 열린 상태로 바뀐다. |
| US1 | Take의 마지막 값으로 끝낸다. | 두 구독자에게 완료를 한 번씩 통지하고 상위 연결을 정리한다. |
| US2 | Skip의 구독을 하나씩 해제한다. | 마지막 해제 때만 폐기하고 상위 연결을 정리한다. 완료 통지는 없다. |
| US3 | TakeWhile에 상위 값 4를 보낸다. | 4는 전달하지 않고 두 구독을 완료하며 조건 평가는 누적 4회이다. |
| US4 | SkipWhile에 상위 값 1을 보내고 구독을 하나씩 해제한다. | 조건을 다시 검사하지 않고 두 구독자에게 1을 전달한다. 조건 평가는 누적 3회이며 마지막 해제로 정리된다. |
| US5–US6 | 재활성화와 늦은 구독 뒤 TakeWhile·SkipWhile의 조건을 실패시킨다. | 스트림은 통지 없이 정리되고 상위의 형제 구독은 현재 값과 다음 값을 받는다. |

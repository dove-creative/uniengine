## 기본 틱 스트림

Main은 호스트가 초 단위 경과 시간을 발행하는 전역 `EventStream<float>`이다. 직접 NUnit 사례로 초기화 전후의 인스턴스·구독·수신 이력을 확인한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| MS1 | Main을 반복 조회하고 float 값과 0을 발행한다. | 초기 접근부터 활성 상태이며 같은 인스턴스가 원래 값을 전달한다. |
| MS2 | Main의 Where 아래 enum 순서 그룹을 역순으로 등록한다. | 조건을 통과한 값만 enum 순서대로 전달한다. |
| MS3 | 구독·Branch·경로를 가진 Main을 비활성화한 뒤 ResetMain을 호출한다. | 기존 스트림과 연결을 완료·오류 알림 없이 정리하고 활성화된 빈 Main을 제공한다. 이전 참조·경로는 재사용할 수 없고 구독은 이전되지 않는다. 독립 스트림은 영향을 받지 않는다. |
| MS4 | Main을 Dispose·OnCompleted·OnError로 종료한 뒤 반복 초기화한다. | 종료만으로는 인스턴스를 교체하지 않는다. 초기화마다 새 스트림이 구독·발행을 받고 이전 스트림은 폐기 상태이다. |
| MS5 | Main과 독립 스트림의 동기·병렬·완료·오류 콜백에서 ResetMain을 호출한다. | InvalidOperationException을 던지고 Main 참조를 유지한다. 호출자가 예외를 처리하면 현재 전파를 마치며 전파 밖에서는 초기화할 수 있다. |

## 스트림과 그래프의 공개 계약

EventStream은 값을 받아 그래프로 전달한다. Where·When·Debug·ForOrder·ForOrderAsync·ForFlags는 경로를 만들고, Take·TakeWhile·Skip·SkipWhile·Branch·Merge는 새 스트림을 시작한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 새 스트림에 구독한 뒤 구독을 하나씩 해제한다. | 마지막 구독을 해제할 때까지 상위 연결을 유지한다. 해제 후 상위의 노드는 없어지고 상위는 그대로 살아 있다. |
| C4 | 비활성 상위에 값을 보낸 뒤 완료 또는 오류를 알린다. | 값은 건너뛰고 종료 신호는 연결된 스트림에 전달한다. |
| C5 | 상위를 명시적으로 폐기한다. | 상위가 만든 스트림은 통지 없이 폐기된다. 생성자로 상위를 받은 독립 스트림은 살아 있고 값을 직접 받을 수 있다. |
| C6 | 새 스트림과 외부 입력 스트림에 OnNext로 값을 직접 넣는다. | 위에서 온 값과 같게 처리하고 그 스트림 아래로만 전달한다. Take·Skip은 횟수에 포함하고, TakeWhile·SkipWhile은 조건을 평가하며, 비활성 스트림은 값을 세지 않는다. 같은 스트림의 전파 중 입력은 거부한다. |
| C7 | 스트림을 다른 스트림의 Subscribe에 수신자로 넘긴다. | 값과 종료 신호를 받는다. 연결은 반환된 핸들로 해제하고, 폐기된 수신자 스트림은 일반 구독의 실패처럼 해제된다. |
| O1 | Where와 SkipWhile에 같은 조건 변화를 준다. | Where는 들어온 값마다 검사한다. SkipWhile은 첫 false부터 이후 값도 그대로 전달한다. |
| O2 | 양수·0·음수 횟수로 Take·Skip을 만들고 같은 스트림에 뒤늦게 구독한다. | 같은 스트림의 구독자는 상태를 공유하고, 연산자를 다시 호출하면 새 상태로 시작한다. 상위 연결은 첫 구독 때 만들고, 직접 입력은 구독 전에도 횟수에 반영한다. 0 이하의 Take는 첫 활성 입력에서 값 없이 완료한다. 끝난 스트림의 구독은 거부한다. |
| O6 | 첫 구독 전에 네 상태 연산자에 상위·직접 입력을 보내고 비활성화·재활성화한다. | 연결 전 상위 입력은 도달하지 않고 직접 입력만 상태에 반영한다. 비활성 직접 입력은 횟수와 조건을 바꾸지 않는다. 구독 전 Take·TakeWhile이 끝나면 상위 연결 없이 폐기되고 구독을 거부한다. |
| O3 | TakeWhile 조건을 닫은 뒤 다시 연다. | 첫 false에서 그 스트림만 완료·폐기한다. 상위의 다른 구독자는 이후 값도 받는다. |
| O4 | 같은 부모에서 Branch를 두 번 만들고 마지막 구독을 해제한다. | 첫 구독까지 부모의 값 경로를 만들지 않는다. 한 Branch의 마지막 해제는 이웃에 영향을 주지 않는다. 부모 종료는 구독 전 Branch의 수명에도 적용된다. |
| O5 | Where 뒤 Debug에 일치·불일치 값을 전달한다. | 통과한 값만 지정한 메시지로 기록하고 원래 값을 전달한다. |
| I1 | 같은 조건 대리자를 두 순서 그룹에 등록하고 한 그룹에서 다시 사용한다. | 같은 그룹에서 조건을 한 번 평가하고 다른 그룹에서는 따로 평가한다. 그룹의 순서 값이 작은 쪽부터 방문한다. |
| I3 | 그룹과 순서 없는 구독자를 같은 위치에 등록한다. | 명시적인 그룹 사이의 순서만 보장한다. 순서 없는 구독의 상대 위치는 보장하지 않는다. |
| I4 | Where 아래에 순서 그룹을 둔다. | 그 위치의 자식이 값 순서로 호출되고 Where 노드는 공유한다. |
| I2 | 조건이 있는 Branch에 구독한 뒤 마지막 구독을 해제한다. | 조건을 통과한 값만 전달한다. 부모의 빈 경로를 정리하고 부모는 새 값을 발행할 수 있다. |
| G1 | 같은 필터·다른 필터를 같은 부모와 서로 다른 부모에 등록한다. | 같은 부모의 같은 대리자만 공유하고 거짓이면 하위를 건너뛴다. 일반 형제·구독 사이의 호출 순서는 보장하지 않는다. |
| G2 | 필터와 Branch를 합쳐 깊이 256인 경로에서 추가 단계를 만든다. | 256단계까지 전파하고 257단계 경로 생성은 거부한다. |
| F1 | 연결된 스트림의 구독과 상위의 구독이 같은 값에서 실패한다. | 첫 미처리 실패에서 새 호출을 중단한다. 실행한 실패 구독만 정리하고 미실행 구독은 다음 발행에 참여한다. |
| F2 | SkipWhile·TakeWhile 조건이 예외를 던진다. | 해당 스트림을 통지 없이 정리한다. 보고가 정상 반환하면 계속하고 재전파되면 후속 호출을 중단한다. |
| F3 | Take의 마지막 값 콜백과 다른 구독자의 완료 콜백이 모두 실패한다. | 처리된 값 실패 뒤에는 완료 통지를 진행한다. 미처리 값 실패 뒤에는 새 값·완료 통지를 시작하지 않으며, 완료만 실패해도 남은 통지를 중단한다. 항상 연결을 정리하고 첫 미처리 예외를 유지한다. |
| M1 | Merge에 폐기된 입력을 넘기거나, 입력을 하나씩 완료·폐기한다. | 폐기된 입력은 거부한다. 모든 입력이 완료하면 결과도 완료한다. 입력이 폐기되면 그 입력만 빠지고, 입력이 하나도 남지 않으면 통지 없이 폐기된다. |
| M2 | 같은 값이 Branch 두 개를 모두 통과한 뒤 Merge에 도달한다. | 입력마다 한 번씩 전달한다. |
| R1 | 발행 중 구독을 해제하고 새로 구독하거나, 콜백이 실패하거나, 콜백에서 스트림을 폐기한다. | 추가·삭제는 루트·Order 종료 때 반영한다. 새 구독은 소유 스트림의 다음 발행부터 받는다. 미처리 실패는 새 호출을 중단한다. 폐기 요청은 현재 단위 완료 후 후속 전파를 중단하고 이후 신규 요청을 거부한다. |

## 키 행 구조와 순회 계약

NodeCount는 경로 노드와 스트림 연결을 세고 루트·공유 Gate·키 행은 세지 않는다. 행은 자기 키와 공통 Connection을 가지며, 그 연결이 다음 노드와 Gate를 참조한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| KR1 | 같은 위치에 같은 키·다른 키를 등록하고 같은 키를 다음 단계에도 등록한다. | 위치별 WhereNode·FlagsNode·WhenNode·OrderedNode 하나 안에서 같은 키의 Connection을 공유한다. 내부 Row는 NodeChild·Node가 아니며, 다음 단계는 별도 노드이다. |
| KR2 | Where(a), ForFlags(m), Where(b) 순서로 등록한다. 각 행의 Gate와 하위 노드도 조합한다. | 키 종류별 노드와 행을 공유하고 일치하는 구독 모두에 전달한다. 일반 노드·행·구독 사이의 호출 순서는 보장하지 않는다. |
| KR3 | Flags a에 한 명, b·c에 두 명씩 구독하고 b·c와 겹치는 값을 발행한다. | b1·b2·c1·c2가 모두 받으며 값 0은 어떤 행에도 전달하지 않는다. 수신 집합으로 검증한다. |
| KR4 | Where·Flags의 서로 다른 키 16개에 중복 구독을 더한 뒤 17번째 키를 추가한다. 행을 하나까지 줄이고 마지막 행도 제거한다. | 16행까지 색인이 없고 중복 구독으로는 전환하지 않는다. 17행에서 색인을 만들고 축소 후 같은 색인을 유지하며 마지막 행 제거 시 해제한다. 빈 노드도 제거한다. |
| KR5 | Where 조건 안에서 현재 행 또는 다음 행을 제거·재등록한다. Ordered의 현재·다음 행을 제거하고 커서 앞뒤 순서 값을 추가한다. | Where의 삭제·재등록은 소유 단위 종료 때 반영한다. 같은 단위의 기존 구독은 현재 값을 받고 새 구독은 다음 값부터 받는다. 앞 Order의 삭제는 뒤 Order 진입 전에 반영하며 명시적인 Order 정렬은 유지한다. |
| KR6 | Where·Flags·When·Order·Debug 각각 256단계 경로에 값을 발행한 뒤 완료·오류·폐기한다. | 발행과 종료가 모두 도달하며 257번째 단계는 구성 때 거부한다. 핸들과 모든 경로를 정리하고 NodeCount는 0이 된다. |
| KR7 | 통과·불일치 키와 Where·Flags의 색인 전환 전후에 첫 발행·10,000회 반복 발행을 측정한다. | 준비·등록·Debug를 제외한 고정 구독의 .NET 발행 할당은 0 B이다. |
| KR8 | Where 조건·When 비교·Debug 로그·TakeWhile/SkipWhile 조건을 실패시키고 등록 비교도 실패시킨다. | Where는 해당 행만, When은 노드 전체를, Debug는 해당 연결을 해제한다. 상태 조건은 스트림을 폐기한다. When 폐기에서는 중첩 사전을 먼저 비워 실패 비교를 반복하지 않는다. 등록 실패의 새 빈 행·노드는 정리하며 대기 중 관계의 첫 등록 실패도 폐기한다. |
| KR9 | 불일치 키와 여러 종류를 섞고 완료·오류·폐기를 전달한다. | 조건과 관계없이 모든 행을 종료 대상으로 삼는다. 완료·오류는 통지하고 폐기는 무통지이며 미처리 통지 실패는 뒤 통지를 중단하고 정리한다. |

## ForFlags 경로 계약

ForFlags는 `ulong` 값에 enum 마스크의 비트가 하나라도 겹치면 하위를 방문하는 경로 연산이다. 아래 사례는 노드 수와 수신 이력을 함께 확인한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| B1 | 한 비트·여러 비트·0인 값을 단일·복합 마스크에 발행한다. int 부호 비트와 ulong 최상위 비트도 구분한다. | HasAny 판정으로 원래 값을 전달하고, 0인 값은 전달하지 않는다. int 부호 비트가 상위 32비트로 확장되지 않는다. |
| B2 | 스트림 또는 기존 경로에서 0 마스크나 Flags 특성이 없는 enum으로 ForFlags를 호출한다. | 구독 전 경로 구성 시점에 ArgumentException이 발생하고 그래프 노드는 생기지 않는다. |
| B3 | 같은 부모에서 같은·다른 마스크를 등록하고, enum 형식·부모·순서 그룹을 바꾼다. | 같은 부모와 같은 비트만 항목을 공유하며 enum 형식은 구분하지 않는다. FlagsNode만 노드 수에 포함하고 행은 세지 않으며 그룹 사이에서는 공유하지 않는다. |
| B4 | 마스크·Where·같은 위치의 구독자를 순서를 달리해 등록한다. 항목을 해제한 뒤 다시 등록한다. | 일치하는 항목·형제·구독에 전달하며 등록·생성 순서에 따른 우선순위는 보장하지 않는다. |
| B5 | 발행 중 FlagsNode·항목·구독을 추가하거나 현재·다음 항목과 같은 항목의 뒤 구독을 해제한다. | 추가·삭제는 소유한 루트·Order 경계에서 반영한다. 같은 단위의 삭제 대상도 현재 값은 받으며 새 구독은 다음 발행부터 받는다. |
| B6 | 마지막 구독을 해제하거나 완료·오류·폐기로 끝낸다. | 빈 항목과 FlagsNode를 정리한다. 기본 스트림은 재사용할 수 있고 관계 스트림은 빈 루트에서 상위 연결까지 해제한다. 종료는 마스크와 관계없이 모든 하위에 전달하며 폐기는 통지하지 않는다. |
| B7 | ForFlags 앞뒤에 Where·Debug·ForOrder·Take·Skip·Branch를 조합하고 256단계 경로를 만든다. | 각 연산 위치에 도달한 값만 처리하고 기존 순서·수명 규칙을 유지한다. ForFlags는 위치마다 FlagsNode 하나와 마스크 행을 만들며 경로 깊이는 한 단계이고 257단계 구성은 거부한다. |

## ForFlags 공유와 수명 상태 전이

Source의 Shape 마스크 경로에서 Branch를 만들고, Branch 아래 Update·Render 순서 그룹을 둔다. Update에는 같은 비트인 서로 다른 enum 마스크로 두 명을 등록하고, Render에는 Shape와 입력에 맞지 않는 최상위 비트 마스크를 등록한다. 비활성 상태와 재활성 상태 각각에서 완료·오류·폐기·전체 해제를 조합해 여덟 종료 이력을 확인한다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 공유 마스크와 서로 다른 순서 그룹을 등록하고 값을 발행한다. | Update의 두 구독은 항목을 공유하고, Render의 같은 비트 항목은 분리된다. Branch.NodeCount는 3, Source.NodeCount는 2이며 명시적인 순서 그룹의 방문 순서를 지킨다. |
| 공통 | Update의 첫 구독을 해제한다. | 남은 공유 구독과 다른 그룹은 유지되며 노드 수는 줄지 않는다. 해제한 구독은 이후 값과 종료 통지를 받지 않는다. |
| 공통 | Branch를 비활성화하고 상위 입력과 직접 입력을 보낸다. | 두 입력 모두 수신 이력과 노드 수를 유지하고 완료·오류·폐기는 계속 받을 수 있다. |
| UF1–UF4 | 비활성 상태에서 완료·오류·폐기·전체 해제 중 하나를 수행한다. | 완료·오류는 값이 맞지 않았던 최상위 비트의 구독까지 전달한다. 폐기·전체 해제는 통지하지 않는다. 모든 경로와 핸들을 정리한다. |
| UF5–UF8 | 재활성화하고 값을 발행한 뒤 완료·오류·폐기·전체 해제 중 하나를 수행한다. | 남아 있는 Shape 구독이 다시 값을 받고, 네 종료 방식은 비활성 때와 같은 통지·정리 규칙을 따른다. |
| 전체 해제 | Update의 마지막 구독과 Render의 Shape 구독을 차례로 해제한다. | Branch.NodeCount가 3에서 2로 줄고 같은 FlagsNode의 행만 제거할 때는 2를 유지하며, 값에 맞지 않았던 최상위 비트 구독만 남아도 Branch와 상위 연결은 살아 있다. |
| 전체 해제 | 마지막 구독을 해제한 뒤 Source에 다시 구독하고 발행한다. | Branch는 폐기되고 Source의 빈 마스크 항목·FlagsNode·연결도 정리된다. Source는 살아 있어 새 ForFlags 경로 한 노드로 일치하는 값만 전달하며, 재구독 해제 후 다시 빈 그래프가 된다. |

## ForFlags 발행 중 변경 상태 전이

Shape=1, Location=2, Both=3인 세 마스크 항목을 등록하고 7을 발행한다. 같은 값이 세 항목을 모두 통과하는 상태에서 현재 Shape 콜백이 구독을 변경한다. 변경 직후와 다음 발행의 수신 집합을 따로 확인하며, 각 변경 경로를 전체 해제와 완료의 두 방식으로 끝낸다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 세 마스크 경로를 등록하고 7을 발행한다. | Shape·Location·Both가 모두 받는다. FlagsNode 하나에 행 세 개를 두며 NodeCount는 1이다. |
| UFM1–UFM2 | 현재 Shape 콜백에서 기존 Location 항목에 늦은 구독과 새 Payload=4 항목을 추가한다. | 현재 발행은 기존 세 구독만 받는다. 종료 후 NodeCount는 1이며 다음 발행에는 새 구독도 참여한다. |
| UFM3–UFM4 | 현재 Shape 콜백에서 뒤의 Location 항목을 제거하고 같은 마스크로 다시 등록한다. | 기존 Location은 현재 값까지 받고 새 Location은 다음 값부터 받는다. 반영 후 NodeCount는 1이다. |
| UFM5–UFM6 | 현재 Shape 콜백에서 현재 항목과 뒤의 Location 항목을 제거한다. | 현재 발행은 세 구독 모두 받고 다음 발행부터 Both만 받는다. 반영 후 NodeCount는 1이다. |
| UFM1–UFM6 | 변경 후 다음 값을 발행한 뒤 모든 구독을 해제하거나 스트림을 완료한다. | 전체 해제는 통지 없이 빈 그래프를 남기고 스트림은 살아 있다. 완료는 남은 구독에 한 번씩 통지한 뒤 그래프와 핸들을 정리한다. |

## When 경로 계약

When은 `EqualityComparer<T>.Default`로 target과 같은 값만 전달하는 경로 연산이다. null target도 유효하며, 같은 부모의 같은 target은 하나의 항목을 공유한다. 등록한 target의 Equals·GetHashCode 결과를 바꾸는 사용은 지원하지 않는다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| W1 | 값 형식·enum·string·참조 형식의 일치·불일치 값을 발행한다. | 기본 비교자의 값 동등성을 사용하며 원래 입력과 참조를 보존한다. 참조 동등성만 제공하는 형식은 같은 인스턴스만 통과한다. |
| W2 | 참조 형식과 Nullable 값의 null target·null 입력을 조합한다. | null끼리만 같고 null과 다른 값은 다르다. null 항목끼리 공유하며 비 null 항목과 분리된다. |
| W3 | 같은·다른 target을 같은 부모·다른 부모·순서 그룹에 등록한다. 64개 target 중 하나와 일치하는 값을 발행한다. | 같은 부모의 같은 target만 공유한다. WhenNode만 세고 행은 세지 않으며 일치 항목 하나만 비교·방문한다. |
| W4 | When·Where·ForFlags·순서 그룹·연결·Gate를 순서를 달리하여 등록한다. 항목을 해제하고 다시 만든 뒤 완료한다. | 일치하는 일반 경로와 구독의 수신 집합을 확인하며 등록·생성 순서에 따른 우선순위는 요구하지 않는다. 명시적인 Order 값 사이의 순서는 유지한다. |
| W5 | 발행 중 컨테이너·항목·구독을 추가하거나 현재·뒤 구독을 제거하고 같은 target을 재등록한다. | 루트·Order 경계에서 등록·삭제를 반영한다. 같은 단위의 기존 구독은 현재 값까지 받고 새 구독은 다음 발행부터 받는다. null 행에도 같은 규칙을 적용한다. |
| W6 | 공유 구독과 마지막 항목을 해제하고 재등록한다. 완료·오류·폐기를 적용한다. | 사전·null 항목과 빈 WhenNode를 정리한다. 관계 스트림은 상위 연결까지 해제하고 기본 스트림은 재사용한다. 종료는 불일치·null target과 Branch까지 전달하며 폐기는 무통지이다. |
| W7 | Where·Debug·ForOrder·Skip·Take·Branch·ForFlags와 조합하고 256·257단계를 구성한다. | 각 위치에 도달한 값만 처리한다. When은 깊이 한 단계이고 위치마다 WhenNode 하나와 target 행을 둔다. ulong의 When은 전체 값 동등성, ForFlags는 공통 비트로 따로 판정한다. |
| W8 | 발행 중 GetHashCode·Equals가 실패하고 보고기를 두거나 생략한다. | 같은 위치의 모든 기존 target·연결을 통지 없이 정리하고 보고한다. 처리된 실패만 형제 전파를 계속한다. 실패 전에 대기한 새 등록은 정리할 색인과 분리하여 다음 값부터 전달한다. |
| W9 | 등록 중 GetHashCode·Equals가 실패한다. 새 Where·순서 그룹·When 조상 뒤의 실패도 만든다. | 전파 밖의 비교 실패는 Subscribe 호출자에게 전파하고, 대기한 등록은 반영 경계에서 요청한 구독에 귀속하여 보고한다. 실패한 등록의 빈 노드는 정리하고 기존 구독·형제는 유지한다. |

## When 공유와 수명 상태 전이

Source의 When("one") 경로에서 Branch를 만들고 Update·Render 순서 그룹에 별도로 생성한 동등한 문자열 target을 등록한다. Render에는 값이 도달하지 않는 null target도 둔다. 비활성과 재활성 상태마다 네 종료 방식을 직접 검증한다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |
| 공통 | 같은 target의 구독과 다른 순서 그룹을 등록하고 null·불일치·일치 값을 발행한다. | Update의 두 구독은 공유하고 Render의 동일 target은 분리된다. Branch.NodeCount는 3, Source.NodeCount는 2이다. 일치하는 값만 순서 그룹 순으로 받는다. |
| 공통 | 첫 공유 구독을 해제하고 Branch를 비활성화한 뒤 상위·직접 입력을 보낸다. | 남은 공유 구독과 노드 수를 유지하며 비활성 값은 수신 이력을 바꾸지 않는다. |
| UW1–UW4 | 비활성 상태에서 완료·오류·폐기·전체 해제 중 하나로 끝낸다. | 완료·오류는 null target까지 통지하고 폐기·전체 해제는 통지하지 않는다. 모든 경로와 핸들을 정리한다. |
| UW5–UW8 | 재활성화와 일치 값 발행 후 네 종료 방식 중 하나로 끝낸다. | 남은 구독이 다시 값을 받고 비활성 종료와 같은 수명·통지 규칙을 유지한다. |

## Branch 수명 상태 전이

부모의 루트에서 Branch를 만들고 Branch의 짝수 조건에 두 명을 등록한다. U1과 U2는 Branch를 비활성화하는 단계까지 같은 이력을 갖는다.

| 경로 | 동작 | 관찰할 상태 |
| --- | --- | --- |

| US2 | Skip의 구독을 하나씩 해제한다. | 마지막 해제 때만 폐기하고 상위 연결을 정리한다. 완료 통지는 없다. |
| US3 | TakeWhile에 상위 값 4를 보낸다. | 4는 전달하지 않고 두 구독을 완료하며 조건 평가는 누적 4회이다. |
| US4 | SkipWhile에 상위 값 1을 보내고 구독을 하나씩 해제한다. | 조건을 다시 검사하지 않고 두 구독자에게 1을 전달한다. 조건 평가는 누적 3회이며 마지막 해제로 정리된다. |
| US5–US6 | 재활성화와 늦은 구독 뒤 TakeWhile·SkipWhile의 조건을 실패시킨다. | 스트림은 통지 없이 정리되고 상위의 형제 구독은 현재 값과 다음 값을 받는다. |

## 병렬 오더

| 상태·동작 | 기대 계약 |
| --- | --- |
| 같은 오더에 병렬 구독 둘 | 작업 스레드에서 동시에 진행할 수 있고 OnNext는 둘 다 끝날 때까지 반환하지 않는다. |
| 동기·병렬 오더 혼용 | 순서 값을 먼저 비교하고 같은 값에서는 병렬 구독을 마친 뒤 동기 구독을 호출한다. |
| 중첩 그룹·Branch·Merge·직접 스트림 관찰자 | 앞 구간을 모두 마친 뒤 발행 스레드에서 차례로 전파한다. 자식의 실행 방식은 독립적이다. |
| 조건 공유·조건 실패 | 조건은 발행 스레드에서 구간의 콜백보다 먼저 평가한다. 실패한 경로를 정리하며, 보고가 정상 반환할 때만 다른 구독을 계속 실행한다. |
| 병렬 콜백의 추가·해제·종료 | 동기 콜백과 같은 루트·Order 경계에서 반영한다. 새 구독은 소유 스트림의 다음 발행부터 참여한다. |
| 대기 구독의 등록 전·후 해제 | 등록 전 취소는 연결을 만들지 않고, 등록 후 해제는 연결된 구독을 해제한다. |
| 콜백·변경 요청·보고 실패 | 시작한 작업을 모두 마친 뒤 발행 스레드에서 보고한다. 보고가 재전파되면 새 호출을 중단하고 큐 정리 후 첫 미처리 예외를 반환한다. |
| 콜백 내부 직접 발행 | 다른 스트림은 자체 전파를 동기로 마친다. 동시 접근은 호출자 책임이며 같은 스트림 재진입은 거부한다. |

## 루트·Order 경계

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| Q1 | 동기·병렬 콜백이 같은 Order와 뒤 Order의 구독을 삭제한다. | 같은 Order의 Async·Sync는 모두 완료하고 뒤 Order의 삭제 대상은 호출하지 않는다. |
| Q2 | 중첩 Order·연결 스트림·다른 타입의 직접 발행에서 상위 구독을 삭제한다. | 작업 대기 지점에서는 반영하지 않고 소유한 활성 상위 단위의 종료까지 미룬다. |
| Q3 | 앞 Order에서 등록·취소하거나 루트에서 Order 구독을 삭제한다. | 새 구독은 다음 발행부터 참여하고 취소된 대기 Handle은 연결하지 않는다. 루트 요청은 루트 종료 때 반영한다. |
| Q4 | 현재 Order에서 루트 폐기를 요청한다. | 현재 가장 안쪽 Order의 Async·Sync는 마치고 후속 전파를 중단한다. 요청 후 새 발행·구독은 즉시 거부한다. |
| Q5 | 변경을 요청한 콜백·조건의 실패가 재전파된다. | 미실행 호출을 중단하고 시작한 작업·큐 정리를 마친다. 이미 보고한 연결 스트림의 실패는 중복 보고하지 않는다. |
| Q6 | 활성 루트의 Enabled를 변경한다. | 루트 종료 전에는 기존 상태로 전파하고 종료 후 다음 발행부터 새 상태를 적용한다. |

행 기반 경로와 병렬 Order의 통합은 When의 null·일치·불일치 행, 같은 숫자의 Async → Sync 대기, When을 거친 상위 Order의 변경 지연을 추가로 검증한다. 비교 실패 전에 대기한 새 When 등록은 기존 색인 정리로 사라지지 않아야 한다.

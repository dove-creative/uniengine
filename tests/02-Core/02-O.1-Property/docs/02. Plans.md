## 목차

- 실행 구성
- 직접 검증

## 실행 구성

기존 tests/UniEngine.Tests.csproj에서 .NET 10·C# 9·NUnit 3과 UniTest 0.4.1로 실행한다. 제품 프로젝트는 .NET Standard 2.1이며 테스트 실행 시 ProjectReference를 통해 함께 빌드한다.

| 테스트 파일 | 상태·동작 표 | 검증 방식 |
| --- | --- | --- |
| [PropertyTests](../PropertyTests.cs) | P1–P9 | 공개 API와 표준 인터페이스의 정상·실패·경계값 및 도메인 소비 시나리오를 직접 실행한다. |
| [PropertyStateProjectTests](../UniTest/PropertyStateProjectTests.cs) | U1 | 모든 후보를 포함한 고정 경로와 seed별 연속 경로를 실행한다. |

## 직접 검증

[상태·동작 표](01.%20Tables.md)의 각 항목을 랜덤 선택과 무관하게 실행한다. 특히 중복 추가, 형식이 맞지 않는 GetAndRemove, null 키, 잘못된 CopyTo 이후의 상태 보존을 확인한다. IPropertySubject 소비 시나리오는 서로 다른 기능 키 두 개를 등록한 뒤 실패한 회수·정상 회수·전체 정리·소비자의 명시적 Dispose를 검증한다.

UniTest 고정 경로의 목표 깊이는 생성 단계를 포함한 24이다. 빈 상태의 조회·실패·정리, 정수 및 null 등록, 중복·형식·쌍 불일치, 교체, 순차 회수·제거와 정리 후 재등록을 모든 후보가 한 번 이상 실행되도록 배치한다.

## 랜덤 연속 실행

독립된 새 프로젝트와 빈 저장소에서 seed 0·1·2를 각각 실행한다. 목표 깊이는 생성 단계를 포함해 각 100이다. 이전 단계의 변경을 누적하며 동일한 후보와 불변 조건을 사용한다. UniTest가 후보를 검증할 때 앞선 경로를 재실행하므로 상태의 재현성도 함께 확인한다.

별도 자동 취소 제한은 두지 않는다. 세 seed의 실제 실행시간 합계가 60초를 넘으면 [테스트 안내](../../../README.md)의 중간 확인 절차를 따른다. seed·도달 깊이·실행시간·결과 및 부모 노드 ID를 포함한 실행 이력을 TRX 출력에 남긴다.

## 실행 명령과 판정

저장소 루트에서 실행한다.

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release --filter 'FullyQualifiedName~BlackThunder.UniEngine.Tests.Property' --results-directory tests/bin/TestResults/Property --logger 'trx;LogFileName=Property.trx'
```

대상 사례 전체 통과, 실패·건너뜀 0개, 고정 경로 깊이 24 및 각 seed 깊이 100 도달을 성공 기준으로 삼는다. 실행 결과는 [Property 검증 결과](03.%20Results.md)에 기록한다. 이번 변경은 Property 테스트 추가이므로 해당 모듈 범위를 실행하며 다른 모듈 전체 테스트와 성능·동시성 검증은 포함하지 않는다.

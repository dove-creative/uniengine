# Property 상태와 동작

## 목차

- 범위
- 상태와 동작
- 연속 실행 불변 조건

## 범위

외부 페이로드 저장소 Property의 값·형식·실패 계약과 IPropertySubject를 통한 소비 흐름을 검증한다. 기준은 [Property 설계](../../../../docs/02.%20UniEngine/02-Core/02-O.1-Property/Property.md)와 [IPropertySubject 설계](../../../../docs/02.%20UniEngine/02-Core/02-O.1-Property/IPropertySubject.md)이다.

## 상태와 동작

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| P1 | 빈 저장소·초기 값·null 저장소의 상태 조회 | Count·HasValue·bool 변환이 일치하며 null 저장소의 bool 변환은 false이다. null 값도 저장된 항목으로 센다. |
| P2 | Add·자기 키 등록·중복·동등 키·인덱서 교체 | Add는 원래 값을 반환하고 중복을 거부한다. 동등 키는 같은 항목을 가리키고, 인덱서 교체는 항목 수를 늘리지 않는다. |
| P3 | 값·참조·상위 형식·nullable 형식으로 조회 | 할당 가능한 형식의 값과 참조를 유지한다. 숫자 변환이나 문자열 변환을 자동 수행하지 않는다. |
| P4 | 없는 키·잘못된 형식·null 값·null 키 | 없는 키의 TryGet은 false와 기본값이며 Get은 KeyNotFoundException이다. 형식 불일치는 InvalidCastException, null 키는 ArgumentNullException이다. 실패 시 기존 항목을 보존한다. |
| P5 | GetAndRemove·Remove·Clear·교체 후 재등록 | 지정한 값만 회수·제거하며 실패한 회수는 값을 보존한다. 저장 값의 Dispose는 호출하지 않는다. 비운 저장소는 재사용할 수 있다. |
| P6 | IDictionary·ICollection의 등록·조회·삭제·뷰 | 모든 경로가 같은 저장소를 사용한다. 키·값 뷰가 변경을 반영하며, 쌍의 Contains·Remove는 키와 값이 모두 일치해야 한다. |
| P7 | 빈/비어 있지 않은 저장소의 순회·CopyTo·잘못된 복사 인자 | 모든 쌍을 한 번씩 제공한다. 순서는 계약으로 고정하지 않는다. 복사 범위 밖 원소와 실패한 복사의 대상 배열을 보존한다. |
| P8 | 빈 저장소·null 값이 있는 저장소의 표시 | 빈 상태와 항목 수·키·null 값을 표시한다. |
| P9 | 도메인 계약을 통한 독립 기능의 등록·회수 실패·회수·정리 | 한 기능의 회수 실패나 성공이 다른 키의 값을 바꾸지 않는다. 페이로드 폐기 책임은 소비자에게 남는다. |
| U1 | 생성·등록·교체·조회·실패·제거·정리의 누적 실행 | 모든 단계에서 기대 목록과 실제 저장소가 일치한다. 고정 경로가 모든 동작 후보를 직접 실행하고 같은 후보를 랜덤 연속 실행에 사용한다. |

## 연속 실행 불변 조건

| 상태 | 사용 가능한 동작 후보 |
| --- | --- |
| 생성 전 | Create |
| 빈 저장소 | AddValue·AddNull·Observe·Missing·NullKey·Clear |
| 항목이 있는 저장소 | 빈 저장소의 후보와 Replace·Duplicate·Mismatch·PairMismatch·Consume·Remove |

기대 상태는 별도 키·값 목록으로 관리한다. 단계마다 Count·HasValue·bool, 전체 순회, 키·값 뷰, CopyTo와 각 항목의 형식 지정 조회를 비교한다. 실패 동작은 기대 목록을 변경하지 않으며, 그 직후 같은 비교로 원래 값이 보존되었는지 확인한다.

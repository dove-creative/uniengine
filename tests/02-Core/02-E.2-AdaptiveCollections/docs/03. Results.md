# Adaptive Collections 검증 결과

## 랜덤 연속 테스트 검증

2026-11-10에 .NET SDK 10.0.403 Release에서 지연·즉시 반영 모드의 랜덤 연속 테스트를 모듈 필터로 실행했다. 모든 seed가 계획 깊이 100에 도달했으며 6개 통과, 실패·건너뜀 0개이다.

| 반영 모드 | seed 0 | seed 1 | seed 2 |
| --- | ---: | ---: | ---: |
| 즉시 | 175.966 ms | 134.983 ms | 194.911 ms |
| 지연 | 268.409 ms | 199.614 ms | 177.238 ms |

각 동작의 방문 순서와 순회 후 목록·개수를 기대 목록과 대조했다. 시간은 빌드와 복원을 제외한 UniTest 실행 기준이다. seed별 동작과 결과는 [Adaptive Collections 랜덤 실행 TRX](../../../obj/RandomContinuous/adaptive-collections.trx)의 NUnit 출력에 기록했다. 각 행의 부모 노드 ID를 따라 해당 후보까지의 실행 경로를 확인할 수 있다.

## 2026-11-15 사전·집합 상태 모델 검증

Windows·.NET SDK 10.0.404·Release에서 [계획](02.%20Plans.md)의 U2·U3·D2를 실행했다. 사전·집합 고정 경로 4개, 랜덤 연속 경로 12개, 삭제한 키의 조회 회귀 사례 4개가 모두 통과했다. 실패·건너뜀은 0개이다. 각 고정 경로는 생성 포함 깊이 17에서 끝나며 모든 Lab을 직접 거친다.

| 대상 | 모드 | seed 0 | seed 1 | seed 2 | 실제 깊이 / 목표 깊이 |
| --- | --- | ---: | ---: | ---: | --- |
| Dictionary | 즉시 | 9,655.028 ms | 6,464.282 ms | 11,328.128 ms | 각각 100 / 100 |
| Dictionary | 지연 | 4,538.386 ms | 5,649.799 ms | 6,407.742 ms | 각각 100 / 100 |
| HashSet | 즉시 | 3,778.586 ms | 3,347.557 ms | 3,753.647 ms | 각각 100 / 100 |
| HashSet | 지연 | 3,406.290 ms | 3,472.543 ms | 2,631.216 ms | 각각 100 / 100 |

각 대상·모드의 세 seed 실행시간 합계는 60초 이내이다. 시간은 공통 실행기의 ExecuteContinuously 측정값이다. 초기 상태에서 이전 동작의 결과를 누적하며 논리 조회, 방문 항목과 횟수, 종료 후 전체 순회·CopyTo와 사전 Keys·Values를 대조했다. 본문 예외는 원래 예외 참조가 전파되고 다음 순회가 가능한지 확인했다.

### 발견한 결함과 재검증

최초 테스트 본문 실행에서 Dictionary의 8개 사례가 실패했다. 순회 중 기존 키를 삭제하거나 대기 교체를 취소하면 TryGetValue가 false를 반환하면서 out 값에는 물리 저장소의 이전 값을 남겼다. 예를 들어 값 20인 키를 삭제한 직후 false와 20을 함께 반환했다. HashSet의 8개 사례는 통과했다.

TryGetValue의 조회 실패 경로에서 out 값을 default(TValue)로 확정하도록 수정했다. 새 상태 모델의 값 형식 검증에 더해 두 모드·교체 취소 여부의 4개 직접 사례에서 참조 형식의 null 반환과 남은 키 보존을 확인했다. 수정 후 이 모듈의 추가 검증 20개가 모두 통과했다. 최초 실패를 통과 결과와 구분하여 보관한다.

- [최종 선택 실행 TRX](../../../obj/StateModels/20261115/focused-final.trx) · [실행 로그](../../../obj/StateModels/20261115/focused-final.log)

TRX는 LifecycleHub와 함께 실행한 24개 사례의 원본이며 위 20개는 그 부분집합이다. 후보별 노드 ID·부모 ID·깊이·상태·Lab ID는 각 사례의 StdOut에 있다. 비교자 실패·null·커서 복사·인터페이스·할당은 기존 NUnit 사례가 담당한다. Unity 실행과 별도 벤치마크는 이번 검증에 포함하지 않았다.

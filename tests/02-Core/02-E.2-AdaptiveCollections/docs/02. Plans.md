## 실행 구성

테스트는 단일 프로젝트 `tests/UniEngine.Tests.csproj`에서 소유하고, 본체를 ProjectReference로 연결한다. 코드는 `tests/02-Core` 아래에서 `src/02-Core`의 모듈 폴더에 대응하도록 배치한다. 로컬 UniTest 0.4.1과 NUnit 3 실행기를 사용하며 .NET 10 SDK로 실행한다. NUnit의 개별 사례를 주 검증으로 사용하고 UniTest 프로젝트로 상태 전이 재실행도 확인한다.

| 테스트 파일 | 표의 범위 | 구현 방향 |
| --- | --- | --- |
| [AdaptiveCollectionTests](../AdaptiveCollectionTests.cs) | C1–C8 | 두 반영 모드, 변경 중 관찰값, 종료 경로, 복사본 수명을 검증한다. |
| [EnumerationAllocationTests](../EnumerationAllocationTests.cs) | A1 | 빈 목록·비어 있지 않은 목록의 직접 foreach를 워밍업하고 동기 구간의 할당량을 측정한다. |
| [AdaptiveActionTests](../AdaptiveActionTests.cs) | R1 | 실제 AdaptiveAction 공개 API를 통해 순회 소비자의 회귀 동작을 검증한다. |
| [AdaptiveDictionaryTests](../AdaptiveDictionaryTests.cs) | D1·B1·A2 | 교체·삭제·후속 묶음·수명과 직접 순회, 제거 기록 이후 순회 및 반복 변경 할당을 검증한다. |
| [AdaptiveHashSetTests](../AdaptiveHashSetTests.cs) | H1·B1·A2 | 유일성·재추가·후속 묶음·수명·정리 실패와 제거 기록 이후 순회 및 반복 할당을 검증한다. |

## 랜덤 연속 실행

지연·즉시 반영 모드 각각에 대해 고정 seed `0`, `1`, `2`로 실행한다. 실행마다 새 UniTest Inline 프로젝트와 두 항목이 있는 목록으로 시작한다. 다음 순회는 이전 동작의 결과를 이어받으며, 실제 방문 값과 순회 후 논리 목록을 별도 기대 목록과 비교한다. 다음 항목 삭제 후보는 목록에 두 항목 이상 있을 때 사용한다.

목표 깊이는 seed마다 100이다. 별도 자동 취소 시간은 두지 않으며, 각 반영 모드의 세 실행에 걸린 시간이 60초를 넘으면 [테스트 안내](../../../README.md)의 실행 중 확인 절차를 따른다.

## 검증 기준

- 공개 API 변경이므로 추가한 테스트 전체를 Release로 실행한다.
- 전역 ExceptionHandler를 사용하는 사례는 병렬 실행하지 않고 각 사례 뒤 초기화한다.
- 할당 측정 구간에는 컬렉션 생성, 테스트 단언, 출력, 대리자 생성이 들어가지 않는다.
- 인터페이스 경로는 기능을 확인한다. JIT의 박싱 제거 여부에 좌우되는 양수 할당량 단언은 하지 않는다.
- 본체가 C# 9·.NET Standard 2.1을 대상으로 하므로, 목록·사전·집합·호출 목록 캐시의 호환성은 본체 Release 빌드로 함께 확인한다.

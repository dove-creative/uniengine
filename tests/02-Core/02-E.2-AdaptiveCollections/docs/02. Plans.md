## 실행 구성

## 랜덤 연속 실행

지연·즉시 반영 모드 각각에 대해 고정 seed `0`, `1`, `2`로 실행한다. 실행마다 새 UniTest Inline 프로젝트와 두 항목이 있는 목록으로 시작한다. 다음 순회는 이전 동작의 결과를 이어받으며, 실제 방문 값과 순회 후 논리 목록을 별도 기대 목록과 비교한다. 다음 항목 삭제 후보는 목록에 두 항목 이상 있을 때 사용한다.

목표 깊이는 seed마다 100이다. 별도 자동 취소 시간은 두지 않으며, 각 반영 모드의 세 실행에 걸린 시간이 60초를 넘으면 [테스트 안내](../../../README.md)의 실행 중 확인 절차를 따른다.

사전·집합도 각 반영 모드에서 seed 0·1·2, 깊이 100으로 실행한다. 각 객체의 고정 경로 2개와 랜덤 경로 6개, 합계 16개를 추가 검증한다. 고정 경로는 생성 Lab을 포함하여 각각 깊이 17이며 모든 동작을 랜덤 선택과 무관하게 실행한다.

- 기대 상태는 표준 Dictionary·HashSet에 공개 변경 요청을 반영하여 유지한다. 대상의 열거 결과로 기대 상태를 채우지 않는다.
- 변경 직후 순회 안에서 Count·Contains 또는 ContainsKey·TryGetValue·인덱서를 대조한다. 각 Lab 뒤에는 전체 순회와 CopyTo를 확인하고, 사전은 Keys·Values도 확인한다.
- 방문 결과는 변경 전 기대 상태와 해당 동작의 방문 계약으로 계산한다. 실제 첫 방문 항목은 순서가 보장되지 않는 순회에서 현재·미방문 대상을 구별하는 데만 사용한다.
- 즉시 모드의 후속 묶음에서 다시 추가하는 동작, 교체 취소와 조기 종료 뒤 다음 순회까지 확인한다. 본문 예외는 원래 예외 참조까지 확인한다.
- 기존 NUnit 사례가 담당하는 null·비교자 실패·오래된 커서·인터페이스·할당 계약을 이 상태 모델에서 중복 구현하지 않는다.

## 실행과 기록

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --filter 'FullyQualifiedName~DictionaryStateProjectTests|FullyQualifiedName~HashSetStateProjectTests'
```

LifecycleHub와 함께 보강하고 조회 실패 동작도 수정하므로 전체 일반 테스트도 실행한다. 벤치마크·Extended 범위는 제외한다. 원본 로그와 TRX는 `tests/obj/StateModels/20261115`에 두고 [결과](03.%20Results.md)에서 연결한다.

## 검증 기준

- 추가한 고정·랜덤 경로와 직접 회귀 사례를 Release로 실행한 뒤 전체 일반 테스트를 실행한다.
- 전역 ExceptionHandler를 사용하는 사례는 병렬 실행하지 않고 각 사례 뒤 초기화한다.
- 할당 측정 구간에는 컬렉션 생성, 테스트 단언, 출력, 대리자 생성이 들어가지 않는다.
- 인터페이스 경로는 기능을 확인한다. JIT의 박싱 제거 여부에 좌우되는 양수 할당량 단언은 하지 않는다.
- 본체가 C# 9·.NET Standard 2.1을 대상으로 하므로, 목록·사전·집합·호출 목록 캐시의 호환성은 본체 Release 빌드로 함께 확인한다.

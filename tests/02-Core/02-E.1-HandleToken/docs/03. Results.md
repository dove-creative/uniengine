# Handle·Token 검증 결과

## 실행 결과

2026-11-15, Windows·.NET SDK 10.0.404·Release에서 [계획](02.%20Plans.md)에 따라 선택 실행했다. 본체 netstandard2.1과 테스트 net10.0 빌드는 경고·오류 없이 통과했다.

| 범위 | 통과 / 실행 | 결과 |
| --- | ---: | --- |
| Handle NUnit 직접 사례 | 15 / 15 | 실행 유예·순서·중복·재진입·예외 정책·GC 참조 해제·파생 가드가 통과했다. 예외 정책과 GC 검증에는 Token도 포함한다. |
| Token NUnit 직접 사례 | 8 / 8 | 생성·등록·마지막 일치 제거·null·폐기 중 변경 차단·제거한 대상 수거가 통과했다. |
| 소비 사례 | 3 / 3 | EventStream 구독 해제와 두 EventHub의 공유 Token 수면 해제, 처리되는 onAwake 실패가 통과했다. |
| UniTest 고정 경로 | 2 / 2 | Handle은 깊이 20, Token은 깊이 35까지 모든 대상 동작을 직접 실행했다. |
| UniTest 랜덤 연속 경로 | 6 / 6 | 대상별 seed 0·1·2가 모두 깊이 100에 도달했다. |
| 이번 선택 실행 전체 | 34 / 34 | 실패·건너뜀 0개이며 실행기 기준 약 3초이다. |

제품 결함은 발견되지 않았으며 Handle·Token 본체는 변경하지 않았다. 일반 사례는 값을 직접 단언하고, UniTest는 독립 기대 정수 목록과 실제 콜백 이력을 비교했다. 미처리 콜백 예외와 처리기 예외의 원래 참조를 확인했으며, 처리 정책에서는 같은 실패 콜백의 중복 등록도 각각 보고하고 이후 호출을 계속했다.

GC 사례는 폐기 후 살아 있는 Handle·Token 및 아직 폐기하지 않은 Token이 해제한 콜백·대상 객체를 보유하지 않는지 확인했다. 약한 참조는 NoInlining 보조 메서드에서 만들고 소유 객체는 GC.KeepAlive로 유지했다.

## 연속 실행 결과

| 대상 | seed 0 | seed 1 | seed 2 | 실제 깊이 / 목표 깊이 |
| --- | ---: | ---: | ---: | --- |
| Handle | 311.477 ms | 255.987 ms | 268.084 ms | 각각 100 / 100 |
| Token | 1,001.099 ms | 835.656 ms | 773.985 ms | 각각 100 / 100 |

시간은 공통 실행기의 ExecuteContinuously 측정값으로 빌드·복원·프로젝트 종료 정리 시간은 제외한다. 세 seed 합계는 Handle 835.548 ms, Token 2,610.740 ms이며 각각 60초 이내이다. 모든 실행은 완료됐고 취소·미도달 사례는 없다.

고정 경로와 랜덤 경로는 같은 Lab을 사용한다. 콜백 목록·설명·정책 선택·호출 이력을 여러 단계에 걸쳐 누적하고 폐기 뒤 새 인스턴스로 이어간다. 등록 목록을 대상에서 읽거나 실제 호출 이력으로 기대값을 만들지 않는다. 재실행용 미완료 인스턴스도 정리하며 전역 예외 정책은 테스트 전후와 임시 사용 뒤 복구한다.

## 실행 근거와 한계

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'FullyQualifiedName~HandleTests|FullyQualifiedName~TokenTests|FullyQualifiedName~HandleToken' --results-directory tests/obj/HandleToken/20261115 --logger 'trx;LogFileName=module.trx'
```

VSTest의 샌드박스 내 testhost 연결 실패가 앞선 작업에서 확인되어 테스트는 샌드박스 밖에서 실행했다. 이번 실행에서는 시작 실패나 테스트 실패가 없었다.

이번은 단일 모듈의 테스트 보강이므로 새 모듈·소비 사례만 실행했다. 전체 일반 테스트 1,302개 통과는 [직전 실행 기록](../../docs/State%20Model%20Results.md)이며 이번에 전체를 재실행한 결과가 아니다. Unity 실행·별도 벤치마크·스레드 간 동시 Dispose와 등록은 검증 범위에 포함하지 않았다.

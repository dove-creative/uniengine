# Handle·Token 상태와 동작

## 목차

- Handle 공통 계약
- Token 등록 계약
- 소비 사례와 연속 수명

## Handle 공통 계약

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| H1 | null 동작 또는 일반 동작으로 생성하고 설명을 설정한다. | 생성 시 실행하지 않으며 IsDisposed는 false이다. 설명은 저장되고 null 동작도 폐기할 수 있다. |
| H2 | 여러 동작과 중복 동작을 담아 폐기한다. | 먼저 IsDisposed를 true로 바꾸고 등록 순서·중복 횟수대로 동기 실행한다. |
| H3 | 반복 Dispose 또는 콜백 안에서 Dispose를 호출한다. | 첫 폐기의 호출 횟수·순서를 유지하며 다시 실행하지 않는다. |
| H4 | 콜백이 실패하고 기본 정책·처리 정책·실패하는 정책을 적용한다. | 기본 정책은 원래 예외를, 실패하는 정책은 정책 예외를 전파하고 이후 호출을 중단한다. 처리 정책은 각 실패를 보고하고 다음 콜백을 계속 실행한다. 모든 경로에서 폐기 상태를 유지한다. |
| H5 | 정상·실패 폐기 후 Handle 또는 Token을 계속 보관한다. | 콜백 대리자와 대상 객체를 붙잡지 않아 GC로 수거할 수 있다. |
| H6 | 파생 형식에서 ThrowIfDisposed를 호출한다. | 활성 상태에서는 통과하고 폐기 후 ObjectDisposedException을 발생시킨다. |

## Token 등록 계약

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| T1 | 인자 없는 생성자·null 생성자·초기 콜백으로 생성한 뒤 등록한다. | 빈 목록 또는 초기 콜백에 새 동작이 이어지며 생성·등록만으로 실행하지 않는다. |
| T2 | 중복 동작 중 하나 또는 멀티캐스트 묶음을 제거한다. | 마지막으로 일치하는 연속 호출 목록을 제거한다. 일치하는 연속 묶음이 없으면 유지한다. |
| T3 | null 추가·제거와 등록하지 않은 동작의 제거를 요청한다. | 활성 상태의 목록은 바뀌지 않는다. |
| T4 | 폐기 중·폐기 후 추가·제거·재폐기를 요청한다. | null을 포함한 추가는 거부한다. 제거·재폐기는 무시하고 폐기 시작 시 목록은 계속 실행한다. |
| T5 | 등록한 동작을 제거하고 Token을 계속 보관한다. | 제거한 대리자와 대상 객체는 수거할 수 있다. |

## 소비 사례와 연속 수명

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| I1 | EventStream이 반환한 Handle을 폐기한다. | 이후 값은 해당 구독에 전달되지 않으며 다른 구독은 유지된다. |
| I2 | 두 EventHub가 같은 Token으로 수면에 들어간 뒤 폐기한다. | 두 허브 모두 한 번 깨어나고 이후 갱신을 전달한다. 처리되는 onAwake 실패가 다른 허브의 복구를 막지 않는다. |
| U1 | Handle의 설명·예외 정책 선택·폐기·반복 폐기·새 인스턴스 생성을 누적한다. | 독립 기대 호출 목록과 실제 호출 이력·보고 횟수·예외 참조·폐기 상태가 일치한다. |
| U2 | Token의 중복·묶음 등록·단일·묶음 제거·null 동작을 누적한다. | 독립 정수 목록으로 계산한 등록 순서와 중복 수가 폐기 시 실제 이력과 일치한다. |
| U3 | 두 대상에서 정상·처리·미처리 실패·정책 실패·재진입 폐기를 거친다. | 중단·계속 계약을 유지하고 새 인스턴스의 수명이 이전 호출 이력에 이어져도 기대값이 맞는다. |

U1–U3는 고정 경로와 seed 0·1·2의 랜덤 경로에서 같은 Lab과 단언을 사용한다. GC·소비 사례는 직접 NUnit 검증이 담당한다. 스레드 간 동시 Dispose·등록은 보장 계약에 포함하지 않는다.

# Handle·Token 테스트 계획

## 목차

- 실행 구성
- 상태·동작 대응
- UniTest 모델
- 검증과 기록

## 실행 구성

기존 단일 `tests/UniEngine.Tests.csproj`에서 .NET 10·C# 9·NUnit 3·UniTest 0.4.2로 실행한다. 기준은 [상태·동작 표](01.%20Tables.md)이다. 전역 ExceptionHandler를 사용하는 모든 클래스는 NonParallelizable이며 사례 전후 기본 정책으로 복구한다.

## 상태·동작 대응

| 테스트 파일 | 범위 | 검증 방법 |
| --- | --- | --- |
| [HandleTests](../HandleTests.cs) | H1–H6 | 생성·실행 시점·순서·중복·재진입·예외 정책·참조 해제·파생 형식 가드를 직접 검증한다. 예외 정책과 참조 해제는 Token에도 적용한다. |
| [TokenTests](../TokenTests.cs) | T1–T5 | 생성 이후 등록, 마지막 단일·연속 묶음 제거, null·무효 해제, 폐기 시 등록 동결과 제거한 대상의 수거를 검증한다. |
| [HandleTokenIntegrationTests](../HandleTokenIntegrationTests.cs) | I1–I2 | EventStream의 반환 Handle과 두 EventHub가 공유하는 Sleep Token을 실제 소비 경로에서 검증한다. |
| [HandleTokenStateProjectTests](../UniTest/HandleTokenStateProjectTests.cs) | U1–U3 | 대상별 고정 경로 1개와 랜덤 연속 경로 3개를 실행한다. Token은 등록·제거 동작도 후보로 제공한다. |

GC 검증은 NoInlining 보조 메서드에서 콜백과 대상의 WeakReference를 만들고 등록 참조를 해제한다. 수거 뒤에도 Handle·Token 자체는 GC.KeepAlive로 유지한다. 객체 필드나 private 호출 목록을 직접 읽지 않는다.

## UniTest 모델

정수 ID 목록이 기대 콜백 순서를 나타낸다. 대상에는 별도의 대리자를 등록하며 실제 호출은 별도 목록에 기록한다. 단일·묶음 제거는 기대 정수 목록에서 마지막 일치 구간을 찾아 계산한다. 대상의 대리자 목록으로 기대 상태를 만들지 않는다.

- Handle과 Token 모두 초기 멀티캐스트에 중복·실패·재진입 콜백을 포함하고, 빈 생성과 새 인스턴스 수명도 확인한다.
- 처리·재전파·처리기 실패 정책을 모델 상태로 선택한다. Dispose Lab 안에서만 정책을 설치하고 finally에서 복구한다. 예상한 콜백 예외 외의 실패는 삼키지 않는다.
- 고정 경로는 등록된 모든 동작 종류와 세 예외 정책을 직접 실행한다. 랜덤 선택에 기본 계약 검증을 의존시키지 않는다.
- 생성 Lab을 포함한 고정 경로의 깊이는 Handle 20, Token 35이다. 일반 직접 사례 23개·소비 사례 3개·고정 경로 2개·랜덤 경로 6개로 총 34개를 실행한다.
- 대상별 seed 0·1·2, 목표 깊이 100으로 독립 실행한다. 이전 단계의 등록·설명·호출 이력을 누적하며 폐기 후 별도 인스턴스로 이어간다.
- 원래 Handle을 재활성화하지 않는다. 새 인스턴스를 만들기 전에 기존 인스턴스의 반복 폐기와 Token의 등록 거부를 확인한다.
- 프로젝트가 재실행을 위해 만든 미완료 인스턴스도 정리한다. 정리 과정의 예상 콜백 실패만 처리하고 정책을 복구한다.
- 세 seed의 실제 실행시간 합계가 60초를 넘으면 테스트 안내의 중간 확인 절차를 따른다. 자동 시간 제한은 두지 않는다.

## 검증과 기록

단일 모듈의 테스트 보강이므로 Release 빌드와 새 모듈 테스트·소비 사례를 선택 실행한다. 본체·공개 API·의존성 변경이 필요하면 검증 범위를 다시 판단한다. 직전 전체 일반 테스트 1,302개 통과 기록은 이번 선택 실행과 구분한다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'FullyQualifiedName~HandleTests|FullyQualifiedName~TokenTests|FullyQualifiedName~HandleToken'
```

VSTest의 샌드박스 내 testhost 연결 실패가 이미 확인되어 실행 가능한 샌드박스 밖에서 테스트한다. 결과는 [검증 결과](03.%20Results.md)에 기록한다. seed·도달 깊이·시간·후보 이력, LF·문서 링크와 기존 변경 보존을 확인한다.

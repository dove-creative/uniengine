## 실행 구성

[LifecycleHubTests](../LifecycleHubTests.cs)는 객체별 연결·폐기와 직접 OnDisposed 구독 정책을 검증하는 NUnit 테스트이다. 본체를 ProjectReference로 참조하며 테스트 프로젝트는 .NET 10·C# 9이다. 기준은 [상태·동작 표](01.%20Tables.md)이다.

## 상태·동작 대응

| 범위 | 테스트 | 검증 방법 |
| --- | --- | --- |
| C1 | ConnectAfterDisposeThrows | 완료 상태와 연결 거부 예외를 확인한다. |
| C2 | DisconnectedListenerIsNotNotifiedOnDispose | 해제 후 완료 알림 횟수가 0인지 확인한다. |
| C3 | DisconnectIgnoresUnknownAndNullListenersAndDisposedHubs | 무효 해제 요청 뒤 기존 연결의 통지와 폐기 후 무예외 처리를 확인한다. |
| C4 | DirectAndClientRegistrationsShareTheSameKey | 등록 순서를 바꾼 두 경우에서 키 충돌 거부와 기존 등록의 유지를 확인한다. |
| C5 | RegistrationsCanBeRemovedThroughEitherEntryPoint | 직접·client 등록을 반대 경로로 해제하고 알림 횟수가 0인지 확인한다. |
| L1 | DisposeNotifiesListenersOnceAndIgnoresRepeatedCalls | 폐기 전후 상태와 반복 폐기 시 알림 횟수를 비교한다. |
| L2 | DisposalFreezesBothRegistrationPathsBeforeNotifying | 두 경로에서 같은 콜백을 실행하며 완료 상태, 해제·재폐기 무시와 새 등록 거부를 확인한다. |
| D1 | DirectDisposalRejectsDuplicateRegistrationAndKeepsTheOriginal | 중복 대리자 등록 예외와 기존 콜백들의 1회 통지를 확인한다. |
| D2 | DirectDisposalMulticastRemovalRequiresTheWholeRegistration | 부분 대리자와 전체 대리자를 해제하는 두 경우의 호출 이력을 비교한다. |
| D3 | CallbackFailureSkipsItsMulticastTail | 등록 경로와 처리기 유무를 조합하여 멀티캐스트의 뒤 호출 생략, 처리기가 있을 때 다른 경로의 알림, 예외 참조와 최종 폐기 상태를 확인한다. |
| D4 | NullSubscriptionsAreIgnoredAndNullClientCallbacksAreAllowed | null 직접 구독·해제와 null client 콜백을 섞고 정상 콜백 통지 및 폐기 후 등록 거부를 확인한다. |
| A1 | DisposalTraversesRegisteredCallbacksWithoutAllocating | 별도 허브로 예열한 뒤 네 콜백의 실행과 GC.GetAllocatedBytesForCurrentThread의 차이를 확인한다. |

## UniTest 연속 수명

[LifecycleHubStateProjectTests](../UniTest/LifecycleHubStateProjectTests.cs)는 UniTest 0.4.2 Inline 프로젝트를 사용한다. 네 개의 대리자 식별자에 대해 직접 등록·별도 client 콜백·null 콜백·미등록 상태를 독립 등록표로 유지한다. 콜백별 실제 누적 호출 횟수와 기대 횟수, IsDisposed를 각 Lab 뒤 비교한다.

| 테스트 | 표의 범위 | 실행과 기대 결과 |
| --- | --- | --- |
| FixedRegistrationLifetimes | U1–U5 | 생성 포함 깊이 34의 고정 경로로 교차 중복·해제·재등록, 정상·처리·미처리 실패·재진입 폐기와 새 허브 수명을 반드시 실행한다. |
| RandomContinuousRegistrationLifetimes | U1–U5 | 독립 초기 상태에서 seed 0·1·2로 각각 깊이 100까지 같은 Lab 후보를 연속 실행한다. 폐기 뒤에는 완료 계약 확인과 새 허브 생성이 가능하다. |

- 미처리 예외 후보는 다른 등록이 없는 상태에만 제공하여 보장되지 않는 알림 순서에 기대값을 의존시키지 않는다.
- 처리되는 실패는 지정한 예외만 수집한다. 단언 실패 등 다른 예외는 다시 전파하여 테스트 실패가 숨겨지지 않게 한다.
- 고정·랜덤 실행과 재실행으로 생성된 미완료 허브는 프로젝트 정리에서 등록을 해제하고 폐기한다. 전역 예외 처리기는 사례 전후와 임시 정책 사용 뒤 복구하며 테스트 클래스는 병렬 실행하지 않는다.
- seed별 실행시간·도달 깊이는 RandomContinuousTest의 출력으로 확인하여 기록한다. 세 seed의 실행시간 합계가 60초를 넘으면 테스트 안내의 중간 확인 절차를 따른다. 자동 시간 제한은 두지 않는다.
- 기존 NUnit의 멀티캐스트 부분 해제와 할당 검증은 유지한다.

## 검증 방법

- 테스트 클래스는 NonParallelizable이며 사례 전후 ExceptionHandler를 초기화한다.
- 직접·client 등록 사이의 호출 순서에 의존하지 않고 호출 대상과 횟수를 비교한다.
- 할당 측정 구간에는 등록·대리자 생성·단언을 포함하지 않는다.
- EventHub의 대응 계약은 [EventHub 테스트 계획](../../03-E.2-EventHub/docs/02.%20Plans.md)에서 검증한다.
- 두 모듈에 걸친 변경은 전체 Release 테스트로 확인한다. 장시간 벤치마크와 외부 장비 테스트는 이 계획에 포함하지 않는다.

## 실행과 기록

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release --filter FullyQualifiedName~LifecycleHub
```

두 Hub와 전체 테스트의 실행 기록은 공통 상위 폴더의 [검증 결과](../../docs/Hub%20Results.md)에 둔다.

이번 UniTest 보강의 상세 결과는 [모듈 결과](03.%20Results.md)에 기록한다. 사전·집합과 함께 보강하므로 Release 빌드와 전체 일반 테스트도 실행한다. 벤치마크·Extended 테스트는 제외한다.

## 과거 검증 범위

[공통 검증 결과](../../docs/Hub%20Results.md)의 단계별 기록을 구분하기 위한 범위이다. 현재 계약은 앞의 상태·동작 대응을 따른다.

| 검증 대상 | 실행 범위와 기대 계약 |
| --- | --- |
| 모듈 분리 | 기존 연결·해제·폐기·멀티캐스트·할당 사례를 LifecycleHub와 EventHub로 나누어 전체 Release 테스트를 실행한다. 공개 API와 동작의 동일성을 확인한다. |
| 직접 생애주기 구독 전환 | 직접 +=의 대리자 묶음 등록, -=의 첫 일치·전체 묶음 해제, 실패 시 나머지 내부 호출 생략과 예외 보고, 폐기 중 변경과 할당을 확인한다. |
| 구독 저장소 통합 | C4–C5·L2·D1–D4에서 직접·client 키 충돌, 교차 해제·null·폐기 중 변경 차단과 실패를 검사한다. 당시 중복 거부는 ArgumentException을 기대하며 등록 간 통지 순서는 비교하지 않는다. |
| 중복 등록 예외 통일 | C4·D1에서 직접·client 중복을 InvalidOperationException으로 거부하고 기존 등록은 유지하는지 확인한다. 전체 Release 테스트를 실행한다. |
| EventHub 후속 변경 | 두 모듈을 포함한 전체 실행에서 LifecycleHub 회귀와 폐기 구간의 무할당을 확인한다. EventHub의 실행 명령과 범위는 해당 [계획](../../03-E.2-EventHub/docs/02.%20Plans.md)을 따른다. |

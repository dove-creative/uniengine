# LifecycleHub 상태와 동작

## 목차

- 연결과 폐기
- 직접 구독
- 할당

## 연결과 폐기

LifecycleHub는 객체별 연결과 폐기 완료 알림을 관리한다. EventHub와 함께 검사하던 기존 사례 중 LifecycleHub 사례를 이 모듈로 분리한다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 폐기 완료 뒤 Connect를 호출한다. | IsDisposed는 true이며 ObjectDisposedException으로 연결을 거부한다. |
| C2 | 완료 반응을 등록한 수신자를 Disconnect한 뒤 폐기한다. | 해제된 수신자에게 완료 알림을 보내지 않는다. |
| C3 | 없는 수신자·null을 해제하고 폐기 후 다시 해제한다. | 기존 연결은 유지하고 무효 해제 요청은 무시한다. |
| C4 | 직접 구독의 대리자와 같은 키로 client 연결을 등록하거나 그 반대로 등록한다. | 두 경로가 같은 키 공간을 사용하므로 중복은 InvalidOperationException으로 거부하고 기존 콜백을 유지한다. |
| C5 | 직접 구독을 Disconnect로 해제하고 대리자 키의 client 연결을 -=로 해제한다. | 같은 식별자에 대한 등록을 제거하여 완료 알림을 생략한다. |
| L1 | 완료 반응을 등록한 뒤 Dispose를 반복 호출한다. | 처음에만 통지하고 IsDisposed는 true로 유지한다. |
| L2 | 직접·client 콜백 안에서 해제·재폐기·새 등록을 시도한다. | 두 경로 모두 완료 상태를 관찰하고 해제·재폐기는 무시하며 새 등록은 거부한다. 등록된 두 콜백은 각각 한 번 통지한다. |

## 직접 구독

직접 OnDisposed 이벤트는 대리자를 키와 값으로 하여 client 연결과 같은 사전에 등록한다. 등록 간 통지 순서와 경로별 우선순위는 검증 계약에 포함하지 않는다.

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| D1 | 이미 등록된 대리자를 직접 이벤트에 다시 등록한다. | InvalidOperationException으로 거부하고 기존 등록과 다른 콜백을 각각 한 번 통지한다. |
| D2 | 멀티캐스트 등록의 내부 콜백 또는 전체 묶음을 해제한다. | 내부 콜백만 지정하면 등록은 유지하고, 전체 묶음을 지정하면 해당 등록만 제거한다. |
| D3 | 직접·client 멀티캐스트의 첫 콜백이 실패한다. | 같은 등록의 나머지 콜백은 생략한다. 보고가 정상 반환하면 다른 경로의 등록도 통지하고, 처리기가 없으면 원래 예외를 전파한다. 어느 경우에도 폐기 상태와 정리는 완료한다. |
| D4 | 활성 상태에서 직접 이벤트에 null을 등록·해제하고 client에 null 콜백을 등록한다. | null 직접 구독은 무시하고 null client 콜백은 통지 없이 건너뛴다. 완료 후 null 등록도 ObjectDisposedException이며 해제는 무시한다. |

## 할당

| ID | 상태와 동작 | 기대 결과 |
| --- | --- | --- |
| A1 | 연결별·직접 멀티캐스트를 등록한 허브를 폐기한다. | 네 콜백을 호출하고 폐기 측정 구간의 관리 힙 할당은 0 B이다. |

등록과 대리자 생성 비용은 폐기 구간의 할당 측정에 포함하지 않는다.

## 실행 구성

[ConfigurationTests](../ConfigurationTests.cs)의 NUnit 사례 9개와 [ConfigurationStateProjectTests](../UniTest/ConfigurationStateProjectTests.cs)의 UniTest 기본 사례 1개를 단일 UniEngine.Tests 프로젝트에서 실행한다. UniTest 상태 전이 구현은 UniTest 폴더에 두고, 표·계획·결과는 이 docs 폴더에서 관리한다. 본체 공개 API로 검증한다.

설치 경로 확장은 InstallationPath·InvalidInstallationPaths 사례에서 명시값·상대 경로 정규화·기존 파일 보존·중복 초기화·잘못된 입력 후 복구를 확인한다. 기존 Initialize 사례로 단일 인자 API의 기본 설치 경로도 검사한다. 전체 초기화 순서와 실패 계약은 [Bootstrapper 테스트](../../../02-Core/04-Bootstrapper/docs/02.%20Plans.md)에서 함께 확인한다.

UniTest는 CompactProject&lt;Model&gt;·Inline 방식으로 네 단계를 구성한다. 프레임워크가 이전 Lab을 재실행하므로 각 Lab은 해당 단계까지의 전체 시나리오를 새 프로세스에서 재현한다. 성공·취소 여부와 마지막 ExecutionCount가 4인지 검사하며 실패에는 JSON 보고서를 포함한다.

ConcurrentReaders는 네 스레드의 초기화 전 조회 거부를 확인하고 신호로 읽기와 초기화를 함께 시작한다. 각 스레드는 DataPath 조회가 처음 성공할 때 InstallationPath도 준비됐는지 확인하고 두 값을 100회 반복 조회한다. 신호와 초기화 관찰의 10초 제한은 교착 시 실패 종료를 위한 한도이다. getter의 lock 제거와 DataPath 공개 API 변경은 Release 전체 일반 테스트로 검증한다.

## 랜덤 연속 실행

[ConfigurationContinuousScenario](../UniTest/ConfigurationContinuousScenario.cs)는 C1–C5와 U1의 동작을 seed 0·1·2에서 각각 깊이 8로 실행한다. 초기화 전 조회와 잘못된 ID, 차단된 경로의 실패와 복구 또는 기존 디렉터리 보존을 거쳐 한 번 초기화한다. 이후 경로 조회와 재초기화 거부를 조합해 확정된 경로와 기존 파일 내용이 유지되는지 검사한다.

Configuration은 프로세스에서 한 번만 초기화할 수 있어 이후의 후보는 조회와 재초기화 거부로 제한된다. 세 단계의 초기화 전 준비와 초기화, 네 단계의 초기화 후 조합을 포함하는 깊이 8로 새 프로세스 생성 비용을 제한한다. 새 후보 이력은 GUID가 다른 프로세스에서 처음부터 재현하고, 동일한 성공 이력의 재검사는 생략한다. 프로세스당 30초 제한을 두고 [테스트 안내](../../../README.md)의 테스트 작성 기준 절에 따라 실행 중 확인한다.

## 격리와 정리

각 프로세스에는 고유 GUID 기반 애플리케이션 ID를 전달한다. 경로 생성 실패는 테스트 전용 프로젝트 경로에 파일을 만들어 유도한다. 부모 실행기는 30초 제한, 종료 코드, 표준 출력과 오류를 확인한다. 정상·실패·시간 초과 뒤에는 부모가 검증한 정확한 테스트 소유 경로만 정리한다.

# Configuration 상태와 동작

## 목차

- 검증 기준

## 검증 기준

공개 API로 설정의 초기화·경로 생성·실패 이후 상태를 검증한다.

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| C1 | 초기화 전 DataPath 조회 | InvalidOperationException이다. |
| C2 | null·빈 문자열·공백·점 경로·유효하지 않은 파일명 | ArgumentException이며 미초기화 상태를 유지한다. |
| C3 | 새 경로·기존 경로 초기화 | 문서 폴더 아래 애플리케이션 경로를 확정하고 기존 파일을 보존한다. |
| C4 | 성공한 초기화 재호출 | InvalidOperationException이며 원래 경로를 유지한다. |
| C5 | 경로가 파일로 차단된 상태 | I/O 실패 시 경로를 확정하지 않고, 차단 제거 후 초기화할 수 있다. |
| C6 | 기존 단일 인자 API와 명시적·상대 설치 경로 | 기본값은 AppContext.BaseDirectory이며 명시값은 절대 경로로 정규화한다. DataPath는 기존 규칙을 유지하고 기존 리소스를 보존한다. |
| C7 | 빈 값·공백·존재하지 않는 설치 디렉터리·파일 경로 | 입력을 거부하고 두 경로 모두 미확정 상태이다. 설치 디렉터리를 생성하지 않으며 올바른 입력으로 재호출할 수 있다. |
| C8 | 초기화와 동시에 여러 스레드에서 경로를 조회 | 초기화 전에는 조회를 거부하며, DataPath 조회가 성공하면 InstallationPath도 준비되어 있다. 이후 반복 조회는 같은 두 값을 반환한다. |
| U1 | 실패 → 미초기화 → 정상 초기화 → 재초기화 거부 | UniTest의 네 단계와 이전 단계 재현이 성공한다. |

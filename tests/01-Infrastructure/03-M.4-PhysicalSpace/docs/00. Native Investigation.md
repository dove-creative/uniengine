# PhysicalSpace 네이티브 사전 조사

2026-11-23의 0단계 조사이다. 최초의 공식 C 바인딩 확장 제안은 사용자 결정에 따라 폐기하고, 수정하지 않은 Rapier·Parry를 정확한 버전 의존성으로 사용하는 별도 Rust 연결 DLL로 변경했다.

## 구조 결정

최초 비교에서는 공식 C 바인딩의 `RprWorld`·`RprSharedShape` 내부가 다른 크레이트에 공개되지 않는 점을 근거로 같은 크레이트 안의 확장을 제안했다. 이는 공식 C 바인딩의 객체를 계속 사용하는 경우의 제약이다. Rapier의 공개 `PhysicsWorld`와 Parry 도형을 별도 Rust 프로젝트가 직접 소유하는 방식에는 해당 제약이 적용되지 않는다.

현재 구조는 `PhysicalSpace C# 객체 → UniEngine 전용 Rust C ABI → Rapier·Parry`이다. 공식 C 바인딩에 의존하지 않는다. 0단계에서는 Rapier 로컬 수정본 0.36.1-r1과 수정하지 않은 Parry 0.31.1을 검증했으며, 연결 계층의 핸들·오류·콜백·수명 관리는 UniEngine이 작성한다. C# 객체와 제품 연결 API는 후속 단계이다.

## 현재 상태

- 승인된 Rust/Cargo 1.99.1을 시스템 PATH 변경 없이 `packages/rapier/obj/tools`에 설치했다. 기존 MSVC를 사용하며 CMake나 바인딩 생성기는 추가하지 않았다.
- Rapier 0.36.1·Parry 0.31.1의 네 조합을 정확한 의존성과 Cargo.lock으로 고정했다. 배포 압축 파일과 빌드 입력 파일의 일치를 확인했다.
- Windows x64의 2D/3D × f32/f64 연결 DLL 빌드, 실제 내보내기·C 헤더 대조와 C 소비 검증을 수행했다.
- 원본의 검사 후 운동 정지와 무수정 dt=0 대안의 초기 수면 전환 실패를 보존했다. [수정 기록](../../../../packages/rapier/docs/revisions/Revisions.md)과 [개조·검증 계획](../../../../packages/rapier/docs/revisions/0.36.1-r1/Plan.md)에 따른 수정본은 Rust Release 76개·Debug 회귀 52개, C assertion 204개와 전체 .NET 1,660개를 통과했다.
- 본체 C# API 구현과 제품 DLL 채택은 아직 시작하지 않았다. 이번 0단계 수정·검증 완료를 1단계 진행 승인이나 전체 API Coverage 완료로 표시하지 않는다.

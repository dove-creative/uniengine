- 검증 범위

## 검증 범위

[모듈별 계획](../README.md)의 공개 API 계약과 상태 전이를 단일 UniEngine.Tests 프로젝트에서 함께 검증한다.

| 범위 | 검증 방법 |
| --- | --- |
| 기준 실행 | 검증 사례를 보강하기 전 기존 전체 테스트 결과를 기록한다. |
| 통합 실행 | 본체 Release 빌드 후 전체 테스트를 실행하고 Infrastructure 모듈별 결과를 분류한다. |
| 정적 상태 격리 | Configuration·Log·ExceptionHandler를 선택해 다시 실행하고 전체 실행과 결과를 비교한다. |
| 시간 표시 회귀 | 극값·큰 시간 경계의 양·음수 사례를 포함한 표시 유틸리티 모듈을 실행한다. 기준은 [표시 유틸리티 계획](../03-M.1-Utilities/docs/02.%20Plans.md)이다. |
| 테스트 폴더명 변경 | 기존 전체 테스트를 다시 실행하여 탐색·실행 결과를 확인한다. |
| 대상 프레임워크 전환 | 본체 빌드와 전체 테스트를 실행하고 생성된 어셈블리 메타데이터·런타임 의존성을 확인한다. |

## 격리와 의존 관계

테스트가 본체를 ProjectReference로 참조한다. 본체의 InternalsVisibleTo는 UniEngine.Tests에 internal 접근만 허용하며, 본체가 테스트 프로젝트나 테스트 패키지에 의존하지 않는지 확인한다.

Configuration·Log의 각 사례와 UniTest 단계별 재현은 새 프로세스와 고유 경로를 사용한다. Support가 프로세스 격리·시간 제한·소유 경로 정리를 담당한다. ExceptionHandler는 각 사례 전후 처리기를 해제하고 병렬 실행을 막는다.

## 실행과 기록

저장소 루트에서 .NET 10 SDK로 실행한다. SDK 선택과 장시간 실행 기준은 [공통 테스트 안내](../../README.md)를 따른다.

```powershell
dotnet build src/UniEngine.sln -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-restore --logger 'trx;LogFileName=Infrastructure-Full.trx' --results-directory tests/bin/TestResults
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'FullyQualifiedName~ConfigurationTests|FullyQualifiedName~ConfigurationStateProjectTests|FullyQualifiedName~LogTests|FullyQualifiedName~LogStateProjectTests|FullyQualifiedName~ExceptionHandler' --logger 'trx;LogFileName=Infrastructure-Static-Isolation.trx' --results-directory tests/bin/TestResults
```

기준 실행·폴더명 변경·프레임워크 전환은 전체 테스트 명령의 LogFileName을 각각 Infrastructure-Baseline.trx·UniTest-Convention-Update.trx·NetStandardMigration.trx로 구분한다. 재실행 시 이전 원본을 덮어쓰지 않도록 실행별 이름이나 디렉터리를 사용한다.

[검증 결과](03.%20Results.md)에 실행 환경·범위·통과·실패·건너뜀·종료 코드와 TRX 경로를 기록한다. 전체 실행과 모듈 단독 실행, 서로 다른 실행에서 얻은 모듈별 합계를 구분한다. 단독 재검증 후에는 전체 재실행 여부도 기록한다. 원본은 버전 관리에서 제외한다.

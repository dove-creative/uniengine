# Log 상태와 동작

## 목차

1. 검증 기준

## 검증 기준

| ID | 상태·동작 | 기대 결과 |
| --- | --- | --- |
| L1 | 초기화 전 접근·기본 출력기 | 설정 전 Initialize와 비어 있지 않은 버퍼 저장을 거부하며 기본 출력은 콘솔에 전달한다. |
| L2 | 메시지·레벨·null·기본 메시지·빈 줄 | 출력기 인자와 파일 버퍼의 표현을 유지한다. |
| L3 | 컬렉션·선택 함수·smartWrite | 간단·상세 표현, 빈 목록과 null, smartWrite 해제를 구분한다. |
| L4 | UTF-8 파일·빈 버퍼 | BOM 없는 UTF-8 내용과 반환값이 같고, 빈 Print는 파일과 마지막 경로를 변경하지 않는다. |
| L5 | 연속 저장 | 매번 고유 경로를 사용하고 기존 파일을 덮어쓰지 않는다. |
| L6 | 출력기 예외·다른 스레드 재진입 | 원래 예외는 전달되고 기록은 유지된다. 출력 중 다른 스레드가 버퍼에 접근할 수 있다. |
| L7 | 스택 추적 설정·Reset·재초기화 | 추적 포함 여부를 반영하고 Reset·Initialize가 대기 기록을 비운다. Initialize는 마지막 경로와 출력기를 갱신한다. |
| L8 | 파일로 차단한 저장 경로 | I/O 예외를 전달하고 성공하지 않은 경로를 확정하지 않는다. |
| U1 | 초기화 → 기록 → 저장 → 빈 버퍼 → 재기록·재초기화 | UniTest의 여덟 단계로 각 상태를 재현한다. |
| U2 | 기존 저장 → 경로 차단 → 저장 실패 → 복구 → 재저장 → 빈 버퍼 | 실패 시 마지막 성공 경로와 버퍼를 유지하고 복구 후 저장한다. |

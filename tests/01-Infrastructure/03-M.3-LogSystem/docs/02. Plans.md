# Log 테스트 계획

## 목차

- 실행 구성
- 랜덤 연속 실행
- 검증 방법

## 실행 구성

[LogTests](../LogTests.cs)의 NUnit 사례 11개와 [LogStateProjectTests](../UniTest/LogStateProjectTests.cs)의 UniTest 기본 사례 2개를 기존 테스트 프로젝트에 배치한다. UniTest 상태 전이 구현은 UniTest 폴더에 두고, 표·계획·결과는 이 docs 폴더에서 관리한다. 각 기본 시나리오와 상태 전이 단계는 새 프로세스에서 실행한다.

UniTest는 CompactProject&lt;Model&gt;·Inline 구성이며 수명 흐름 8단계와 저장 복구 6단계를 수행한다. 이전 Lab 재실행 때 정적 상태와 파일이 남지 않도록 각 Lab에서 해당 단계까지의 전체 흐름을 고유 경로의 새 프로세스에 재현한다. 성공·취소 여부와 수행 단계 수를 검사하고 실패에는 JSON 보고서를 포함한다.

## 랜덤 연속 실행

[LogContinuousScenario](../UniTest/LogContinuousScenario.cs)는 L2·L4·L5·L7·L8과 U1·U2를 seed 0·1·2에서 각각 깊이 100으로 실행한다. 기록 레벨, 빈 줄, 저장, 버퍼 초기화, 출력기 교체, 저장 경로 차단·복구를 조합한다. 출력기 인자와 누적 버퍼, 파일 내용·경로의 고유성, 실패 전 마지막 성공 경로와 복구 후 저장되는 버퍼를 검사한다.

각 seed는 GUID 기반 경로를 사용하는 새 프로세스에서 실행한다. 각 후보 이력을 재현하기 전에 해당 경로를 비우고 공개 `Log.Initialize`로 Log 상태를 초기화한다. 동일한 성공 이력의 재검사는 생략한다. 연속 실행 자식 프로세스당 120초 제한을 두고 [테스트 안내](../../../README.md)의 테스트 작성 기준 절에 따라 실행 중 확인한다.

## 검증 방법

- 파일 저장 실패는 테스트 소유 프로젝트 디렉터리를 파일로 교체하여 유도한다. 권한 변경을 사용하지 않는다.
- 저장 결과는 원본 문자열과 실제 바이트를 비교한다. 시간 문자열과 스택 전체 내용은 고정하지 않는다.
- 연속 저장은 파일 경로의 고유성과 기존 파일 내용을 검사하며 특정 초 경계나 접미사 번호를 가정하지 않는다.
- 출력기 재진입은 콜백에서 다른 스레드의 Write가 완료되는지 확인한다.
- 공통 실행기는 기본 사례의 프로세스당 30초 제한과 랜덤 연속 실행의 프로세스당 120초 제한을 적용한다. 부모가 확인한 정확한 테스트 소유 경로를 정리한다.

# Log 테스트 계획

## 목차

- 실행 구성
- 검증 방법

## 실행 구성

[LogTests](../LogTests.cs)의 NUnit 사례 11개와 [LogStateProjectTests](../UniTest/LogStateProjectTests.cs)의 UniTest 사례 2개를 기존 테스트 프로젝트에 배치한다. UniTest 상태 전이 구현은 UniTest 폴더에 두고, 표·계획·결과는 이 docs 폴더에서 관리한다. Configuration과 Log는 각 사례와 상태 전이 단계마다 새 프로세스에서 사용한다.

UniTest는 CompactProject&lt;Model&gt;·Inline 구성이며 수명 흐름 8단계와 저장 복구 6단계를 수행한다. 이전 Lab 재실행 때 정적 상태와 파일이 남지 않도록 각 Lab에서 해당 단계까지의 전체 흐름을 고유 경로의 새 프로세스에 재현한다. 성공·취소 여부와 수행 단계 수를 검사하고 실패에는 JSON 보고서를 포함한다.

## 검증 방법

- 파일 저장 실패는 테스트 소유 프로젝트 디렉터리를 파일로 교체하여 유도한다. 권한 변경을 사용하지 않는다.
- 저장 결과는 원본 문자열과 실제 바이트를 비교한다. 시간 문자열과 스택 전체 내용은 고정하지 않는다.
- 연속 저장은 파일 경로의 고유성과 기존 파일 내용을 검사하며 특정 초 경계나 접미사 번호를 가정하지 않는다.
- 출력기 재진입은 콜백에서 다른 스레드의 Write가 완료되는지 확인한다.
- 공통 실행기는 프로세스당 30초 제한을 두고, 부모가 확인한 정확한 테스트 소유 경로를 정리한다.

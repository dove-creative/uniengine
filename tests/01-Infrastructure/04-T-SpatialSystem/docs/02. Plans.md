# Spatial System 검증 계획

## 이번 단계

현재 구현·검증 대상은 CollisionSpace 2D·3D와 Unity 연결이다. PhysicalSpace·공개 Rigidbody 및 물리 전용 사례는 제외한다. 소스 작성 단계의 사용자 지정 범위는 소스와 정적 검사까지였다. 이후 전체 .NET 테스트를 실행하였으며 결과는 [검증 결과](03.%20Results.md)에 둔다. Unity Editor 실행, 패키징·배포는 수행하지 않았으며 해당 절차는 후속 실행 검증 단계의 계획이다.

## 공통 고정 사례

[상태·동작 표](01.%20Tables.md)의 양쪽 차원을 다음 소스에서 검증한다.

- `SpatialContract2DTests/SpatialContract3DTests`: Collider 대리자 읽기·쓰기, 결과·필터·동일성, 쌍 전이, 무효화, 구독·해제 실패와 도중 Dispose.
- `SpatialWorld2DTests/SpatialWorld3DTests`: 월드별 시간·설정, 생성·소속·입력 검사, 인자 이름, Update 재진입·실패 복구, 다른 공간의 생성 결과 해제, 생성한 하위 핸들의 해제 순서와 리스너 실패.
- `SpatialRules2DTests/SpatialRules3DTests`: 지연 설정·최종값·콜백 중 예약, 관계 식별자와 이전 종료, Trigger 종류 변경·유지, 중단된 Update의 설정으로 끝난 관계와 대기 중인 시작, 여러 상대와 닿은 Collider의 해제·외부 소멸·개별 종료·비활성화·재시작, 중첩 알림 순서, 외부 비활성 상태, 오류 보고·객체 제외·미등록 처리기·처리기 실패·해제 실패, 엔진 오류 책임 경계. 알림 콜백 실패는 네 가지 알림마다 공간 콜백이면 그 구독만 해제하고 쌍·다른 구독을 유지하는지, Collider 콜백이면 양쪽 Collider만 제외하고 월드·다른 쌍·공간 구독을 유지하는지 확인한다. 미처리 예외의 중단과 다음 Update의 전달, 쌍 안팎 객체의 읽기 실패, 해제된 핸들 사용을 포함하며, 이미 보고된 예외와 엔진 오류로는 구독 해제와 제외가 없는지 확인한다. 어댑터의 잘못된 알림과 월드 진행 예외는 처리기 등록·미등록·예외마다 월드를 유지하고 남은 종료와 알림을 전달하는지 확인한다. .NET에서는 전역 ExceptionHandler 설정을 쓰므로 비병렬 fixture이며 매 사례 전후 기본 정책으로 복원한다.
- `SpatialShapeTests`: 6개 기본 형상의 로컬 속성과 입력 실패, 해제 후 접근.
- `UniTest/SpatialLifetime2DStateTests/SpatialLifetime3DStateTests.FixedLifetimePaths`: 상태표의 시작·중복·종료·재진입과 해제/소멸/Reset의 고정 경로. 후보 이력마다 새 fixture로 전체 경로를 재구성한다.

고정 사례는 랜덤 경로 선택과 무관하게 수행한다. 공통 대리자 fixture는 물리 계산을 대신하지 않으며 외부 상태 접근·알림·수명 계약만 관찰한다. Unity의 자세 변환과 실제 충돌 콜백은 Unity 연동 사례가 담당한다.

## UniTest 연속 경로

2D·3D 각각 seed 0·1·2, seed당 깊이 100이다. 각 실행은 독립된 초기 상태이며 같은 실행 안에서 이전 동작의 결과를 누적한다. 후보는 상태표의 16개 동작이다. ToggleEnabled·ToggleTrigger의 예약값과 적용값, 실제 관계 종류를 독립 모델로 유지한다. Update·Configure·Create를 수명 전이와 함께 적용한다. 외부 무효화·명시적 해제·늦은 알림·Reset을 섞고 매 단계 유효성, 공간·양쪽 핸들의 알림 수, release·unsubscribe·Update·월드 Disposed 횟수를 모델과 비교한다. 실제 도달 깊이·시간·부모 ID 이력은 RandomContinuousTest의 출력으로 기록한다.

동일 대상의 세 seed 실제 실행시간 합계가 60초를 넘으면 공통 테스트 안내의 중간 확인 기준을 따른다. 실행시간·도달 깊이는 추정하지 않고 실제 실행 결과만 기록한다.

## Unity PlayMode 사례

`Unity/SpatialUnity2DTests.cs`, `Unity/SpatialUnity3DTests.cs`는 `UNITY_2022_3_OR_NEWER && UNITY_INCLUDE_TESTS` 조건의 소스이다. Unity 2022.3과 Unity 6의 PlayMode 테스트 어셈블리에 공통·Unity 소스 및 기존 Transform/Math 의존 소스를 연결하고, Unity Test Framework를 통해 실행한다. 공통 NUnit·UniTest 소스 전체를 Unity로 복사할 필요는 없다. 이번 단계에는 별도 테스트 프로젝트·asmdef를 만들지 않는다.

| 메서드 | 기대값 |
| --- | --- |
| FactoriesSelectEverySupportedWrapperAndPreserveIdentity | 기본 형상·Unity 전용 형상·fallback, 동일 핸들, Source 형식, 자체 Scene 소속, Renderer 없음 |
| QueriesGrowAndWorldsAtIdenticalCoordinatesRemainIsolated | 전체 40개, Trigger 제외 20개, 다른 월드 제외, 빈 레이어 0개 |
| EventsAreDeliveredByTheSelectedWorldUpdate | 명시적 Update를 호출한 월드에서만 알림 전달, 다른 월드의 알림 수 유지 |
| LayerPoliciesAreIndependentAndKeepGlobalsUnchanged | 월드별 레이어 허용·차단·변경, Unity 전역 중력과 레이어 행렬 불변 |
| CollisionOnlyWorldAutomaticallyReportsNativeTransitions | 각 차원 기본 3형상×접촉/Trigger, 공개 강체 없이 자동 전달, 재진입 거부, 콜백 중 생성·해제, 종료 후 재진입 |
| DeferredDisableAndExternalInactiveStateEndRelationshipsOnce | 같은 Update 전 false→true는 관계 유지, 다음 Update 비활성화는 Exit 한 번, 외부 GameObject 비활성 상태 보호 |
| QueryResultsReuseExistingHandlesAndRejectUnregisteredObjects | 질의 결과의 핸들 동일성, 직접 삽입한 미등록 native 객체의 오사용 오류 |
| UnsupportedCompositeIsRejectedWithoutLeavingAnObject (2D) | NotSupportedException으로 거부하고 월드에 객체를 남기지 않음 |
| ReenabledSensorCanReportANewNativeEntry | 센서 비활성화·재활성화 후 이전 쌍 기록 때문에 새 Enter가 누락되지 않음 |
| MovingOwnedObjectInvalidatesTheOriginalHandle | Source를 다른 씬으로 옮긴 뒤 기존 핸들 무효화·Disposed 1회 |
| AmbiguousTriggerLayoutsAreRejectedAndExcluded | 시스템 생성 객체에 모호한 구조를 외부 주입했을 때 다음 Update에서 오류와 제외 |
| DisposeIsImmediateAndNativeDestructionIsDeferred | 즉시 논리 해제, 지연 native 파괴, 외부 소멸은 명시적 Update에서 감지 |
| WorldDisposesChildrenBeforeItsEventAndUnloadsOwnedScene | 하위 Disposed 후 월드 Disposed 각각 1회, 비동기 Scene unload |
| OwnedRelayIsRemovedWithItsCollider | 시스템 생성 Collider의 중계를 자동 연결하고 소유 객체와 함께 제거 |
| ExternalSceneUnloadInvalidatesTheWorld | 외부 Scene unload에 따른 월드·하위 핸들 무효화와 Disposed |

씬 전환 중 월드 유지는 지원하지 않으므로 검증하지 않는다. 월드의 씬이 내려갈 때의 해제는 ExternalSceneUnloadInvalidatesTheWorld가 확인한다.

형상 선택과 실제 접촉 사례는 구분한다. Mesh/Terrain 등의 데이터 편집·복잡한 형상 조합, native solver·수면·전역 콜백 설정의 차이, 대규모 객체 성능, 플랫폼별 실행까지 이 고정 사례로 검증되었다고 판단하지 않는다.

## 후속 실행 명령과 완료 기준

공개 API 변경이므로 후속 실행 단계에는 전체 .NET 테스트와 두 Unity 버전의 연동 사례를 확인한다.

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release
```

재현 범위를 좁힐 때 공통 모듈 필터는 `TestCategory=SpatialSystem`, 연속 경로 필터는 `TestCategory=SpatialSystem&TestCategory=RandomContinuous`이다. Unity는 PlayMode에서 `SpatialSystemUnity` 범주를 선택한다.

Unity를 실행하지 않고 소스만 확인할 때는 [분석 스크립트](AnalyzeSpatial.ps1)를 사용한다. 공통 소스와 Unity 래퍼를 한 어셈블리로 분석하고, 공통 소스를 참조하는 별도 어셈블리로도 분석하여 internal 접근 문제를 찾는다.

```powershell
pwsh -NoProfile -File tests/01-Infrastructure/04-T-SpatialSystem/docs/AnalyzeSpatial.ps1
pwsh -NoProfile -File tests/01-Infrastructure/04-T-SpatialSystem/docs/AnalyzeSpatial.ps1 -IncludeTests
```

`-IncludeTests`는 테스트 프로젝트를 복원한 뒤 사용한다. Unity 테스트 소스까지 포함하려면 Test Framework가 있는 Unity 프로젝트의 `nunit.framework.dll`과 `UnityEngine.TestRunner.dll`을 `-UnityNUnit`과 `-UnityTestRunner`로 지정한다. 설치되지 않은 Unity 버전은 건너뛰고 그 사실을 출력한다.

빌드와 NUnit/UniTest 실행 결과, Unity 버전·씬·실패 로그, 미검증 범위를 결과 문서에 기록한다. seed별 목표 100 도달과 모든 고정 사례의 통과를 확인한다.

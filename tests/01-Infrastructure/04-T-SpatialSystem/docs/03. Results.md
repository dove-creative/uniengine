# Spatial System 검증 결과

## 2026-11-25 오류 처리와 객체별 관계 목록

알림 콜백의 예외가 구독한 공간이나 Collider 하나를 해제하던 동작을 바꾸었다. 공간에 등록한 콜백은 그 구독을 해제하고, Collider에 등록한 콜백은 그 알림의 양쪽 Collider를 제외하며, 두 경우 모두 월드를 유지한다. 콜백 안의 읽기 실패는 읽지 못한 객체만 제외한다. 추가한 고정 사례는 네 가지 알림의 공간 구독 해제 4건과 양쪽 Collider 제외 4건, 처리기 미등록·처리기 예외의 중단과 다음 Update 전달 4건, 쌍 안팎 객체의 읽기 실패 8건, 해제된 핸들 사용 2건, 엔진 오류 1건이다. 차원마다 같은 사례를 둔다.

어댑터의 잘못된 알림과 월드 진행 예외가 월드를 해제하던 동작도 바꾸어, 그 알림만 버리거나 그 Update만 끝내고 월드를 유지한다. 처리기 등록·미등록·예외의 고정 사례를 각각 3건씩 차원마다 추가하였으며 변경 전 소스에서 모두 실패하였다.

월드 하나에 모으던 진행 중인 관계를 각 Collider가 가지도록 바꾸고, Unity 연결의 관계 번호도 Collider별 연결에 나누었다. 끝난 관계의 기록은 없앴다. 여러 상대와 닿은 Collider의 해제·외부 소멸·개별 종료·비활성화·재시작을 확인하는 고정 사례 1건을 차원마다 추가하였으며, 이 사례는 변경 전 소스에서도 통과하였다.

시작과 종료는 적용한 설정이 그 관계를 실제로 끝냈는지로 판정하도록 바꾸었다. 이전에는 관계 종류가 그대로인 IsTrigger 변경에도 대기 중인 시작을 버렸고, 설정을 적용한 Update가 중단된 뒤 설정을 되돌리면 종료를 전달하지 않았다. 차원마다 고정 사례 10건을 추가하였으며, 변경 전 소스에서 7건이 실패하고 대기 중인 시작을 버려야 하는 3건은 통과하였다. 생성 대리자가 다른 공간의 핸들을 반환하면 해제하고 거부하는 사례도 차원마다 1건 추가하였으며 변경 전 소스에서 실패하였다.

Unity 연결의 점검은 월드의 쌍 목록을 Collider마다 복사하던 반복을 Collider별 목록의 순회로 바꾸었다. 같은 모양의 .NET 반복문에서 복사는 Collider·쌍 1,000개 기준 Update당 15.3 MB였으며, Unity에서는 변경 전후 모두 측정하지 않았다.

명령은 `dotnet test tests/UniEngine.Tests.csproj -c Release --filter "TestCategory=SpatialSystem"`이다. 실행 이력은 로컬 obj 산출물인 [TRX](../../../obj/SpatialSystem/spatial-2026-11-25.trx)에 있다. 전체 .NET 테스트의 랜덤 연속 사례 87건은 모두 목표 깊이에 도달하였고, 대상별 합계는 Log 64.304초만 60초를 넘었다. Unity 테스트는 실행하지 않았다.

CompositeCollider2D 지원을 제거하고 생성을 거부하도록 바꾸었다. Unity 전용 소스이므로 정적 분석만 수행하였으며 위 12회와 같은 구성에서 오류 0, 경고 0이다.

잘못된 자세·방향 인자의 예외가 실제로 받은 매개변수의 이름을 알리도록 고쳤다. 차원마다 고정 사례 1건을 추가하였으며 변경 전 소스에서 실패하였다. Unity 연결에서는 쓰임이 없는 providesContacts 복원, 중계의 다중 소유자 관리와 Edit Mode 파괴 분기를 제거하였고 정적 분석만 수행하였다. 빌드한 UniEngine.dll을 참조하여 Unity 래퍼 소스 23개만 컴파일 분석한 결과도 2022.3.60f1·6000.3.18f1 모두 오류 0, 경고 0이다.

## 2026-11-25 Rules 반영 정적 검사

Enabled·IsTrigger의 지연 적용과 최종값 처리, 비활성화·Trigger 종류 변경의 종료, 관계 식별자와 공통 알림 순서를 반영하였다. 공통 대리자의 오류는 ExceptionHandler와 객체 제외로 연결하고, 미처리 예외의 중복 보고·정상 호출자 제외를 막는 범위와 중단 후 미적용 설정 보존을 추가하였다. 어댑터가 식별한 프레임워크 오류는 SpatialEngineException으로 구분한다.

Unity의 공개 Wrap·월드 Source·UnityScene과 질의의 자동 등록을 제거하였다. 동일한 레이어 설정의 반복 쓰기 방지와 Ray 방향 길이 계산도 수정하였다. 공통 고정 사례·UniTest 상태 모델과 Unity 테스트 소스를 현재 계약에 맞췄다.

분석은 Roslyn GetDiagnostics를 사용한다. 경계 분석은 공통 CompilationReference를 별도 연결 어셈블리의 참조로 제공하므로 internal 접근 문제도 검사한다. 공통 의존성에는 Transform·Math와 ExceptionHandler 소스를 포함한다. Emit·DLL 생성·프로젝트 빌드·테스트 실행은 하지 않았다.

명령은 `pwsh -NoProfile -File tests/obj/SpatialSystem/AnalyzeSpatial.ps1`과 같은 명령의 `-IncludeTests` 지정이다. [분석 스크립트](../../../obj/SpatialSystem/AnalyzeSpatial.ps1)와 [2026-11-25 로그](../../../obj/SpatialSystem/static-analysis-2026-11-25.txt)는 로컬 obj 산출물이다. 해당 모듈 C# 소스 56개를 대상으로 LF·120자·후행 공백을 별도 확인하였다.

공통 고정 사례와 2D·3D seed 0·1·2, 깊이 100 연속 사례는 소스를 작성했으며 실행하지 않았다. 실제 도달 깊이·실행시간·통과/실패/건너뜀 개수는 미측정이다. Unity의 관계 식별자 대응, native 종료 순서, 실제 레이어 동작도 PlayMode 검증 대기이다. 전체 .NET 테스트와 두 Unity 버전의 연동 테스트는 후속 실행 범위이다.

씬 전환 중 월드 유지는 이후 지원하지 않는 것으로 정하였다. 남은 Unity 실행 확인 항목은 [ISSUES](../../../../docs/02.%20UniEngine/01-Infrastructure/04-T-SpatialSystem/ISSUES.md)에 유지한다.

## 2026-11-24 CollisionSpace 범위 정리 정적 검사

PhysicalSpace·공개 Rigidbody 구현, 강체 연결 API와 물리 전용 테스트·예제를 제거하였다. CollisionSpace의 내부 고정 강체와 생성·질의·알림·Update·레이어·수명은 유지한다. 수정한 테스트 소스를 포함해 정적 분석을 수행하였다.

이번 변경 후 빌드·.NET 테스트·Unity 실행은 수행하지 않았다. 아래 결과는 C# 소스 정적 의미 분석이며 실제 충돌·콜백·수명 사례의 실행 통과를 의미하지 않는다.

| 분석 대상 | 참조 환경 | 오류 | 경고 |
| --- | --- | ---: | ---: |
| 공통·Unity 조건부 제외 소스 | C# 9, .NET Standard 2.1 참조 | 0 | 0 |
| 공통 테스트·UniTest 소스 포함 | C# 9, .NET 10 참조, 현재 NUnit·UniTest 메타데이터 | 0 | 0 |
| Unity 2022.3 소스·Unity 테스트 포함 | 2022.3.60f1 설치 DLL, Unity Test Framework 메타데이터 | 0 | 0 |
| Unity 6 소스·Unity 테스트 포함 | 6000.3.18f1 설치 DLL, Unity Test Framework 메타데이터 | 0 | 0 |

Roslyn의 구문 분석과 GetDiagnostics만 호출했으며 Emit·DLL 생성·테스트 실행은 하지 않았다. 공통 분석에는 기존 Transform2D/3D와 Math 소스도 포함했다. 전체 저장소 컴파일이나 전체 테스트 결과는 아니다. Unity 테스트 메타데이터는 기존 로컬 Unity 프로젝트의 NUnit·TestRunner에서 읽었으며 프로젝트를 실행하거나 수정하지 않았다.

로컬 분석 명령은 `& tests/obj/SpatialSystem/AnalyzeSpatial.ps1`과 `& tests/obj/SpatialSystem/AnalyzeSpatial.ps1 -IncludeTests`이다. [분석 스크립트](../../../obj/SpatialSystem/AnalyzeSpatial.ps1)와 [원본 로그](../../../obj/SpatialSystem/static-analysis.txt)는 로컬 obj 산출물이며 저장소 추적 대상이 아니다.

# Spatial System 상태·동작 표

## 상태

현재 대상은 CollisionSpace 2D·3D이며 같은 수명 모델을 적용한다. 접촉 C와 Trigger T는 쌍의 적용된 Trigger 설정에 따라 구분하며 동시에 활성화되지 않는다. 살아 있는 공간·양쪽 Collider에서만 전이한다. Enabled·IsTrigger는 예약값과 적용값을 별도로 모델링한다. 해제·외부 무효화 상태는 Reset으로 새 외부 상태와 새 핸들을 만들 때까지 유지한다.

| 상태 | 공간/양쪽 핸들 | C | T |
| --- | --- | --- | --- |
| Idle | 유효 | 0 | 0 |
| Contact | 유효 | 1 | 0 |
| Trigger | 유효 | 0 | 1 |
| Disabled | 핸들은 유효하지만 충돌 비참여 | 0 | 0 |
| ColliderDisposed | 첫 Collider 해제 또는 외부 소멸, 공간·두 번째 Collider 유효 | 제거 | 제거 |
| SpaceDisposed | 공간 해제 또는 외부 월드 무효화, 모든 소속 핸들 해제 | 제거 | 제거 |

## 상태별 동작

| 동작 | Idle / Contact / Trigger / Disabled | ColliderDisposed | SpaceDisposed |
| --- | --- | --- | --- |
| ContactEnter | Update에서 최종 설정 적용 후 접촉 종류·활성일 때 C=0이면 시작 1회 | 늦은 알림 무시 | 늦은 알림 무시 |
| ContactExit | C=1이면 종료 1회, C=0이면 무시 | 무시 | 무시 |
| TriggerEnter | Update에서 최종 설정 적용 후 Trigger 종류·활성일 때 T=0이면 시작 1회 | 무시 | 무시 |
| TriggerExit | T=1이면 종료 1회, T=0이면 무시 | 무시 | 무시 |
| ToggleEnabled / ToggleTrigger | 첫 Collider의 예약값만 반전, 다음 Update에서 반영 | ObjectDisposedException | ObjectDisposedException |
| Write | 첫 Collider의 외부 레이어 변경 | ObjectDisposedException | ObjectDisposedException |
| Update | 0.125초를 해당 월드에 전달하고 호출 횟수 증가 | 공간은 계속 진행 | ObjectDisposedException |
| Configure | (2,7) 레이어 충돌 금지와 대칭성 확인 | 동일 | ObjectDisposedException |
| Create | 새 상자 생성·소속 확인 후 개별 해제 | 동일 | ObjectDisposedException |
| Probe | 유효성, 알림 수, 해제 수 일치 | 첫 핸들만 해제 | 전체 해제 |
| DisposeCollider / DestroyCollider | 첫 핸들 무효화·release 1회 | 중복 해제 없음 | 중복 해제 없음 |
| DisposeSpace / DestroyWorld | 소속 핸들·구독·공간 release 각 1회 | 나머지 연결 정리 | 중복 해제 없음 |
| Reset | 새 외부 상태·공간·핸들, 이벤트 수 0 | 동일 | 동일 |

native 알림 동작은 그 알림을 해당 Update에 주입한다. Update는 비활성화·종류 변경에 따른 기존 관계의 종료도 반영한다. 같은 프레임의 Exit→Enter는 다른 전이이며, 쌍 순서를 뒤집은 중복 콜백은 같은 전이이다. 공통 fake fixture의 release는 호출 횟수만 기록하고 Alive 값을 바꾸지 않는다. Unity 연결은 소유 객체의 파괴·씬 unload를 요청한다. DestroyCollider/DestroyWorld는 테스트 대리자의 외부 생존 값을 바꾼다.

## 직접 계약과 Unity 연결

| 대상 | 고정 사례의 관찰 기준 |
| --- | --- |
| 속성·자세 | 자세·레이어의 직접 접근, Enabled·Trigger 예약·최종값 적용, 콜백 중 변경의 다음 Update 적용 |
| 기본 형상 | 6개 기본 형상의 로컬 크기·중심·방향, 부적절한 값과 해제 후 접근 |
| 질의 | 필터 전달, Ray 정규화·정렬·최근접·빈 결과, 동일 핸들, 읽기 전용 스냅샷, 40개 결과, Overlap 중복 제거 |
| 실패·재진입 | 다른 공간 핸들 거부, 처리기가 정상 반환한 객체 오류는 제외 후 나머지 작업 계속, 처리기 미등록·던짐은 정리 후 중단, 공간 콜백 실패는 그 구독만 해제하고 쌍·다른 구독 유지, Collider 콜백 실패는 그 알림의 양쪽 Collider만 제외하고 월드·다른 쌍·공간 구독 유지, 콜백 안의 읽기 실패는 읽지 못한 객체만 제외, 어댑터의 잘못된 알림은 그 알림만, 월드 진행 예외는 그 Update만 끝내고 월드 유지, 알림 도중 Dispose 이후 전달 중단, 해제 실패 이후 나머지 정리 |
| Unity 타입 | 2D Box/Circle/Capsule/Polygon/Edge, 3D Box/Sphere/Capsule/Mesh/Terrain, 일반 래퍼 fallback, 지원하지 않는 Composite 거부 |
| Unity 씬·질의 | 로컬 물리 씬 분리, 40개 native 결과, 레이어·Trigger 필터 |
| Unity 알림 | 공개 강체 없는 CollisionSpace의 기본 3형상 자동 접촉/Trigger 시작·종료, 같은 프레임 재진입, 모호한 배치의 연결 실패 |
| 월드 생성·진행 | 공통 팩터리의 소속·월드 자세·로컬 형상, 다른 공간의 생성 결과 해제·거부, 양의 유한 dt, 중첩 Update 거부, 실패 후 복구 |
| 월드 설정 | 대칭 레이어 행렬·시간의 독립성, 다른 월드 객체 거부, Unity 전역 설정 불변 |
| 오류 책임 | 어댑터 식별 엔진 오류의 SpatialEngineException 전달, 공통 ExceptionHandler 중복 보고 없음 |
| Unity 수명 | 논리 Dispose와 지연 Destroy 차이, 수동 등록 제거와 미등록 질의 거부, 하위 Disposed 이후 월드 Disposed, 씬 unload, 소유 객체와 함께 중계 제거 |

## 확인한 경계 조건

DurationExtremaPreserveTheirMinuteRemainder의 두 사례가 최초 검증에서 동일한 제품 결함으로 실패했으며, 수정 후에는 모두 통과했다.

| 입력 | 기대·수정 후 결과 | 수정 전 결과 |
| --- | --- | --- |
| TimeSpan.MaxValue | '256204778h 48m' | '256204778h 7m' |
| TimeSpan.MinValue | '-256204778h 48m' | '-256204778h 7m' |

기존 ToDisplayString은 총 분을 int로 변환한 뒤 분 나머지를 계산했다. TimeSpan 양 끝에서는 총 분이 int 범위를 초과하여 48분이 7분으로 표시되었다.

수정 후에는 Ticks를 시간당 틱 수로 나눈 뒤 절댓값을 취하여 총 시간을 구하고, 범위가 제한된 Minutes·Seconds 성분을 사용한다. TimeSpan.MinValue.Ticks 자체의 절댓값은 계산하지 않는다. 부동소수점 변환을 제거하여 매우 큰 시간값의 단위 경계 반올림도 방지했다.

양·음수 각각에서 256204778시간보다 1틱 작은 값이 '256204777h 59m'와 '-256204777h 59m'으로 표시되는 회귀 사례 2개를 추가했다. 기존 극값 2개를 포함한 총 42개가 통과했다.

같은 날 UniTest 폴더명을 갱신한 뒤 전체 테스트를 다시 실행했을 때는 제품 소스가 다시 TotalSeconds와 int 캐스팅을 사용하는 이전 계산식인 상태였다. 이번 폴더명 변경에서는 해당 소스를 수정하지 않았다. 극값 두 사례는 위 수정 전 결과로 다시 실패했고, 시간 경계의 기대 '256204777h 59m'와 '-256204777h 59m'도 실제로는 '256204778h 7m'와 '-256204778h 7m'으로 표시되어 실패했다. 최신 전체 실행에서 이 모듈의 결과는 38개 통과, 4개 실패이다.

이후 현재 제품 소스에 틱 기반 계산과 Minutes·Seconds 성분 사용을 다시 반영했다. 수정이 빠진 경위는 현재 Git 이력만으로 확정할 수 없다. 해당 모듈 42개를 재실행하여 모두 통과했고, 결과는 Infrastructure-Formatting-Reapply.trx에 기록했다. 이 재반영 후 전체 테스트는 실행하지 않았다.

2026-11-03에 본체를 netstandard2.1로 전환한 뒤 전체 테스트를 실행했을 때, 제품 소스는 다시 TotalSeconds와 int 캐스팅을 사용하는 이전 계산식이었다. 이 파일은 커밋 666b880 이후 바뀌지 않았고 틱 기반 계산을 담은 커밋은 없으므로, 이전 재반영은 커밋되지 않은 상태였다. 극값과 시간 경계 사례 4개가 위와 같은 결과로 실패했다.

같은 날 Ticks를 시간당 틱 수로 나눈 뒤 절댓값을 취하는 계산과 Minutes·Seconds 성분 사용을 다시 반영했다. 해당 모듈 42개를 재실행하여 모두 통과했고, 최신 결과는 Infrastructure-Formatting-Ticks.trx에 기록했다. 이 수정 후 전체 테스트는 다시 실행하지 않았다.

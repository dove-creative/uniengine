# USM 검증 계획

## 범위

[상태·동작 표](01.%20Tables.md)를 기준으로 직접 생성 API, OperationInfo, 소유권·수명, FSM·BT·Parallel·Reframe을 검증한다. 기존 UniEngine.Tests 프로젝트와 Usm 분류를 사용한다.

## 직접 사례

- 이름·생성자·자식 목록 복사·형제 ID·트리 내/트리 간 공유·초기화 실패.
- 상세 상태 변환·Result 조회·시작·갱신·완료·재시작·자식 우선 종료·중복 Stop.
- 콜백 중 정지·재진입·실행 및 정리 예외·실패 기록.
- Matrix 규칙 우선순위·null 구분·Builder 동결·ID 검증·출력 전달·자기 전이·순환 예산·복구.
- Direct 대기·요청 교체·지연 적용·정지·자기 전이·잘못된 ID.
- Selector StopOnFailure 유무·Self·선점, Sequence 진행 유지·Self·선점.
- 두 평가기의 LoopType별 성공·실패·빈 목록.
- Reframe 소비·동일 요청 재등록·조건 입력·종료 후 재시작·정지 취소·예산 초과.
- Parallel 완료 정책·동일 입력·완료 자식 유지·스냅샷·조건 실패·조기 종료·정리 예외.
- 혼합 트리의 계층별 결과와 실행 기록.

불변 자식 목록의 생성 과정이 순환 삽입을 차단하며 초기화 검증도 중복 방문을 거부한다. 공개 API 테스트는 생성자에 전달했던 배열을 루트로 바꿔도 트리가 변경되지 않음을 확인한다.

## 연속 검증

Matrix 프로젝트는 생성 후 고정 동작 18개, TTC 혼합 프로젝트는 고정 동작 16개를 직접 실행한다. 각 프로젝트에서 seed 0·1·2를 별도 초기 상태로 깊이 100까지 실행한다. Work 시작·갱신·정지 횟수와 활성 상태를 독립 모델로 계산하여 비교한다.

TTC 혼합은 Matrix 아래 Parallel에 Conditional Sequence와 Forced Selector를 배치한다. 성공·실패·조건 거부·Reframe·예외·정지를 누적하며 갱신 횟수와 결과 목록도 검증한다. Results에 seed·깊이·시간·노드/부모 경로를 보관한다.

## 실행

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release --filter TestCategory=Usm --logger "trx;LogFileName=ttc-usm-final.trx" --results-directory tests/bin/UsmResults
dotnet build src/UniEngine.sln -c Release
dotnet test tests/UniEngine.Tests.csproj -c Release --logger "trx;LogFileName=ttc-all-final.trx" --results-directory tests/bin/UsmResults
git -c diff.ignoreSubmodules=all diff --check
```

공개 API 변경이므로 전체 테스트를 실행한다. 실제 집계·실패·건너뜀·한계와 원본 결과를 Results에 기록한다. UTF-8·LF와 변경 범위 공백도 검사한다. Unity 실행, 외부 서비스·장비, 성능·할당 측정은 포함하지 않는다.

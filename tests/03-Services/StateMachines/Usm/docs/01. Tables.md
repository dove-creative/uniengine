# USM 상태·동작 표

## 구성과 실행 수명

| 상태 | 동작 | 기대 결과 |
| --- | --- | --- |
| 생성 직후 | 자식 원본 배열 변경 | 복사 계층 유지, 순환 삽입 불가 |
| 초기화 전 | Initialize | 전체 구조·소유권 검증, Owner·Blackboard 전달 |
| 구조 오류 | Initialize | 중복 ID·공유·누락 전이기 거부, 콜백 이전 실패 |
| 초기화 완료·실패 | Initialize | 재사용 거부 |
| 비활성 | Update | 시작 후 갱신, Work 종료 시 전이기 생략 |
| Running | Update | 시작 반복 없음 |
| 종료 | Update | 새 실행 |
| 활성 | Stop | 자손 → 전이기 → 부모 Work |
| 비활성 | Stop | 중복 종료 없음 |
| 콜백 중 | Stop | 남은 실행·Reframe 취소 |
| 갱신 중 | 재진입·예외 | 정리, 실행·정리 예외 보존 |

## UniTest 누적 경로

| 프로젝트 | 상태 | 동작 | 검증 |
| --- | --- | --- | --- |
| Matrix | 활성 a·b·비활성 | TickA·TickB·Finish·Fault·Halt·Observe | 현재 자식·Payload·수명 횟수 |
| TTC 혼합 | 활성·비활성 | Success·Failure·Reject·Replay·Fault·Stop·Observe | Matrix–Parallel–Sequence/Selector 회차·수명·Reframe·예산 |

각 프로젝트는 모든 동작을 고정 경로로 직접 실행한다. 랜덤 연속 실행도 같은 동작·불변 조건을 사용하며 seed별 독립 초기 상태에서 깊이 100까지 진행한다.

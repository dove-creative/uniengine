# Planar 검증 계획

## 위치 역조회 추가 검증

LocationQueryTests의 직접 사례는 알려진 직선·교차·중첩 선분의 거리와 오차를 기대값으로 사용한다. 정·역방향과 Length·Rate, 공간 오차 경계, 검색 순서·범위·한 점, Hinge, 큰 좌표, 무효 형상과 수명, 원본 첫 후보가 Clip 밖에 있는 경우, 역방향·중첩·반복 Route, 비평면 구현을 검증한다. GenericGeometryTests는 string 위치를 쓰는 인터페이스 직접 구현의 두 조회 오버로드를 확인한다.

SceneProject는 매 상태에서 독립 모델의 시작 좌표·길이·비율로 Source·Clip·Route의 역조회 기대 거리를 검증한다. PolyProject는 형상 편집·Shaper 교체 후 시작점 역조회와 위치 왕복, 원본·Route 결과 일치, 무효 상태의 조회 실패를 확인한다. 기존 고정 경로를 모두 수행하고 seed 0·1·2를 각각 독립 상태에서 깊이 100까지 실행한다. 이는 기본·통합·실패 직접 사례를 대체하지 않는다.

본체·테스트·GeoSystem 샘플 Release 빌드 후 LocationQuery 직접 사례와 GeoSystem 전체를 실행하고 샘플 verify를 확인한다. 공개 API 변경이므로 장시간 실행 사전 확인 후 전체 테스트를 수행한다. 직접 인터페이스 구현자와 사용자 파생형의 새 계약 구현을 빌드로 확인한다. 실행시간·seed별 실제 깊이·결과·필요 이력은 Results와 Runs에 기록하고, 형식·문서 링크를 검사한다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=LocationQuery'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem'
dotnet run --project samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release --no-build -- verify
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore
```

## 범위

[상태·동작 표](01.%20Tables.md)의 모든 계약은 NUnit 직접 사례와 UniTest 고정 경로로 확인한다. SceneProject의 seed 0·1·2는 독립된 초기 상태에서 각각 깊이 100을 수행한다. 좌표와 길이는 독립적인 수치 기대값으로 비교하고, 회전은 360도 주기를 고려한다. 원본 이벤트에서 전체 그래프 완료를 가정하지 않고 공개 변경 메서드 반환 후 최종 결과와 객체별 통지를 확인한다.

직접 NUnit은 경계·거부·예외·수명 순서와 모든 방향 조합을 검증한다. 고정 Scene 경로는 추가·제거·전체 해제·크기 변경·평행 이동·핀 이동·앵커 교체·재생성을 반드시 수행한다. 랜덤 실행은 같은 동작들을 누적하여 조합을 검증한다.

## 실행과 기대값

실행 환경·전체 회귀·형식 검사는 [공통 계획](../../Common/docs/02.%20Plans.md)을 따른다. Planar만 재검증할 때는 다음 필터를 사용한다.

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystemPlanar'
```

각 랜덤 실행의 목표는 성공·취소 없음·실제 깊이 100/100이다. seed·시간·노드와 부모 노드 ID를 포함한 이력을 결과 문서에 연결한다. Circular·Offset·3D·자동 재탐색은 검증 범위에 포함하지 않는다. Route 끝점 편집은 [공통 계획](../../Common/docs/02.%20Plans.md)의 RouteTests·RouteProject에서 공통·Planar 양쪽을 검증한다.

NavigationContractsTests는 Property의 독립성·지연 생성·폐기 후 내용과 페이로드 보존, 옵션 변경의 알림·유효성·폐기 검사, 원본 옵션의 Shape 비전파, Clip·Route의 독립 옵션과 공간 조회를 검증한다. AStarPathfinder&lt;Vector2&gt;의 거리 휴리스틱과 제네릭·비제네릭 결과도 포함하며 실행 집계는 [공통 결과](../../Common/docs/03.%20Results.md)에 기록한다.

## PolySegment·Shaper

PolySegmentTests는 표의 각 계약을 랜덤 선택과 무관하게 직접 검증한다. PolylineShaper은 길이 3·4의 직각 경로와 목표 길이 2에 대해 위치·거리·회전을 정확한 값으로 비교한다. QuadraticBezierShaper·CubicBezierShaper는 알려진 중간점, 세밀한 직접 다항식 평가로 합산한 길이, 목표 길이 변경과 제어점 수 불일치·회복을 검증한다. 길이·회전의 기대값은 구현의 분할 함수를 호출하지 않는다.

PolyProject 고정 경로는 생성과 20개 입력·수명 동작을 모두 실행한다. 연속 테스트는 독립된 초기 상태에서 seed 0·1·2, 각각 깊이 100으로 실행하고 RandomContinuousTest가 출력하는 시간·깊이·노드 ID·부모 ID·Lab ID를 보존한다. 같은 모델에서 Pin·Route의 유효성·길이·폐기도 확인한다.

Hinge 은닉은 공개 인터페이스·구현 클래스에서 Hinges를 조회할 수 없는지, Hinge 자체가 외부에 보이지 않는지, 생성 훅이 private protected인지 검사한다. 기존 분할 데이터 불변 조건 검사는 테스트 어셈블리의 InternalsVisibleTo 권한으로 유지한다. 사용자 기능은 Length와 Try 조회, IShaper 구현과 Pin·Clip·Route 연동으로 검증한다. GeoSystem 회귀와 세 Release 빌드를 수행하고 전체 회귀는 장시간 실행 여부를 확인한 뒤 진행한다.

```powershell
dotnet build src/UniEngine.sln -c Release
dotnet build tests/UniEngine.Tests.csproj -c Release
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=PolySegment'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem'
```

공개 계약과 LinearSegment 기반 클래스 변경이므로 전체 회귀도 실행한다. 이전 전체 회귀가 약 13분이었으므로 AGENTS의 장시간 실행 지침에 따라 실행 전에 확인한다. 기본 기대값은 실패·건너뜀 0, 빌드 경고·오류 0이다. 중단·미실행 결과는 성공 결과와 구분한다. 전체 테스트는 별도 실행 기록으로 보존하며 집중 실행과 중복 합산하지 않는다.

## Tracer와 Wheel

TracerTests는 B → A의 앞 구간 길이 변경, 같은 말단의 두 번째 뷰 유지, Route와 말단 각각의 폐기, 역방향 Clip의 경계 조회를 검증한다. 분기에서는 연결 순서와 실제 회전이 서로 다른 후보를 놓고 FIFO·각도·대체 인덱스를 구별한다. 경계 도착과 통과를 나누어 예약 소비 시점도 확인한다.

TracerStateProjectTests는 seed 0·1·2를 각각 깊이 100으로 실행한다. 길이 8인 선로 위의 기대 좌표·방향·정책을 독립적으로 누적하면서 배치, Route 해제, 방향 전환과 이동 결과를 비교한다. 집중 검증 후 공개 계약 변경에 맞춰 전체 Release 테스트를 실행한다.

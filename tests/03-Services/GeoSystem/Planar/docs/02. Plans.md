# Planar 검증 계획

## 범위

[상태·동작 표](01.%20Tables.md)의 모든 계약은 NUnit 직접 사례와 UniTest 고정 경로로 확인한다. SceneProject의 seed 0·1·2는 독립된 초기 상태에서 각각 깊이 100을 수행한다. 좌표와 길이는 독립적인 수치 기대값으로 비교하고, 회전은 360도 주기를 고려한다. 원본 이벤트에서 전체 그래프 완료를 가정하지 않고 공개 변경 메서드 반환 후 최종 결과와 객체별 통지를 확인한다.

직접 NUnit은 경계·거부·예외·수명 순서와 모든 방향 조합을 검증한다. 고정 Scene 경로는 추가·제거·전체 해제·크기 변경·평행 이동·핀 이동·앵커 교체·재생성을 반드시 수행한다. 랜덤 실행은 같은 동작들을 누적하여 조합을 검증한다.

## 실행과 기대값

실행 환경·전체 회귀·형식 검사는 [공통 계획](../../Common/docs/02.%20Plans.md)을 따른다. Planar만 재검증할 때는 다음 필터를 사용한다.

```powershell
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystemPlanar'
```

각 랜덤 실행의 목표는 성공·취소 없음·실제 깊이 100/100이다. seed·시간·노드와 부모 노드 ID를 포함한 이력을 결과 문서에 연결한다. Circular·Offset·3D·자동 재탐색은 검증 범위에 포함하지 않는다. Route 끝점 편집은 [공통 계획](../../Common/docs/02.%20Plans.md)의 RouteTests·RouteProject에서 공통·Planar 양쪽을 검증한다.

NavigationContractsTests는 Property의 독립성·지연 생성·폐기 후 내용과 페이로드 보존, 옵션 변경의 알림·유효성·폐기 검사, 원본 옵션의 Shape 비전파, Clip·Route의 독립 옵션과 공간 조회를 검증한다. AStar&lt;Vector2&gt;의 거리 휴리스틱과 제네릭·비제네릭 결과도 포함하며 실행 집계는 [공통 결과](../../Common/docs/03.%20Results.md)에 기록한다.

## PolySegment·Shaper

PolySegmentTests는 표의 각 계약을 랜덤 선택과 무관하게 직접 검증한다. FreeHandle은 길이 3·4의 직각 경로와 목표 길이 2에 대해 위치·거리·회전을 정확한 값으로 비교한다. Bezier2·3는 알려진 중간점, 세밀한 직접 다항식 평가로 합산한 길이, 목표 길이 변경과 제어점 수 불일치·회복을 검증한다. 길이·회전의 기대값은 구현의 분할 함수를 호출하지 않는다.

PolyProject 고정 경로는 생성과 20개 입력·수명 동작을 모두 실행한다. 연속 테스트는 독립된 초기 상태에서 seed 0·1·2, 각각 깊이 100으로 실행하고 RandomContinuousTest가 출력하는 시간·깊이·노드 ID·부모 ID·Lab ID를 보존한다. 같은 모델에서 Pin·Route의 유효성·길이·폐기도 확인한다.

```powershell
dotnet build src/UniEngine.sln -c Release
dotnet build tests/UniEngine.Tests.csproj -c Release
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=PolySegment'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem'
```

공개 계약과 LinearSegment 기반 클래스 변경이므로 전체 회귀도 실행한다. 이전 전체 회귀가 약 13분이었으므로 AGENTS의 장시간 실행 지침에 따라 실행 전에 확인한다. 기본 기대값은 실패·건너뜀 0, 빌드 경고·오류 0이다. 중단·미실행 결과는 성공 결과와 구분한다. 전체 테스트는 별도 실행 기록으로 보존하며 집중 실행과 중복 합산하지 않는다.

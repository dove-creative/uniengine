# Navigation·Location 검증 계획

## Network Creator 검증

LinearNetworkCreatorTests는 Idle·Anchor·Connect의 모든 Put·Select 동작과 감지 갱신, 기존 Node 우선, Segment 위치 역조회 기반 Pin Factory, GeoGroup 등록을 검증한다. 실패·예외·재진입·잘못된 Factory 결과는 기존 노드와 확정 결과를 보존하면서 새 임시 객체만 정리해야 한다. 취소·종료·폐기는 생성 결과를 소유하지 않는지 확인한다.

CreatorProject는 생성 활성 여부·선택 대상·현재 기준·확정한 노드와 구간의 독립 모델을 보관한다. 고정 경로는 첫 배치·다음 배치·기존 노드 선택·중복 선택·Factory 거부와 재시도·단계 취소·종료를 직접 실행한다. 독립 seed 0·1·2의 연속 실행은 각 100단계이며 매 단계에서 상태, 객체 수명, 연결 양방향 참조를 비교한다. seed·실제 깊이·실행시간·이력은 Results와 Runs에 기록한다.

공개 API 변경이므로 집중 검증 후 전체 테스트를 실행한다. 2026-11-26에 사용자가 전체 실행을 요청했다. 기존 전체 실행은 약 4분이며 장시간 실행도 이 요청에 포함한다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=NetworkCreators' --logger 'trx;LogFileName=creators.trx' --results-directory tests/bin/NetworkCreators
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --logger 'trx;LogFileName=full.trx' --results-directory tests/bin/NetworkCreators
```

본체·테스트 빌드, 코드 LF·UTF-8·공백·문서 링크 검사를 포함한다. Bezier·Route 구체 생성기, 입력 장치·화면 표시·스냅·자동 구간 분할과 Unity 실행은 범위 밖이다.

## 범위

[상태·동작 표](01.%20Tables.md)의 각 계약을 NUnit 직접 사례로 확인하고, UniTest GraphProject의 고정 경로와 seed 0·1·2 연속 실행으로 누적 상태를 확인한다. 각 seed는 독립적으로 시작하며 목표 깊이는 100이다. Navigation 원본 테스트의 연결·중복 거부·해제·방향 조회·폐기 사례를 공개 API에 맞추어 재작성했다. Internal 메서드는 공개되지 않는지 별도로 확인한다.

평면 객체와 수명 전파는 [Planar 계획](../../Planar/docs/02.%20Plans.md)에서 검증한다. 여러 모듈과 공개 계약을 추가하므로 전체 기본 회귀 테스트를 실행한다. 벤치마크, Unity·Mono·IL2CPP 및 멀티스레드 검증은 범위에 포함하지 않는다.

제네릭 Geometry 계약은 GenericGeometryTests의 NUnit 직접 사례로 검증한다. Planar와 독립된 float 위치·bool 회전 구현, 회전이 없는 string 위치 구현을 사용하여 특정 공간 타입이나 기본 클래스의 상속을 요구하지 않는지 확인한다. 기존·제네릭·Navigation 인터페이스의 참조 일치, 변경 알림, 연결 거부, 조회 실패·허용 오차·수명과 Planar Pin·Clip·Route의 제네릭 조회를 포함한다. 기존 Navigation·Planar의 고정·랜덤 연속 시나리오는 그대로 회귀 범위에 포함한다.

TryGetLocation의 기본·범위 계약은 string 위치 직접 구현과 float 위치·bool 회전 구간으로 검증한다. 범위의 공간 오차를 비교하는 제네릭 Clip·Route가 Vector2 연산이나 회전 표현에 의존하지 않는지 확인한다. 구체 사례·고정 경로·seed 0·1·2의 깊이 100 연속 검증은 [위치 역조회 계획](../../Planar/docs/02.%20Plans.md)의 추가 범위를 따른다.

## 절차와 기대값

경로 탐색·통행 옵션·외부 속성의 추가 범위는 PathfindingTests와 NavigationContractsTests의 NUnit 직접 사례로 검증한다. 네 알고리즘의 실패·빈 경로·방향 제한·순서·동률·비용과 결과 참조를 확인하고, 읽기 전용 직접 구현으로 가변 인터페이스나 Property·EventHub 접근에 의존하지 않는지 확인한다. Property의 지연 할당 검사에만 저장소 필드 관찰을 사용하며 나머지 수명·독립성·알림은 공개 API로 검증한다.

독립 최단 거리 대조는 seed 0·1·2마다 6노드 방향 그래프 20개를 생성한다. 각 그래프에서 모든 출발점과 두 목표의 최소 비용을 Floyd–Warshall로 계산하고 DijkstraPathfinder, 영 휴리스틱 A*, 허용적 비일관 휴리스틱 A*와 비교한다. 이는 유한 그래프의 NUnit 무작위 대조 사례이며 UniTest 연속 상태 전이의 깊이 100과 구분한다. 기존 Navigation·Planar·Property의 고정·연속 회귀는 별도로 실행한다.

1. Release 빌드가 경고·오류 없이 완료된다.
2. GeoSystem 필터의 모든 직접·고정·랜덤 사례가 통과한다.
3. 전체 기본 테스트가 통과한다.
4. 각 랜덤 사례에서 실제 깊이 100/100, 취소 없음과 성공을 확인하고 이력을 보관한다.
5. 새로운 C# 파일의 UTF-8·LF와 git diff --check를 확인한다.

```powershell
dotnet build src/UniEngine.sln -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore
```

테스트 호스트가 시작되지 못한 실행은 사례 실패와 구분하고, 허용된 실행 환경에서 같은 빌드로 재검증한다. 랜덤 세 seed의 실제 실행시간 합계가 60초를 넘으면 테스트 안내의 중간 확인 절차를 따른다.

탐색·통행 옵션 추가 범위의 집중 회귀는 다음과 같이 실행한다. 공개 API 변경에 따른 전체 회귀는 약 13분의 기존 실행 기록이 있으므로 AGENTS의 장시간 테스트 사전 확인 후 실행한다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem|FullyQualifiedName~PropertyTests|FullyQualifiedName~PropertyStateProjectTests' --logger 'trx;LogFileName=focused.trx' --results-directory tests/bin/GeoSystem/Pathfinding
```

## Route 끝점 편집 검증

RouteTests의 직접 사례는 생성자별 탐색기 선택, From·To 연결 순서와 교체, 역방향 View, 같은 노드 재설정·동일 출발/도착, 해제·재연결, 입력·수명 오류와 탐색 실패를 검증한다. 잘못된 탐색 결과와 새 구독 실패는 기존 상태·구독이 유지되어야 한다. 관찰자 예외는 완료된 경로를 되돌리지 않는다. 공통 Route를 비평면 Geometry에서도 실행하고 Planar·제네릭·Navigation 계약의 참조와 공간 조회를 비교한다.

RouteProject는 노드 3개와 구간 2개의 독립 모델을 사용한다. 모델은 끝점 인덱스와 부호 있는 구간 번호로 방향 View 목록을 기록하고 실제 경로·노드·길이·Source 및 단독 끝점 구독 수와 비교한다. 고정 경로는 연결·실패·해제·교체·형상·수동 편집·폐기·재생성을 수행한다. 랜덤 연속 실행은 독립 seed 0·1·2마다 깊이 100으로 같은 동작 후보를 누적한다. 실행시간·깊이·이력을 결과에 기록하고 60초 중간 확인 규칙을 적용한다.

```powershell
dotnet build src/UniEngine.sln -c Release --no-restore
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=RouteEditing' --logger 'trx;LogFileName=editing.trx' --results-directory tests/bin/GeoSystem/RouteEditing
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem|FullyQualifiedName~PropertyTests|FullyQualifiedName~PropertyStateProjectTests' --logger 'trx;LogFileName=focused.trx' --results-directory tests/bin/GeoSystem/RouteEditing
```

전체 회귀는 집중 검증 후 장시간 실행 사전 확인을 받는다. 형식·공백·문서 링크를 검사하고, 수동 관리 다이어그램과 기존 작업은 보존한다. 자동 재탐색은 범위 밖이며 PolySegment 공간 계산과 새 공통 편집 계약의 Planar 연동은 [Planar 계획](../../Planar/docs/02.%20Plans.md)의 별도 사례로 검증한다.

## 제네릭 Route System과 그룹 검증

GenericRouteTests는 Planar에 의존하지 않는 문자열 위치와 float 위치·bool 회전으로 Pin·Hold·Clip·Route를 검증한다. GroupTests는 세 그룹의 직접 등록·공유·조회 투영·폐기 자동 제거·비소유 정리·실패 보존과 순환 검사를 검증한다. GroupProject는 독립 등록 모델을 사용하여 고정 경로와 seed 0·1·2, 깊이 100의 연속 경로를 실행한다. 각 seed의 실제 깊이·시간·결과와 이력은 Results와 Runs에 기록한다.

1. 본체·테스트·GeoSystem 샘플 Release 빌드를 수행하고 샘플 verify의 기본·Tracer 장면을 확인한다.
2. GeoGroups 필터로 새 직접·고정·랜덤 사례를 실행한다.
3. GeoSystem 전체 필터로 기존 Planar·탐색·경로·Tracer·Shaper 회귀를 실행한다.
4. 공개 API 변경이므로 전체 테스트를 실행한다. 기존 약 13분 실행 기록에 따라 AGENTS의 장시간 테스트 사전 확인을 받는다.
5. UTF-8·LF·변경 공백·문서 링크를 확인한다. Unity·Mono·IL2CPP 실행과 성능 벤치마크는 별도 범위이다.

```powershell
dotnet build tests/UniEngine.Tests.csproj -c Release --no-restore
dotnet build samples/03-Services/GeoSystem/UniEngine.GeoSystem.Sample.csproj -c Release --no-restore
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoGroups'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore --filter 'TestCategory=GeoSystem'
dotnet test tests/UniEngine.Tests.csproj -c Release --no-build --no-restore
```
